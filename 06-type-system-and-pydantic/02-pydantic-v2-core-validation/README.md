# 专题 02：Pydantic V2 数据契约、Rust 核心引擎与复杂联动校验

在生产环境中，外部通过 HTTP 传入的 JSON 数据是不可信的野生数据（如字段缺失、字符串冒充数字、空值越界）。**Pydantic** 是现代 Python（尤其是 FastAPI 生态）绝对的数据契约底座。Pydantic V2 彻底放弃了旧版纯 Python 验证，采用 **Rust 重写核心验证器（`pydantic-core`）**，带来了高达 **5 ~ 17 倍的性能飞跃**，是构建微服务请求校验与数据序列化的工业标杆。

---

## 一、 痛点驱动：野数据侵入业务层引发的穿透崩溃

若在业务 Controller 中裸写校验逻辑：
```python
# ❌ 数十行冗长的手动类型转换与防御性校验，极易遗漏导致 500 崩溃
if "age" not in data or not str(data["age"]).isdigit():
    ...
```
业务代码被大量防御性检查吞噬；且在面对复杂的跨字段联动（如“确认密码必须等于原密码”）时，手动逻辑脆弱易错。

---

## 二、 机制解密：Rust 核心（pydantic-core）与三层校验流水线

```text
[ Pydantic V2 验证与序列化流水线 ]
  原始非受信输入 (JSON / Dict)
         │
         ▼
  ┌────────────────────────────────────────────────────────────┐
  │ pydantic-core (Rust 原生编译高速验证器)                    │
  │ ├── 阶段 1: 零拷贝内存解析与强制类型转换 (Coercion)        │
  │ ├── 阶段 2: @field_validator 单字段精确格式校验 (如正则)   │
  │ └── 阶段 3: @model_validator(mode="after") 跨字段联动业务校验│
  └────────────────────────────┬───────────────────────────────┘
                               ▼
              产出强类型不可变实例 / 抛出结构化 ValidationError
```

1. **Rust 底层性能跨越**：
   - V1 版本依赖 Python 递归解析，深度嵌套对象性能极差；V2 将数据校验与序列化下沉到 Rust，在 C 语言内存级别完成单次扫描转换；
2. **联动校验的执行时序**：
   - **`@field_validator`**：针对单个字段独立触发；
   - **`@model_validator(mode="after")`**：在所有单个字段都校验通过、实例组装完成后的最后关卡触发，在此处进行多字段逻辑交叉验证。

---

## 三、 生产规范与最佳实践

- **永远在接口最外层完成校验**：坚决禁止将未经验证的裸字典传入深层 Service / DAO；
- **利用 `model_dump(mode="json")` 序列化**：自动处理 `datetime`、`UUID`、`Decimal` 等复杂对象的 JSON 规范转换。
