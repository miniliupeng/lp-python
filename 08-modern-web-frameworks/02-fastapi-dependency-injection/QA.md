# 大厂高频面试题精讲 (07-02-fastapi-dependency-injection)

---

### Q1: 请详述 FastAPI 中 Depends 依赖注入系统的底层运行机制与子依赖拓扑图解析。

#### 🎯 面试官考点
- 依赖注入（Dependency Injection）、控制反转（IoC）与有向无环图（DAG）求解算法。

#### 💡 满分回答模板
1. **依赖树拓扑求解（Dependency Graph Resolution）**：
   - 当服务启动加载路由时，FastAPI 利用 Python 反射（`inspect.signature`）深度解析每个路由函数形参中的 `Depends(fn)`；
   - 如果某个依赖函数 `fn` 自身又声明了其他 `Depends`，框架会递归追踪并构建出一张**依赖有向无环图（DAG）**；
2. **运行时调用分发与入参注入**：
   - 当请求到达时，FastAPI 按照拓扑排序自底向上依次执行各个依赖函数；
   - 依赖函数的返回值被就地暂存，并作为入参传递给下游的高级依赖，最终整合成一个干净的参数字典无缝注入给核心 Controller 路由函数。

### Q2: 在 FastAPI 的依赖函数中，yield 语法起到了什么决定性作用？它是如何保证资源必然被清理释放的？

#### 🎯 面试官考点
- 异步生成器协议（PEP 525）、异常隔离边界与连接池安全回收保障。

#### 💡 满分回答模板
1. **双向生命周期拦截（Setup / Teardown）**：
   - 普通依赖函数只能返回数据；而使用 **`yield` 的依赖函数被框架包装为一个异步上下文管理器**；
   - **`yield` 之前**：在请求真正进入路由前执行（如创建 `AsyncSession`、开启数据库事务、记录链路耗时开始时间）；
   - **`yield value`**：将该连接或上下文对象注入给路由函数使用，同时当前依赖协程在此被安全挂起；
   - **`yield` 之后**：在路由函数执行完毕、响应已生成或中途抛出异常后折返执行（如提交事务、关闭数据库连接）。
2. **异常安全兜底**：
   - 框架内部将依赖的 `yield` 放置在 `try-finally` 块中。即便路由内部发生崩溃或抛出未捕获的 500 错误，FastAPI 依然无条件驱动生成器步进到 `finally`，**确保数据库连接 100% 归还连接池，杜绝泄漏**。

### Q3: Depends(use_cache=True)（默认）与 use_cache=False 有什么本质区别？

#### 🎯 面试官考点
- 单请求生命周期缓存（Request-scoped Cache）与多实例重重创建隔离。

#### 💡 满分回答模板
1. **`use_cache=True`（默认行为，单请求单例）**：
   - **原理**：在同一个 HTTP 请求的整个调用链中，如果多个子依赖或路由函数多次声明了同一个依赖函数（如 `db: Session = Depends(get_db)`）；
   - **效果**：该依赖函数**仅会被实际执行一次**！后续的调用直接复用首次计算缓存的结果；
   - **价值**：保证了整个请求链路上所有 Controller、Service 共享的是**同一个数据库事务与同一个认证用户上下文**。
2. **`use_cache=False`（强制每次重新执行）**：
   - **应用场景**：在需要每次获取全新独立状态的特殊场景下（例如每次需要生成独立的追踪子 Span、独立的加密临时盐值，或需要显式开启两个独立的非嵌套物理事务连接），必须显式配置 `use_cache=False`。
