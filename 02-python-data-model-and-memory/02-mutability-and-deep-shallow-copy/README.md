# 专题 02：可变性陷阱、深浅拷贝底层拓扑与默认参数哨兵

在 Python 体系中，数据类型的**可变性（Mutability）**决定了状态演变的确定性。浅拷贝与深拷贝的误用是引起高并发接口数据串扰与安全漏洞的主要温床；而函数定义中的“默认可变参数陷阱”更是常驻大厂中高级面试的经典考核点。

---

## 一、 痛点驱动：默认参数全局污染与浅拷贝状态共享

1. **默认可变参数的全局状态累积**：
   - 声明 `def add_item(val, target=[])` 时，由于函数定义仅在模块加载时执行一次，该空列表作为函数元数据被全局唯一分配。每次调用若不传 `target`，所有请求都会向同一个列表中追加数据，造成灾难级的跨用户数据串扰；
2. **浅拷贝（Shallow Copy）引发的隐蔽修改**：
   - 开发者误以为调用 `copy.copy()` 或 `list[:]` 就能安全隔离数据，但若容器内部嵌套了字典或列表，嵌套对象的指针依然被原样共享。

---

## 二、 机制解密：深浅拷贝内存拓扑与默认参数加载时序

```text
[ 浅拷贝 (copy.copy) ]
  新容器 ───┐ (新指针)
            ├───> [ 内部元素 0x8899 ] (共享指针，修改内层元素会相互影响！)
  旧容器 ───┘ (旧指针)

[ 深拷贝 (copy.deepcopy) ]
  新容器 ────> [ 深度递归复制的全新内部元素 0x9999 ] (完全物理隔离)
```

1. **函数默认参数的加载时序**：
   - Python 在解释到 `def` 语句的瞬间（编译加载期），就会对默认参数表达式求值，并存入函数对象的 **`__defaults__`** 元组中；
   - 随后的每次函数调用，形参若未传值，将直接引用该唯一的元组对象！
2. **深拷贝解决循环引用的字典缓存机制**：
   - `copy.deepcopy(x, memo)` 在底层维护了一个 **`memo` 字典**。每次复制对象前先查表，若已被复制过则直接返回已存在的副本引用，天然免疫自循环引用引发的递归爆栈。

---

## 三、 生产规范与避坑指南

- **默认参数必用 `None` 哨兵**：
  ```python
  def append_record(record: dict, container: list | None = None) -> list:
      if container is None:
          container = []
      container.append(record)
      return container
  ```
- **嵌套数据结构强隔离必选深拷贝**：处理多租户配置或复杂树状实体时，必须使用 `copy.deepcopy()`。
