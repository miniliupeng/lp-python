### Q1: Python 中的“一切皆对象”在 CPython 底层是如何实现的？请详述 PyObject 的核心数据结构。

#### 🎯 面试官考点
- CPython C 源码实现、面向对象在 C 语言层面的多态模拟机制。

#### 💡 满分回答模板
1. **统一的结构体继承基石**：
   - 在 CPython 中，所有对象类型在 C 语言结构体定义的最前部，都嵌入了宏 **`PyObject_HEAD`**；
   - 它的核心包含两个基础字段：
     ```c
     typedef struct _object {
         _PyObject_HEAD_EXTRA // 双向链表指针，用于跟踪活动堆对象
         Py_ssize_t ob_refcnt; // 64位无符号整数，维护该对象的引用计数
         struct _typeobject *ob_type; // 指向描述该对象类型的 PyTypeObject 结构体指针
     } PyObject;
     ```
2. **C 语言层面的多态实现原理**：
   - 任何指向具体 Python 对象（如 `PyListObject`, `PyLongObject`）的指针，都可以被**安全地强制类型转换为 `PyObject*`**；
   - 当调用一个方法或获取属性时，解释器通过当前对象的 `ob_type` 指针找到对应的类型对象，进而分发调用类型结构体中预设的函数指针表（如 `tp_as_number`, `tp_as_sequence`），实现了 C 语言层面的动态多态。

### Q2: Python 的参数传递机制到底是什么？为什么说既不是传统意义上的传值也不是传引用？

#### 🎯 面试官考点
- 语言执行规范（The Python Language Reference）中赋值传递（Pass by Assignment）的严格定义。

#### 💡 满分回答模板
1. **官方规范定义：赋值传递（Pass by Assignment）**：
   - 很多开发者误用 C++ 的“引用传递”或 Java 的“基本类型值传递”来套用 Python，这都不准确；
   - Python 的函数实参传递给形参，执行的是**与赋值语句 `param = arg` 完全一致的规则**——即传递的是“对象指针的拷贝”。
2. **可变对象与不可变对象的表现差异**：
   - **当传入不可变对象（如 int, str, tuple）**：函数内对形参重新赋值（如 `x = x + 1`），只是让局部变量 `x` 重新指向了一个新的堆对象，外部实参指向的物理对象纹丝不动；
   - **当传入可变对象（如 list, dict, 自定义类）**：如果直接在形参上调用就地修改方法（如 `param.append(100)`），由于形参与外部实参指向同一个物理 `PyObject`，修改会立即对外部可见。

### Q3: id(obj) 返回的数字到底代表什么？两个不同生命周期的对象 id() 可能相同吗？

#### 🎯 面试官考点
- CPython 内存地址抽象、内存分配器（obmalloc）回收复用机制。

#### 💡 满分回答模板
1. **数值的底层本质**：
   - 在标准 CPython 中，`id(obj)` 返回的整数是**该对象在 C 语言进程虚拟内存空间中的物理内存起始地址（Pointer Address）**。
2. **不同生命周期的 id 复用现象**：
   - **可能相同**！当一个短命对象被创建后立即销毁，该对象的内存被 CPython 内存池释放回收；
   - 紧接着下一个新对象被分配时，底层内存分配器极大概率会直接**将刚刚释放的那块内存切片重新分配给新对象**。因此两者的 `id()` 会完全一致，但这绝不代表它们是同一个对象。
   - **生产铁律**：只有当两个对象在**同一时间点同时存活**时，比较 `a is b`（即 `id(a) == id(b)`）才有确定的唯一性保证。
