# 大厂高频面试题精讲 (01-03-interning-and-identity)

---

### Q1: 简述 is 运算符与 == 运算符的底层本质区别。为什么不能用 is 比较普通字符串或数值？

#### 🎯 面试官考点
- 内存物理指针同一性（Identity）与对象值等价性（Equality）的边界、生产严重事故防范。

#### 💡 满分回答模板
1. **底层机制对比**：
   - **`is`（同一性检查）**：底层等价于比较两者在 C 语言层面的指针物理内存地址（`id(a) == id(b)`），执行耗时极低（单个机器指令），不关心内容；
   - **`==`（等价性检查）**：底层会调用左操作数的 **`__eq__()`** 魔术方法，逐字段或逐字符比对两者存储的值是否相等。
2. **为什么严禁使用 `is` 比较数值或字符串**：
   - 无论是小整数池（-5~256）还是字符串驻留，都属于 **CPython 解释器的内部实现细节与性能优化手段**，并不属于 Python 语言规范强约束的一部分；
   - 如果使用 `if status_code is 200:`，代码在小规模测试可能碰巧成立，但当状态码超出小整数池或者在其他虚拟机实现（如 PyPy）中，`is` 将不可预测地返回 `False`，酿成严重的生产业务逻辑穿透。

### Q2: CPython 为什么要在全局预分配小整数池（-5 到 256）？底层数据结构是什么？

#### 🎯 面试官考点
- CPython 内存优化策略、静态数组初始化与空间换时间思想。

#### 💡 满分回答模板
1. **背景动机**：
   - 在程序运行中，极小整数（尤其是 0、1、-1、循环索引、HTTP 状态码）的使用频次占据了整数总分配量的 80% 以上；
   - 如果每次循环都执行 `malloc` 和 `free`，系统调用开销与内存碎片将严重劣化解释器吞吐量。
2. **底层数据结构实现**：
   - 在 CPython 源码 `longobject.c` 中，定义了一个全局静态数组：
     ```c
     static PyLongObject small_ints[257 + 5];
     ```
   - 在解释器启动初始化阶段，这 262 个整数对象就被一次性全部创建好；
   - 当调用 `PyLong_FromLong(v)` 创建整数时，解释器先判断 `-5 <= v <= 256`。若命中区间，直接返回 `&small_ints[v + 5]` 的指针并递增引用计数，省去了一切内存分配开销。

### Q3: 什么是字符串驻留机制（String Interning）？它为什么能大幅提升字典（dict）的键检索速度？

#### 🎯 面试官考点
- 哈希表检索算法优化、字符串驻留表实现与 O(1) 属性查找。

#### 💡 满分回答模板
1. **字符串驻留定义**：
   - 将不可变字符串对象在全局唯一哈希表（Interned 字典）中注册保存在内存中，确保同名字符串只存在一份物理拷贝。
2. **对字典查找的决定性加速（大幅消除字符级比较）**：
   - 在 Python 的类属性访问、全局变量查找中，底层全部由字典存储；
   - 字典在哈希寻址碰撞比对时，常规情况下需要逐字节比对两个字符串的内容（耗时与字符串长度成正比）；
   - **驻留加速机制**：如果两个字符串都被驻留，解释器只需首先判断：
     ```c
     if (key1 == key2) return entry; // 直接比较指针地址！
     ```
   - 如果指针相等，直接判定命中，**耗时缩减为单次 CPU 指针比对**，彻底避免了漫长的字符串逐字符内存循环比对。
