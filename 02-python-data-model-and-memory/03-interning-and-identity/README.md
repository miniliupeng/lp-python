# 专题 03：小整数对象池、字符串常量驻留与同一性比较红线

在追求极速与高内存密度的 CPython 中，频繁创建和销毁微小对象（如整数 0、1、短字符串）会造成严重的内存碎片和垃圾回收停顿。CPython 引入了**小整数静态对象池（Small Integer Cache）**与**字符串常量驻留（String Interning）**黑科技。深入理解这些机制是规避 `is` 与 `==` 混淆滥用、杜绝生产偶发 Bug 的关键。

---

## 一、 痛点驱动：对象频繁分配的性能损耗与同一性判定混淆

1. **高频标量分配带来的性能损耗**：
   - 在任何业务系统中，计数器、下标、状态码（如 200, 404, 0, 1）被高频重复使用。若每次都触发 `malloc` 分配堆内存，CPU 与内存开销巨大；
2. **`is` 与 `==` 混用引发的幽灵 Bug**：
   - 开发者在本地或简单测试时发现 `a = 100; b = 100; a is b` 恒为 `True`，便误以为 `is` 可以安全替代 `==` 做值比较；
   - 结果一旦上线到生产环境，遇到数值 1000 时，`a is b` 突然变成 `False`，导致关键权限或计费逻辑分支走错，酿成事故。

---

## 二、 机制解密：小整数池区间与字符串驻留表

```text
CPython 全局静态缓存:
  small_ints 数组: [ -5, -4, ... 0, 1, 2, ... 255, 256 ] (预先常驻内存，全局唯一单例)

  数值在 [-5, 256] 之间 ──> 直接返回全局单例指针 (is 恒为 True)
  数值超出此区间        ──> 动态 malloc 分配新 PyObject (即使值相同，指针也不同)
```

1. **小整数池（[-5, 256] 闭区间）**：
   - CPython 解释器在启动时，静态初始化包含 262 个整数的连续数组。任何时候需要这些数字，直接返回预设单例地址；
2. **字符串常量驻留（String Interning）**：
   - 满足 Python 标识符命名规范的短字符串（如属性名、关键字），CPython 会在内部全局字典进行驻留；
   - 优势：当在字典中通过键查找值时，直接**对比两者指针地址（C 语言 `p1 == p2`，单周期完成）**，而无需逐字符进行内存比较，使属性访问与字典检索达到硬件级极速。

---

## 三、 生产规范与避坑红线

- **严禁使用 `is` 进行数值或普通字符串比较**：
  - `is` 判定的是**内存物理地址同一性**（Identity）；
  - `==` 判定的是**对象值等价性**（Equality）；
- **`is` 的合法生产使用场景仅有两处**：
  1. 判断是否为空单例：`if val is None:` 或 `if val is not None:`；
  2. 判断是否为全局布尔单例：`if flag is True:`。
