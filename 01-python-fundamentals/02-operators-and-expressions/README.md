# 02-operators-and-expressions: 运算符语义与短路求值

## 一、核心机制与设计哲学

- **`is` 与 `==` 的本质隔离**：
  - `==`（Equality）：调用对象的 `__eq__` 协议方法，比较两个对象在**业务逻辑值（Value）**上是否相等。
  - `is`（Identity）：比较两个操作数所指向的**内存地址（Pointer Identity）**是否完全一致（即 `id(a) == id(b)`）。
- **逻辑运算符短路机制（Short-circuit Evaluation）与值返回特性**：
  - Python 的 `and` 与 `or` 不仅仅返回布尔值，而是返回**决定该表达式真假性的具体操作数本身**。
  - `A or B`：若 `A` 为真值，则立即短路返回 `A`；否则计算并返回 `B`。
  - `A and B`：若 `A` 为假值，则立即短路返回 `A`；否则计算并返回 `B`。

## 二、生产规范与避坑指南

1. **单例与哨兵对象的比较规范**：比较 `None`、`True`、`False`、`Ellipsis (...)` 等内存全局单例时，**必须且只能使用 `is` / `is not`**。使用 `x == None` 会触发用户自定义类的 `__eq__` 重载，产生严重穿透风险并被 Ruff/Flake8 警告。
2. **链式比较陷阱**：Python 允许写 `1 < x < 10`，其在底层编译为 `1 < x and x < 10`，中间操作数 `x` 仅会被求值一次。严禁随意嵌套非常规比较操作导致可读性崩塌。
3. **短路默认值陷阱**：生产中常用 `param or default_val` 设置默认值，若 `param` 本身为合法假值（如 `0`、`""`、`[]`、`False`），则会被错误地覆盖为默认值。应显式使用 `param if param is not None else default_val`。
