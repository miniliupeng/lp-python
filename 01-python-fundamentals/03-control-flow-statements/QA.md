# 常见高频面试题：控制流与高级循环

### Q1: Python 中的 `for...else` 语法是如何工作的？有哪些典型应用场景？

🎯 **面试官考点**：考察候选人对 Python 独有控制流语法的理解深度，以及能否用优雅语法消除样板代码。

💡 **满分回答模板**：
1. **工作机制**：
   - `for...else` 块中的 `else` 分支不是在条件不满足时执行，而是在**循环完整遍历完毕（迭代器自然耗尽）且未发生 `break` 时**触发。
   - 如果循环内部命中 `break` 退出，则跳过 `else` 块。
2. **核心价值**：
   - 传统编程中搜索列表需要维护一个临时标志位（如 `found = False`），退出循环后再用 `if not found` 做兜底。
   - `for...else` 直接消除了临时布尔变量，使逻辑内聚于控制流自身。
3. **典型工程场景**：
   - 节点服务发现与健康探测；
   - 循环重试指定次数（如 `for i in range(MAX_RETRIES)`），全部重试失败后在 `else` 中抛出 `MaxRetryExceededError`。

### Q2: 为什么在遍历列表时直接调用 `list.remove()` 会引发严重逻辑错误？生产中如何正确处理？

🎯 **面试官考点**：序列可变性与迭代器内部指针游标寻址机制的原理性缺陷。

💡 **满分回答模板**：
1. **Bug 根因**：
   - 列表迭代器在内部维护一个自增整数游标 `index`。
   - 当遍历到索引 `i` 并调用 `remove()` 时，底层数组立即发生就地内存平移（所有后续元素左移一位）。
   - 下一轮循环时游标自增为 `i + 1`，原本位于 `i + 1` 的元素已被移到 `i`，导致该元素被**无感知跳过**，引发漏删。
2. **生产级解决方案**：
   - **方案一（首选推荐）**：使用**列表推导式**过滤生成新列表：`items = [x for x in items if not should_remove(x)]`，时间复杂度为 $O(N)$，且语义清晰无副作用。
   - **方案二（原位修改）**：切片全量赋值替换：`items[:] = [x for x in items if not should_remove(x)]`，保留原引用对象的就地更新。
   - **方案三**：若数据量极大必须就地操作，可采用**逆序索引遍历**（`reversed(range(len(items)))`），删除左移不会影响更小索引的元素位置。
