# 常见高频面试题：异常处理与上下文协议

### Q1: Python 中 `try...except...else...finally` 的执行时序是怎样的？`finally` 中写 `return` 会发生什么？

🎯 **面试官考点**：考察控制流分支完整语义，以及在 `finally` 中篡改返回值的严重反模式。

💡 **满分回答模板**：
1. **执行时序**：
   - `try` 块发生异常时，跳过其后续语句，匹配对应的 `except` 处理分支；
   - 若 `try` 块**完全正常执行未抛出任何异常**，则执行 `else` 分支（适合放成功后的延续逻辑）；
   - 无论上述分支走哪个、无论是否触发了未捕获异常、甚至 `try`/`except`/`else` 中包含 `return`，**`finally` 块始终都会被无条件执行**。
2. **`finally` 中写 `return` 的致命后果**：
   - 如果在 `finally` 块中显式执行 `return val`，它将**无条件覆盖并丢弃**前面在 `try` 或 `except` 中计算出的所有返回值！
   - 更严重的是：如果 `try` 块抛出了异常，而 `finally` 中包含了 `return`，该异常将被**彻底静默吞掉（Suppressed）**，调用方完全无法感知错误！
   - **生产铁律**：严禁在 `finally` 块中书写 `return`、`break` 或 `continue`。

### Q2: `with` 语句底层实现的完整协议是什么？`__exit__` 如何控制异常的传播与抑制？

🎯 **面试官考点**：PEP 343 上下文管理器底层双重魔术方法协议与异常抑制策略。

💡 **满分回答模板**：
1. **底层协议**：
   - 任何对象只要实现了 `__enter__()` 和 `__exit__()`，即满足上下文管理器协议。
   - 当进入 `with ctx as target:` 时：先调用 `ctx.__enter__()`，其返回值绑定到 `target`。
   - 当退出代码块时（无论正常退出还是抛出异常），Python 必定触发调用 `ctx.__exit__(exc_type, exc_val, exc_tb)`。
2. **异常抑制逻辑**：
   - 若代码块内部抛出异常，这三个参数分别传入异常类型、异常实例和 traceback 对象；若无异常则均为 `None`。
   - **返回值语义**：
     - 若 `__exit__` 返回 **布尔真值 `True`**，Python 解释器会将该异常**就地抑制（Suppress）**，不在外层继续冒泡；
     - 若返回 `False`、`None` 或未显式返回，该异常将在执行完 `__exit__` 后**继续向上层传播冒泡**。
