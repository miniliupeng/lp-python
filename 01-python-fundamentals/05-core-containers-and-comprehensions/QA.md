# 常见高频面试题：核心容器与数据结构

### Q1: Python 中 `list` 和 `dict` 的底层数据结构是什么？为什么列表在头部删除元素性能极差？

🎯 **面试官考点**：底层 CPython 结构体模型（`PyListObject` 与紧凑字典）、数组移动开销与系统时间复杂度分析。

💡 **满分回答模板**：
1. **底层数据结构**：
   - **`list`**：底层基于动态连续内存指针数组（`PyObject** ob_item`），维护当前元素容量与预分配空间。
   - **`dict`**：自 Python 3.6 起采用紧凑哈希表设计（两个数组：稀疏哈希索引表 + 连续紧凑键值对数组），空间利用率极高且天然保持插入顺序。
2. **为什么头部操作性能极差**：
   - `list.pop(0)` 或 `list.insert(0, val)` 会使第 0 位之后的所有元素指针在内存中整体左移或右移一个槽位（调用底层 `memmove`）。
   - 时间复杂度为**严格的 $O(N)$**。随着数据量增大（如 100 万条），头部操作会导致严重的 CPU 缓存失效与性能骤降。
3. **工程替换方案**：
   - 频繁头部或双端进出场景，必须替换为标准库的 `collections.deque`（基于双向链块缓冲），首尾增删复杂度均为严格的 $O(1)$。

### Q2: 列表推导式与生成器表达式在底层执行模型和内存占用上有何根本区别？

🎯 **面试官考点**：即时求值（Eager Evaluation）与惰性迭代器（Lazy Evaluation）的内存换算与流式架构思维。

💡 **满分回答模板**：
1. **根本区别**：
   - **列表推导式（`[x for x in ...]`）**：是**即时求值（Eager）**。在执行该行语句时立即遍历整个可迭代对象，在内存中完整分配并构建 `list` 对象，时间复杂度为 $O(N)$，空间复杂度为 $O(N)$。
   - **生成器表达式（`(x for x in ...)`）**：是**惰性求值（Lazy）**。它返回一个生成器对象（遵循迭代器协议），并不立即计算任何元素；只有在调用 `next()` 或在循环中消费时才即时计算产出一个值，空间复杂度恒定为 $O(1)$。
2. **选型决策**：
   - 数据量巨大（如读取数 GB 日志、消费海量流式数据）或只需要流式校验/寻找第一个匹配项（如 `any(x > 10 for x in stream)`）时，**必须使用生成器表达式**，防止引发 OOM（内存溢出崩溃）。
   - 需要频繁随机索引下标访问或多次重复遍历同一个集合时，使用列表推导式。
