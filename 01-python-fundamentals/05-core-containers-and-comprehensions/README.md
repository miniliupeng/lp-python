# 05-core-containers-and-comprehensions: 核心容器体系与推导式

## 一、核心机制与设计哲学

- **四大核心容器的底层数据结构与渐进复杂度**：
  - **`list`（动态数组）**：连续内存指针数组（`PyObject** ob_item`）。尾部追加 `append()` 分摊复杂度为 $O(1)$；头部插入/删除 `insert(0, v)` 需要全量内存平移，复杂度为 $O(N)$。
  - **`tuple`（不可变元组）**：固定长度只读结构，分配开销极小且享有小对象池优化，可作为字典键或集合元素（前提是其包含的所有元素均可哈希）。
  - **`dict`（现代紧凑哈希表）**：Python 3.6+ 采用双数组分离布局（稀疏索引数组 + 紧凑顺序条目数组），既节约 30%~40% 内存，又天然保证**插入键序**。平均查找、插入、删除复杂度为 $O(1)$。
  - **`set`（哈希集合）**：底层基于纯哈希表实现，元素唯一性由 `__hash__` 与 `__eq__` 联合保证。
- **推导式（Comprehensions）与生成器表达式（Generator Expressions）**：
  - 列表/字典/集合推导式在底层由 C 字节码循环优化（`LIST_APPEND` 汇编级指令），效率显著高于显式 `for` 循环配合 `.append()`。
  - 生成器表达式（圆括号 `(x for x in data)`）采用**惰性求值**，返回生成器迭代器，内存开销为 $O(1)$。

## 二、生产规范与避坑指南

1. **队列与频繁首部操作**：生产中若需要实现先进先出（FIFO）队列，严禁使用 `list.pop(0)`，必须使用 `collections.deque`（双向链表数组结构，首尾增删均为 $O(1)$）。
2. **字典安全访问与缺省合并**：
   - 避免直接 `d[key]` 引发 `KeyError`，优先使用 `d.get(key, default)` 或 `collections.defaultdict`。
   - Python 3.9+ 提供了字典并集运算符 `dict_a | dict_b`，以最直观纯粹的语法替代旧式 `.update()` 拷贝。
