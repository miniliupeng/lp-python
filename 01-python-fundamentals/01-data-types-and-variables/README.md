# 01-data-types-and-variables: 数据类型与动态变量模型

## 一、核心机制与设计哲学

Python 采用“万物皆对象”与“强类型动态语言”的设计范式：
- **动态类型（Dynamic Typing）与名字绑定**：变量名在 Python 中本质上只是指向内存中对象的**指针引用**（PyObject 指针）。赋值语句 `x = 42` 并未在栈上分配一个 int 容器，而是在堆上创建（或复用）了一个 `PyLongObject`，并将名字 `x` 绑定到该对象的内存地址。
- **强类型（Strong Typing）**：类型绑定在堆对象本身，而非变量名上。Python 不会在运行时进行隐式类型跨界强制转换（例如 `'42' + 1` 会直接引发 `TypeError`）。
- **IEEE 754 双精度浮点陷阱**：Python 的 `float` 基于底层 C 语言的 `double`（64 位二进制浮点）。十进制小数（如 `0.1`）在二进制下是无限循环小数，故 `0.1 + 0.2 != 0.3`。金融、计费场景必须使用标准库 `decimal.Decimal`。

## 二、生产规范与避坑指南

1. **类型注解规范（PEP 484/585/604）**：在现代企业级代码中，必须显式书写类型提示（如 `price: Decimal`、`name: str | None = None`），以便静态分析工具（Mypy/Ruff/Pyright）在 CI 阶段拦截类型错误。
2. **金融精度强制规则**：涉及货币运算时，严禁使用 `float(amount)`，且创建 `Decimal` 时必须通过**字符串入参**（如 `Decimal("0.1")`，而非 `Decimal(0.1)`，后者会直接固化二进制浮点误差）。
3. **小整数池与不可变驻留**：C-Python 默认缓存 `[-5, 256]` 的小整数与短 ASCII 字符串。该特性属于底层优化，业务逻辑严禁依赖 `is` 判断数值相等性。
