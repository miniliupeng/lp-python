# E02　数据模型题

> 对照示例：`examples/part_e/e02_data_model.py`

### 1. 属性查找的顺序是什么？

**常见错法：** 永远先查实例字典，再查类。

**回答：** 数据描述符（有 `__set__` 或 `__delete__`）优先于实例字典。然后才是实例字典，再是普通类属性和非数据描述符，最后才是 `__getattr__`。函数是非数据描述符，所以实例字典可以盖住它。`property` 是数据描述符，赋值进 `__set__`，不会在实例字典里留下公开名字。示例的 `Field` 把值存到 `_n`，并且在 `__set__` 里乘了 2，用来证明走的是描述符而不是裸赋值。

### 2. `__new__` 和 `__init__` 谁先执行？

**常见错法：** `__init__` 创建对象，`__new__` 只是可选的初始化。

**回答：** `__new__` 负责得到一个实例，通常调用 `object.__new__(cls)`。如果返回的是这个类的实例，才会继续调用 `__init__`。如果返回了别的对象，`__init__` 不会被调用。不可变类型的子类要在 `__new__` 里决定值，因为值定了以后 `__init__` 改不了它。

### 3. `super()` 找的是父类吗？

**常见错法：** `super()` 等于 `父类名.方法(self)`。

**回答：** `super()` 从当前实例的 MRO 里、当前类的下一站开始找。菱形继承 `D(B, C)` 且 `B`、`C` 都继承 `A` 时，MRO 是 `D, B, C, A, object`。每一层都 `super()`，`A` 只执行一次。点名父类会跳过同级的 `C`。示例断言 `D().name() == "DBCA"`。

### 4. 什么时候用元类？

**常见错法：** 想注册子类、想做单例，就写元类。

**回答：** 注册子类用 `__init_subclass__`。单例通常是模块级实例，不需要元类。元类在创建类时控制命名空间，能拒绝不完整的子类，也容易和另一个元类冲突。框架作者才经常需要它。应用代码默认不写。

### 5. `__eq__` 和 `__hash__` 的契约？

**常见错法：** 写了相等方法，对象仍然可以按身份放进集合。

**回答：** 若 `a == b`，则 `hash(a)` 必须等于 `hash(b)`，而且作为字典键期间哈希不能变。只定义 `__eq__` 时，Python 把类标成不可哈希，防止默认的身份哈希和内容相等性不一致。可变对象不要按内容哈希。列表不可哈希，示例断言 `hash([])` 抛 `TypeError`。dataclass 在可比较且未冻结时同样不可哈希；冻结之后才会生成哈希。

### 6. `__slots__` 带来什么，不带来什么？

**常见错法：** 加上 `__slots__` 程序就会明显变快，而且子类自动继承这套布局。

**回答：** 槽用固定字段代替实例字典，省内存，也让拼错属性名立刻失败。它不改变算法复杂度。子类不会自动获得基类的槽布局；要省掉字典，继承链上要一起设计。需要弱引用时，槽里还要有 `__weakref__`。没有实例字典的槽对象，默认也不能随便挂临时属性。

### 7. 引用计数和 GC 各管什么？

**常见错法：** Python 只有标记-清除 GC，`del` 只是“建议回收”。

**回答：** CPython 的主路径是引用计数。没有其他引用时，对象马上回收，不必等 `gc.collect`。互相引用的环计数不会到 0，分代循环 GC 负责这个。`del` 只是解绑名字。`__del__` 不是 `with` 的替代品，调用顺序不可靠，还可能把对象复活。PyPy 的回收时机不同，所以及时释放资源要靠上下文管理器，这才是语言层面站得住的说法。

### 8. 哪些对象不能做弱引用？

**常见错法：** 任何对象都能 `weakref.ref`。

**回答：** `int`、`str`、`list`、`dict` 这类没有弱引用槽的内置类型不行。用户类默认可以。弱引用不增加引用计数，适合缓存和观察回收。弱引用对象本身必须被持有，回调才会在目标回收时运行。

### 9. 浅拷贝和深拷贝？

**常见错法：** 切片是深拷贝。`deepcopy` 能复制任何对象。

**回答：** 浅拷贝是新的外层容器，元素仍是原对象。切片、`list()`、`copy.copy` 都是浅的。`deepcopy` 递归复制，并用备忘录处理环。文件、锁、模块没有通用的复制语义，不要假设深拷贝会做对。

### 10. `__enter__` / `__exit__` 怎样抑制异常？

**常见错法：** 写了 `with` 就等于异常已经被处理。

**回答：** 离开 `with` 时一定会调用 `__exit__`。只有它返回真值才抑制异常。默认返回 `None`，异常继续传播。清理应当发生，错误仍应当可见。不要在 `finally` 或 `__exit__` 里 `return` 掉原来的异常。

### 11. 生成器里为什么不能 `raise StopIteration`？

**常见错法：** 这和 `return` 完全一样。

**回答：** 生成器的 `return` 会被转换成 `StopIteration`，这是结束迭代的正常方式。在生成器里直接 `raise StopIteration`，从 3.7 起会变成 `RuntimeError`。想提前结束就 `return`。

### 12. `NotImplemented` 和 `NotImplementedError`？

**常见错法：** 运算不支持时抛 `NotImplementedError`，或者返回 `None`。

**回答：** 特殊方法遇到自己不会处理的类型时，返回单例 `NotImplemented`，解释器再试另一边的反向方法，都不会才 `TypeError`。`NotImplementedError` 是给“子类还没实现”用的异常。两者不是拼写变体。

### 13. MRO 用的是什么算法？冲突时何时失败？

**常见错法：** 深度优先，从左到右，运行时再看找不找得到。

**回答：** C3 线性化。子类在基类前，声明时靠左的基类在靠右的前面，每个类只出现一次。违反单调性的声明在定义类时就抛 `TypeError`，不会留到调用时。权威顺序看 `类型.__mro__`。

### 14. 类装饰器和元类都能改类，选哪个？

**常见错法：** 都能改，所以选起来没有差别。

**回答：** 装饰器在类对象已经创建之后再处理它，显式写在类头上，读代码的人看得到。元类参与创建过程，子类会继承这个行为，即使子类作者没有再写一遍。需要“所有子类都被迫遵守”时才考虑元类或 `__init_subclass__`。只对一个类补充方法时用装饰器。
