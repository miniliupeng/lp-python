# C02　可变性、拷贝与身份

> 示例：`examples/part_c/c02_copy_identity.py`

## 学完你能做什么

在该拷贝的时候选出浅拷贝或深拷贝，并且把“小整数缓存”“常量合并”“字符串驻留”分成三件不同的事。

## 赋值仍然不拷贝

A02 的模型在这里不变。`alias = nested` 是第二个名字。要得到另一个容器，必须调用拷贝。

`copy.copy` 做浅拷贝：新的外层容器，里面的元素仍是原来的对象。示例里 `shallow[0].append(2)` 之后，原列表也变成 `[[1, 2]]`。外层 `is` 比较为假，内层是同一个列表。

`copy.deepcopy` 递归复制。示例再改深拷贝的内层，原列表不变。深拷贝用备忘录处理环：一个列表把自己放进自己，复制之后副本的第 0 项指向副本自己，而不是指向原来的列表。示例断言 `cloned[0] is cloned`。没有这个备忘录，环会变成无限递归。

深拷贝不是万能的。打开的文件、锁、模块、socket 没有一个通用的“再来一份”语义。`deepcopy` 遇到不支持的对象会抛异常，或者在你提供 `__deepcopy__` 之前拒绝。业务对象如果包含这些资源，不要指望 `deepcopy` 会做对，显式写一个复制方法，由你决定哪些字段是值、哪些字段是共享的资源。

## 可变性决定别名危不危险

不可变对象共享没有内容被改掉的风险，因为内容不能就地改。字符串、元组、数字可以放心让多个名字指着。元组里如果装着列表，浅拷贝和赋值一样危险，危险的是那个列表，不是元组的槽位。

`+=` 对列表可能就地改，对字符串一定是新对象。这在 A05。拷贝不能替代“这个 API 会不会就地修改”的文档。函数名是 `sort` 还是 `sorted`，本身就是契约的一部分。

## 三个容易混成一句的实现细节

**语言不保证** 相等的整数或字符串是同一个对象。下面三件事都是 CPython 的实现，而且触发条件不同。

1. **小整数缓存。** 解释器准备了 `-5` 到 `256`。动态构造的 `int("256")` 与另一个 `int("256")` 是同一对象。`int("257")` 不是。示例用这个方式观察缓存，因为字面量会被下一件事干扰。
2. **代码对象的常量合并。** 编译函数时，相同的常量放进常量表的同一格。`return 257` 每次返回的是这格里的对象，所以两次调用可以 `is` 为真，即使 257 不在小整数缓存里。A03 的 `returns_257` 就是这个现象。
3. **字符串驻留。** `sys.intern` 把字符串放进驻留表，内容相同的驻留字符串是同一个对象。自动驻留的规则（哪些字面量会自动进入表）可以随版本变，不要背。示例只保证：动态拼出来的 `"hello world"` 和字面量内容相等，但在 `intern` 之前不是同一个对象；显式 `intern` 之后是同一个。

因此业务代码比较值用 `==`。`is` 只用于 `None`、枚举成员，以及你自己刚刚建立、确实要判断别名的地方。

## `==` 的代价

容器的 `==` 递归比较元素。两个巨大的嵌套结构比较可能很慢。带环的列表互相 `==` 可能撞上递归上限。不要用嵌套结构的相等性当热路径上的缓存键。需要稳定摘要时，用明确的字段组成元组，或用哈希库对规范化后的字节计算摘要。

## 机制

赋值、参数传递、容器插入，放进去的都是引用。拷贝是另一条显式路径。

浅拷贝构造新的外层容器，元素仍是原来的引用。`list.copy()`、`dict.copy()`、`items[:]`、`copy.copy` 都是浅的。深拷贝递归复制，`copy.deepcopy` 会处理环，用备忘避免无限递归。深拷贝不复制模块、函数这类外部资源的语义。它也复制不了打开的文件。遇到自定义对象会走 `__deepcopy__` 或按实例字典重建。

身份、相等、哈希要分三列说：

| 问题 | 运算 | 业务里怎么用 |
| --- | --- | --- |
| 是不是同一个对象 | `is` | `None`、哨兵、证明别名 |
| 值等不等 | `==` | 几乎所有业务判断 |
| 能不能做键 | `hash` 与 `==` 一致 | 字典和集合 |

CPython 有三件容易混在一起的实现细节，都不是语言保证：

1. 启动时准备 `-5` 到 `256` 的整数对象。`int("256") is int("256")` 为真，`int("257") is int("257")` 为假。
2. 一个代码对象里相同的常量只存一份。函数两次 `return 257`，两次拿到的是同一格常量。
3. 短字符串可能被驻留。`intern` 可以显式驻留。业务代码不要依赖。

`==` 可以很贵，也可以有副作用，因为会调用 `__eq__`。把巨大结构的相等放在热路径上之前先想清楚。NaN 不等于自己，所以用 NaN 做字典键会得到反直觉的查找结果。不要这么做。

## 会出事的写法

- 配置字典 `defaults.copy()` 之后又改了里面的嵌套字典。外层是新的，内层仍共享。需要隔离用 `deepcopy`，或者一开始就不要共享可变配置。
- 深拷贝一棵挂着数据库会话的对象图。会话不该被复制。把数据对象和资源对象分开。
- `is` 比较从 JSON 读出的数字。JSON 的数字是新对象。
- 复制了列表却把同一个可变元素 append 进两个列表。复制的是容器，不是你后来插入的共享元素。

## 示例对照

`examples/part_c/c02_copy_identity.py` 对比赋值、浅拷贝、深拷贝对嵌套列表的影响，并用动态构造的整数区分缓存和常量合并。断言里应当能看到：浅拷贝后改内层，两边都变；深拷贝后只变一边。

## 加练

1. `a = [[1]]`，`b = copy.copy(a)`，`b[0].append(2)` 之后 `a` 是什么？`b = copy.deepcopy(a)` 再做同样的事呢？
2. 为什么 `is` 适合 `None`，不适合 `256`？

参考答案：

1. 浅拷贝后 `a` 变成 `[[1, 2]]`。深拷贝后再 append，原来的 `a` 仍是 `[[1]]`。
2. `None` 是语言级单例。`256` 只是 CPython 缓存范围内的一个实现细节，而且字面量比较还会触发语法警告。

## 面试

### Q1. 浅拷贝和深拷贝？

**考点**：复制到第几层。

**回答**：

1. 浅拷贝只新做外层容器，元素引用不变。
2. 深拷贝递归复制，并处理循环引用。
3. 不可变对象往往没有必要拷贝。拷贝的理由是后面会就地修改。

### Q2. 小整数和常量合并怎么讲才不算错？

**考点**：实现细节的边界。

**回答**：

1. 语言不保证相等整数是同一对象。
2. CPython 缓存 `-5` 到 `256`。要用动态构造观察，例如 `int("256")`。
3. 函数里两次返回字面量 `257` 仍可能是同一个对象，因为它们来自同一代码对象的常量表。这不能证明 257 被全局缓存。

### Q3. 什么时候不该 `deepcopy`？

**考点**：对象图里有资源。

**回答**：

1. 图里有文件、套接字、锁、数据库会话时，深拷贝没有明确语义。
2. 它是递归，大对象图会又慢又占内存。
3. 更好的做法是构造新的数据对象，只复制需要的字段。

## 常见错误

- 用切片 `items[:]` 以为是深拷贝。那是新列表加共享元素，和 `copy` 一样浅。
- 把 `257 is 257` 写进面试答案，声称“只有 -5 到 256 会被复用，所以这一定是假”。同一代码对象里的字面量可以复用。
- 深拷贝一个带锁的对象，然后在另一个线程使用副本的锁。锁不该被复制来“分开竞争”，两个线程如果应该互斥，它们必须用同一把锁。

## 练习

1. `a = [[1], [2]]`，怎样得到一个改内层也不影响 `a` 的副本？
2. 怎样演示 257 没有进入全局小整数缓存？
3. `sys.intern` 改变的是哪一种比较？

参考答案：

1. `copy.deepcopy(a)`。
2. `int("257") is int("257")` 为假。
3. 它让内容相同的字符串在 `is` 下为真。`==` 本来就为真。驻留是为了节省重复字符串并加快一部分查找，不是为了改变相等性。

## 小结

浅拷贝共享内层，深拷贝递归复制并能处理环。整数缓存、常量合并、字符串驻留是三件不同的 CPython 细节。值比较用 `==`，身份比较只用于单例和别名。
