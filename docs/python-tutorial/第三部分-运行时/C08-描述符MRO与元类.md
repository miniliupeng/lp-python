# C08　描述符、MRO 与元类

> 示例：`examples/part_c/c08_descriptors_mro.py`

## 学完你能做什么

按真实的属性查找顺序解释 `property`、方法和“赋值为什么没写进实例字典”。知道元类存在，并且多数时候用 `__init_subclass__` 就够了。

## 查找顺序

对实例取属性时，`object.__getattribute__` 大致按这个顺序：

1. 在类的 MRO 上找 **数据描述符**。数据描述符同时定义了 `__get__` 和 `__set__`（或 `__delete__`）。
2. 找实例 `__dict__`。
3. 在类的 MRO 上找普通属性和非数据描述符。非数据描述符只有 `__get__`。
4. 还没有，就调用 `__getattr__`，如果类定义了它。

函数是非数据描述符。从实例上取函数时，`__get__` 返回绑定方法。你可以在实例字典里放一个同名对象，盖住类上的函数，因为函数不是数据描述符。

`property` 是数据描述符。实例字典里就算有同名项，也轮不到它，赋值会进 `__set__`。这就是“为什么给 property 赋值不会在 `__dict__` 里出现这个公开名字”。

## 示例里的 `Field`

`Field` 在 `__set_name__` 里记下私有键 `_name`。`__set__` 把值写进 `obj.__dict__[self.private]`，`__get__` 再从那里读。公开名字 `name` 始终走描述符。示例断言 `user.name == "Ada"`，同时实例字典里的键是 `_name` 不是 `name`。

如果数据描述符的 `__get__` 又去 `getattr(obj, self.public)`，就会无限递归，因为公开名字再次进入描述符。存储键必须和公开名字错开，或者对象内部用另一种结构。这是写描述符时的实际约束，不是风格问题。

`__set_name__` 在类创建时被调用，参数是拥有这个描述符的类和属性名。用它，就不必在每个字段上重复写字符串。

## MRO 再看一次

B05 已经走过 `D, B, C, A`。描述符也沿这条线查找。子类的数据描述符盖住基类的同名描述符。`super()` 从 MRO 的下一站开始，所以合作式继承才能穿过菱形。这里没有新的顺序，只是把“方法解析”和“描述符解析”合成同一条规则：都在 MRO 上找。

## `__init_subclass__`

示例的 `Plugin` 在子类被创建时把子类放进 `registry`。基类自己不会因此进列表。注册插件、校验子类属性，优先用这个钩子。它是普通的继承方法，可读，也可调用 `super()`。

## 元类

类的类是 `type`。创建类时，解释器选出元类，准备命名空间，执行类体，然后调用元类。`RequireLabel` 在 `__new__` 里拒绝没有 `label` 的子类。示例因此无法定义 `Missing`。

元类影响它创建的整棵类树，也会和另一个元类冲突：两个不相关的元类不能简单组合成一个子类。能用 `__init_subclass__` 或装饰器解决的，就不要写元类。需要元类的典型场景是框架在类创建期改命名空间、而 `__init_subclass__` 的时机太晚。那是框架作者的工具。

`__slots__` 也在类创建期生效。它阻止实例字典，从而让拼错的属性名立刻失败，并省下字典的内存。槽不会自动包含基类的槽。有槽又想支持弱引用时，把 `__weakref__` 放进槽列表。这些是内存布局决定，不是装饰器能事后补上的。

## 机制

属性查找的顺序，面试时按这个序列说，不要漏掉数据描述符：

1. 数据描述符：类型上定义了 `__set__` 或 `__delete__` 的描述符，优先于实例字典。`property`、示例里的 `Field` 属于这一类。
2. 实例 `__dict__` 里的条目。
3. 非数据描述符：只定义了 `__get__`，例如函数。所以方法可以被实例属性遮住。
4. 继续沿 MRO 找类属性。
5. 找不到则调用 `__getattr__`，如果定义了的话。`__getattribute__` 是更早的钩子，覆盖它容易把查找弄断。

`Field` 在 `__set_name__` 里记住私有名，`__set__` 写入实例字典的 `_name`，`__get__` 从那里读。因此 `user.name` 不在字典的 `"name"` 键上，而在 `"_name"` 上。示例断言 `user.__dict__["_name"] == "Ada"`。通过类访问 `User.name` 时 `__get__(None, User)` 返回描述符自己。

MRO 用 C3 线性化。`D(B, C)` 且 `B` 和 `C` 都继承 `A` 时，顺序是 `D, B, C, A, object`，前提是这个顺序单调、能算出来。冲突的基类顺序会在类定义时 `TypeError`，而不是调用时才乱。`super()` 按这条链前进。

`__init_subclass__` 在子类被创建时调用，适合注册插件。示例里 `JsonPlugin` 出现在 `Plugin.registry`，`Plugin` 自己不在里面，因为它不是自己的子类。这比元类轻。

元类的 `__new__` 在类对象诞生前看到名字、基类和命名空间。示例的 `RequireLabel` 拒绝没有 `label` 的子类。元类会传染：子类的元类必须是父类元类的子类，两个不同元类的类很难一起继承。能用 `__init_subclass__` 或装饰器解决的，不要写元类。

## 会出事的写法

- 覆盖 `__getattribute__` 又在里面访问 `self.x`，造成递归。要用 `object.__getattribute__`。
- 数据描述符和非数据描述符搞反，以为实例字典总能压过 `property`。赋值 `obj.field = 1` 仍走 `property` 的 `__set__`。
- 为了注册子类写元类，团队没人能改。`__init_subclass__` 就够。
- 在类定义时做重活。元类和类体都在导入时执行。

## 示例对照

`examples/part_c/c08_descriptors_mro.py` 断言 `User("Ada").name == "Ada"`，字典里是 `_name`，`JsonPlugin` 被注册，以及缺少 `label` 的类在定义时 `TypeError`。类定义失败的断言写在 `try` 里。如果 `except` 没写，测试会误报成功。

## 加练

1. 实例字典里已经有 `"name"`，类上又有数据描述符 `name`。`obj.name` 读到哪一个？
2. 为什么两个都用了自定义元类的基类常常无法一起继承？

参考答案：

1. 读到数据描述符。数据描述符压过实例字典。要绕过它必须直接操作 `__dict__` 或 `object.__getattribute__`，业务代码不要这么做。
2. 子类需要一个同时是两边元类子类的元类。没有现成的合并时，类定义直接失败。所以元类要少。

## 面试

### Q1. 属性查找的顺序？

**考点**：数据描述符插在实例字典前面。

**回答**：

1. 数据描述符，然后实例字典，然后非数据描述符和类属性，沿 MRO。
2. 最后才是 `__getattr__`。
3. 方法是非数据描述符，所以实例属性可以遮住方法。`property` 是数据描述符，实例字典遮不住。

### Q2. 什么时候用元类？

**考点**：克制。

**回答**：

1. 需要在类创建时改命名空间或拒绝不合法的类，并且装饰器做不到。
2. 注册子类优先 `__init_subclass__`。改方法优先装饰器。校验字段优先描述符。
3. 元类会进入继承关系。多个元类冲突时类无法创建。框架作者偶尔用，业务代码很少需要。

### Q3. `__set_name__` 解决什么？

**考点**：描述符知道自己被赋给了哪个属性。

**回答**：

1. 类创建时，解释器把属主类和属性名告诉描述符。
2. 描述符才能生成 `_name` 这种私有键，而不必在构造描述符时手写字符串。
3. 这发生在类定义期，不是每次取值时。

## 常见错误

- 数据描述符把值存在公开名字下，再通过公开名字去读，造成递归。
- 用元类做“所有类都要记录日志”。那是装饰器或显式调用的事。
- 以为实例字典永远优先。数据描述符优先于实例字典。

## 练习

1. 把 `Field.__set__` 改成保存 `value` 的两倍，实例字典里的 `_name` 和 `user.name` 各是什么？可以自己改一份跑。示例当前保存原值。
2. `JsonPlugin` 在注册表里，`Plugin` 为什么可以不在？
3. 什么情况下两个基类无法同时继承？

参考答案：

1. 如果 `__set__` 写进两倍，`user.name` 和 `_name` 都会是两倍，因为 `__get__` 读的就是那个私有键。
2. `__init_subclass__` 在创建子类时运行，不会在创建 `Plugin` 自己时把它加入自己的表。示例的实现是这样写的。
3. 它们的元类冲突，而且没有一个元类是另一个的子类。解释器无法决定用哪一个来创建新类。

## 小结

数据描述符优先于实例字典，非数据描述符靠后。方法和 `property` 都是这套规则的例子。注册子类用 `__init_subclass__`。元类能在类创建时拒绝不完整的子类，也因此容易和别的元类冲突，默认不要用。
