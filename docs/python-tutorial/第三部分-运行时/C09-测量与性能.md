# C09　测量与性能

> 示例：`examples/part_c/c09_performance.py`

## 学完你能做什么

先用工具指出时间或内存花在哪，再谈优化。知道几条不会过时的结构事实，同时不背虚假的倍数。

## 先有问题，再有秒表

没有负载之前，所有“更快的写法”都只是风格。测量的顺序：

1. 用业务能感到的指标定义慢：一次请求的延迟、一个批处理的总时间、进程的常驻内存。
2. 用分析器看时间花在哪个函数，而不是凭感觉改最内层的循环。
3. 改一处，用同一组输入再测。测试要锁住结果仍然正确，示例对 `join` 和循环拼接做了这个正确性断言， **没有** 断言谁更快。

`timeit` 适合测一个表达式。它会多跑几次，避免你把一次调度抖动当成语言特性。测函数时把准备数据放进 `setup`，不要把构造数据的时间算进算法。

`cProfile` 是确定性分析器：记录每次函数调用。示例跑完 `by_join`，在统计文本里找到这个名字。它有开销，不适合直接长期开在生产流量上。3.15 把这套工具放进 `profiling.tracing`，`cProfile` 仍是别名。3.15 另外提供采样分析器 `profiling.sampling`（Tachyon），可以按 PID 附着，几乎不改代码。3.12 没有这个包，示例继续用 `cProfile`。

`tracemalloc` 追踪 Python 分配。示例启动它、分配一个列表、读出峰值。峰值大于等于 0 只说明 API 可用；真正用的时候比较两次快照的差，找出是哪一行在涨。它看的是 Python 对象分配，不是进程的全部 RSS，C 扩展自己申请的内存不一定出现在这里。

## 结构比微优化先

这些是复杂度，不是秒表：

- 列表按下标访问 O(1)，中间插入 O(n)，末尾追加均摊 O(1)。
- `deque` 两端 O(1)，中间按下标 O(n)。
- 字典和集合的平均查找 O(1)，最坏情况会退化。不要在依赖哈希碰撞的攻击面上用不受信任的键硬扛，标准库对字符串哈希有随机化，但你自己的 `__hash__` 如果返回常数就会退化。
- 循环里 `s += piece` 会反复复制。拼很多段用 `"".join`。两者结果相同，示例断言了这一点。哪一个更快，用 `timeit` 在你的数据量上测。
- 成员测试：在循环里反复 `x in some_list` 是 O(n) 乘以循环次数。先做成集合。

算法从 O(n²) 变成 O(n log n) 的收益，通常超过把局部变量改成另一种拼写。先看复杂度，再看常数。

## 值得知道、不值得迷信的点

- 局部变量通常比反复查找全局或属性便宜。3.11 的特化缩小了差距。把 `obj.method` 在循环外取一次，是可读性和速度往往一致的改法。
- 预编译正则、把 `cache` 加在纯函数上，针对的是“重复做同一件昂贵的事”。
- `__slots__` 省的是实例字典的内存，不是把 Python 变成另一种语言。热路径如果根本不在这些对象上，开槽没有体感。
- 对象创建不是免费的。在最内层循环里构造短命对象，分析器会把时间算在分配和回收上。这时再考虑复用或换算法。

进程、网络、数据库的一次往返通常比这些都贵。一个服务慢，先看它在不在等别的系统。C05 和 C06 的并发模型解决的是“等的时候能不能做别的事”，不是把一条 SQL 变成 O(1)。

## 常见错误

- 用一次 `time.time()` 包住很短的代码，比较两个相差无几的数字。用 `timeit` 或性能分析器。
- 在调试构建或打开了追踪的情况下做结论，然后拿到生产去承诺倍数。
- 为了快把代码改到测试不能表达其行为。没有正确性的速度不是优化。

1. 用 `timeit` 比较 `by_join` 和 `by_plus` 在 1 万个片段上的差别。把结论留在你自己的笔记里，不要写进断言。
2. `tracemalloc` 看不到哪一类内存？
3. 为什么示例不断言 `deque` 比列表快？

参考答案：

1. `timeit.timeit` 配 `setup` 构造 `parts = ["a"] * 10000`。跑完看数字，并确认两次结果字符串相等。
2. 不一定看得到扩展模块用分配器直接申请、又没有通过 Python 对象暴露的内存。进程 RSS 用操作系统工具看。
3. 示例要固定的是语义：两端可以弹出。速度取决于操作和数据量，不适合写成永远为真的断言。

## 小结

用 `cProfile`、`timeit` 和 `tracemalloc` 找到花费，再用同一输入证明结果没变。列表、双端队列、字典的复杂度比任何微优化口诀都稳定。3.15 才有标准库里的采样分析器，3.12 用 `cProfile`。
