# C05　GIL、线程与进程

> 示例：`examples/part_c/c05_threads_processes.py`

## 学完你能做什么

按工作负载选择线程、进程或“不要并发”。说清默认构建里的 GIL 保护什么、不保护什么。自由线程和子解释器放在 C07，避免和默认构建混成一句。

## GIL 是解释器的锁

在默认的 CPython 构建里，一个线程要执行 Python 字节码，必须先持有 GIL（全局解释器锁）。所以同一个进程、同一个解释器里，多条线程不会在两个核上同时执行 Python 字节码。这把锁保护的是解释器内部结构。它 **不是** 你的业务数据的锁。两个线程照样可以把自己的列表改坏，只要它们没有用你自己的锁。

GIL 会在一定时间后让出，好让别的线程跑。`sys.getswitchinterval()` 的默认值是 `0.005` 秒，示例断言了这个默认值。它是调度参数，不是“每 5 毫秒必然发生一次业务原子操作”。不要用切换间隔代替锁。

下面这些情况线程仍然有用：

- 等待文件、网络、锁。很多 C 扩展在等待时释放 GIL，别的线程可以跑。
- 把阻塞调用挪出主线程，让界面或事件循环继续。
- 组织并发的 I/O。真正的大量连接更常使用 asyncio，但线程池处理少量阻塞调用很常见。

纯 Python 的 CPU 计算加线程，通常不能随核数变快，还要付切换成本。示例故意不比较耗时，因为一次短跑的快慢不能当成规则。选择依据是工作是不是在等待 I/O，而不是某台机器上的一次秒表。

## 线程共享内存

示例用四条线程各加 1000 次。锁包住 `counter[0] += 1`，最后是 4000。`+=` 不是原子操作：它读取、加法、写回，中间可以插入另一条线程。没有锁时结果可能变小，但是不是变小取决于调度，测试不能靠“偶尔失败”当断言。所以示例只断言有锁的正确结果。

`threading.Lock` 是互斥锁。同一条线程重复获取非可重入的锁会死锁。`RLock` 允许同一条线程重入。锁的范围要短，只包住不变量被修改的那几行。先拿 A 锁再拿 B 锁、另一处先 B 后 A，是经典死锁。顺序写死，或者用一把锁。

`queue.Queue` 自己带锁，适合在线程之间移交对象。列表不带这种保证。把同一个列表交给多个线程 `append`，不要假设“GIL 让 append 变安全”这种口口相传的结论。容器的线程安全以文档为准，`queue.Queue` 的文档写了。

守护线程（`daemon=True`）在主线程结束时被直接停掉，`finally` 不一定执行。不要用守护线程写文件。让线程自己看一个退出标志，主线程 `join` 它。

## 进程不共享这把锁

每个进程有自己的解释器和自己的 GIL。`ProcessPoolExecutor` 把函数和参数序列化送进子进程，再把返回值送回来。示例计算平方，结果是 `[1, 4, 9]`。函数必须是顶层函数，子进程用 spawn 方式启动时要能重新导入它。文件用 `if __name__ == "__main__"` 保护入口，避免子进程再次执行启动代码。

进程的代价是复制或序列化。大对象传来传去可能比计算还贵。共享内存和 `multiprocessing` 的同步原语可以少复制，但复杂度立刻上升。CPU 密集、数据可以按任务切开时，进程池是默认构建上的常用办法。

进程崩溃不会自动回放你的 Python 栈到父进程的某一行。要有超时和失败可见性。`map` 会把子进程的异常重新抛到父进程，示例没有制造异常，是因为这一章要证明的是隔离计算，不是错误处理。超时和取消在 D07。

## 选择

| 负载 | 默认构建上的常用选择 |
| --- | --- |
| 等待网络或磁盘 | 线程，或 asyncio |
| 纯 Python 吃 CPU | 进程，或多解释器（3.14 标准库，见 C07） |
| 少量阻塞函数嵌在 async 程序里 | `asyncio.to_thread` |
| 只是代码更好读 | 不要加并发 |

## 机制

默认 CPython 构建里，执行 Python 字节码要先拿到 GIL。所以同一个解释器里，不会有两条线程同时在两个核上跑 Python 字节码。GIL 保护的是解释器内部结构，尤其是引用计数这种会并发改坏的状态。它不是你的列表、余额或缓存的锁。

GIL 会在检查间隔附近让出，也会在阻塞 I/O 时放开。`sys.getswitchinterval()` 默认 `0.005` 秒。这是调度参数，不是“每 5 毫秒业务操作原子一次”。很多 C 扩展在等待系统调用时调用允许线程的 API，于是别的线程可以跑。这就是 I/O 密集时线程仍然有用的原因。

`counter[0] += 1` 是读、加、写多条字节码。有 GIL 也会在中间让出。示例只用锁保护的结果做断言：四条线程各加 1000 次，结果是 4000。没有锁的结果取决于调度，不能写成“一定变小”的测试。

`threading.Lock` 不可重入，同一线程再拿会死锁。`RLock` 允许同一线程重入。锁要短，只包住不变量被修改的几行。持有锁时调用未知代码，对方再来拿锁就是死锁，对方很慢就把所有线程堵住。两把锁的获取顺序必须全局一致。

`queue.Queue` 自己带锁，用来移交对象。列表没有这种承诺。不要口口相传“GIL 让 `list.append` 原子所以安全”。即使某次实现里单条 `append` 在持有 GIL 时不拆开，这也不是你可以依赖的业务锁，而且自由线程构建下这个假设直接不成立。

`daemon=True` 的线程在主线程结束时被直接停掉，`finally` 不一定执行。不要用它写文件。用退出标志，主线程 `join`。

进程各有解释器和 GIL。`ProcessPoolExecutor` 把函数和参数序列化到子进程。函数必须是顶层函数，spawn 启动时子进程要能导入它。入口放在 `if __name__ == "__main__"` 里，避免子进程再次启动池。序列化大对象的成本可能超过计算。进程崩溃不会自动变成父进程某一行的 Python 回溯。`map` 会把子进程异常重新抛到父进程。

| 负载 | 默认构建上的选择 |
| --- | --- |
| 等待网络或磁盘 | 线程或 asyncio |
| 纯 Python 吃 CPU | 进程；3.14 起还可实验子解释器 |
| async 里少量阻塞函数 | `asyncio.to_thread` |
| 只是想让代码看起来高级 | 不要加并发 |

自由线程是另一种构建，不是这张表的默认列。C07 把版本说准确。在自由线程进程里，数据竞争更容易出现，锁不能少。

## 会出事的写法

- 用切换间隔代替锁。
- 持有锁时做网络请求。临界区变成所有线程的等待。
- 把巨大对象送进进程池，只为了在子进程里加一。
- 守护线程里 `flush` 文件。进程退出时写到一半。

## 示例对照

`examples/part_c/c05_threads_processes.py` 断言默认切换间隔是 `0.005`，带锁的计数是 4000，进程池对顶层 `square` 得到 `[1, 4, 9]`。它故意不比较耗时。一次短跑的快慢不是选型规则。

## 加练

1. 为什么示例不对“无锁计数一定小于 4000”做断言？
2. 进程池的函数为什么不能是嵌套函数？

参考答案：

1. 调度可能让这几次 `+=` 碰巧没有交错。测试会闪烁。正确性断言只写有锁的结果。
2. spawn 要按模块名导入可调用对象。嵌套函数无法被 pickle 找到。

## 面试

### Q1. GIL 是什么？它保护什么，不保护什么？

**考点**：不要把解释器锁说成业务锁，也不要说 2026 年默认已经没有 GIL。

**回答**：

1. 默认构建里，执行 Python 字节码前要持有这把锁。同一个解释器不会并行执行字节码。
2. 它保护解释器内部状态。你的不变量仍要自己的锁或队列。
3. 阻塞 I/O 会放开它，所以线程适合等待。纯 Python 计算用进程。自由线程是 3.13 实验、3.14 起官方支持的可选构建，不是默认解释器。用 `sys._is_gil_enabled()` 看当前进程，3.12 没有这个函数。

### Q2. 线程、进程、asyncio 怎么选？

**考点**：负载类型，而不是“哪个最快”。

**回答**：

1. 大量等待用 asyncio 或线程。asyncio 是单线程协作式，不能有人长时间占着不让出。
2. CPU 密集用进程，避开默认构建的 GIL。
3. 共享可变数据最少的方案最好。有共享就要锁、队列或进程间消息，并写明主人是谁。

### Q3. `queue.Queue` 和列表有什么差别？

**考点**：文档里的线程语义。

**回答**：

1. `queue.Queue` 的放入和取出是带锁的，可以在线程之间移交。
2. 列表没有这种契约。
3. 队列还可以有 `maxsize`，满了就阻塞，形成背压。列表会一直涨到内存耗尽。

## 常见错误

- “有 GIL，所以 Python 没有竞态。”GIL 不保护你的不变量。
- “有 GIL，所以线程没用。”I/O 会释放它。
- 在持有锁时调用未知代码。未知代码再来拿同一把锁，或者很慢，都会把并发毁掉。

## 练习

1. 为什么 `counter[0] += 1` 即使在有 GIL 的解释器里也要加自己的锁？
2. 进程池的 `square` 为什么定义在模块顶层？
3. `getswitchinterval` 的默认值能代替锁吗？

参考答案：

1. `+=` 是多条字节码。GIL 可能在中间让出。另一条线程会读到旧值。锁把这三步合成调用方眼里的临界区。
2. 子进程要按名字导入它。嵌套函数无法被 pickle 找到。
3. 不能。它只影响线程多久被换下，不保证你的几行代码独占数据。

## 小结

默认 CPython 用 GIL 让一个解释器里只有一条线程执行字节码。I/O 可以放开这把锁，所以线程适合等待。CPU 计算用进程分开解释器。共享数据的不变量要靠你自己的锁或队列，不靠 GIL。
