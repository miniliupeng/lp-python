# C03　引用计数与垃圾回收

> 示例：`examples/part_c/c03_gc.py`

## 学完你能做什么

分清 CPython 回收对象的两条路径：引用计数马上做掉没有环的对象，分代 GC 专门处理环。

## 主路径是引用计数

每个对象头部有一个计数，表示有多少引用指着它。名字绑定、容器插入、参数传递会增加；名字离开作用域、容器删除、引用被覆盖会减少。计数降到 0，CPython 立刻回收这个对象，并减少它所指对象的计数。这一步不需要等待 `gc.collect()`。

示例用弱引用观察这件事。`Node` 实例删除唯一的名字之后，`weakref.ref` 马上变成死的，中间没有调用 `gc.collect`。弱引用不增加目标的引用计数，所以它适合做这种观察。回调也只在目标被回收时触发。

弱引用对象自己必须还活着，回调才会被调用。示例把环上的弱引用放进 `held`，否则弱引用先被丢掉，回调根本不会登记到最后。这是 API 的使用约束，不是 GC 漏掉了对象。

内置的 `list`、`dict`、`int`、`str` 不能创建弱引用，示例对 `[]` 断言 `TypeError`。不是“所有对象都能弱引用”。用户定义的类默认可以，除非 `__slots__` 里没有 `__weakref__` 又没有实例字典。

## 环需要另一条路径

`left.other = right` 且 `right.other = left` 时，即使删掉两个名字，计数也不会到 0，因为它们互相指着。引用计数看不见这个环已经从程序的根（栈、全局、寄存器里的引用）走不到了。

CPython 还有一个分代循环检测器，标准库接口是 `gc`。它从容器出发找环，确认环上没有外部引用后回收。示例在 `del` 之后调用 `gc.collect()`，两个回调都触发。不手动 `collect` 时，分配积累到阈值也会自动跑。阈值可以用 `gc.get_threshold()` 看，默认三代的阈值是实现参数，写代码时不要依赖“再分配 700 次就一定会回收”。

三代的意思是：熬过一次收集的对象移到更老的一代，老一代收集得更少。长寿对象不需要每次都扫描。这是性能策略，不是“第三代的对象永远不回收”。

## `__del__` 和复活

对象可以定义 `__del__`。计数到 0 时 CPython 会调用它。环上的终结器历史上很麻烦。PEP 442 之后，CPython 可以回收含 `__del__` 的环，但终结器的调用顺序不应被依赖，而且 `__del__` 里如果又把 `self` 存到全局，对象会“复活”。不要用 `__del__` 关闭文件或释放锁。那是 `with` 的工作。`__del__` 适合解释器自己的内部清理，普通业务几乎不写。

## 其他实现不一样

PyPy 不用引用计数当主路径，对象可能活得比 CPython 更久。所以“删掉名字就立刻调用了 `__del__`”不是语言保证。语言保证的是：对象在不可达之后，**最终**可以被回收，终结器最多相关于实现。需要及时释放的资源用上下文管理器，不要赌 GC 的时机。

`gc.disable()` 会关掉循环检测，不会关掉引用计数。关掉之后环就泄漏了。只有在确认程序不产生环、并且你在做特殊的延迟控制时才考虑，结束前要知道自己在做什么。一般服务不要关。

## 机制

CPython 的主路径是引用计数。每个对象头部有计数。名字绑定、容器插入、传参增加；解绑、删除、覆盖减少。降到 0 就立刻回收，并顺着减少它所引用对象的计数。这一步不经过 `gc.collect`。示例用弱引用观察：删掉唯一名字后，`ref()` 马上是 `None`。

环是计数的盲区。`left.other = right` 且 `right.other = left`，删掉外部名字后计数仍不为 0。分代循环检测器从被跟踪的容器出发找环。`gc.collect()` 返回不可达对象的计数，示例则用回调证明两个节点都被回收。

默认阈值 `gc.get_threshold()` 是 `(700, 10, 10)`。含义是调度参数：分配减去释放超过第一阈值时收集年轻代；老一代按更低的频率被纳入。不要写成“每分配 700 个对象就一定会回收我的环”。阈值可以改，一般服务不要改，除非你在测量之后知道自己在做什么。

三代是性能策略。熬过收集的对象晋升，长寿对象少扫描。第三代不是永不回收。

弱引用不增加计数。`weakref.ref(obj, callback)` 在对象回收时调用回调。弱引用对象自己必须活着，否则回调不会留下。示例把它们放在 `held` 里。`list`、`dict`、`int`、`str` 不能创建弱引用。用户类默认可以，除非 `__slots__` 去掉了 `__weakref__` 且没有实例字典。`WeakValueDictionary` 适合缓存：外部不再持有对象时，缓存条目自动消失。

`__del__` 在计数到 0 时调用。环上的终结器在 3.4 之前很难处理，含 `__del__` 的环可能进 `gc.garbage` 永不回收。PEP 442 之后，CPython 可以回收这种环，但调用顺序不要依赖，`__del__` 里把 `self` 存到全局还会复活对象。资源释放用 `with`。

PyPy 不以引用计数为主路径。语言不保证“删掉名字立刻调用 `__del__`”。需要及时释放的资源不要赌 GC。

`gc.disable()` 只关循环检测，不关引用计数。环会泄漏。不要在普通服务里关。

## 会出事的写法

- 全局缓存用普通字典持有所有用户对象。没有淘汰，就没有回收。用弱引用或带上限的 LRU。
- `del obj` 写成“销毁”。`del` 只解绑这个名字。
- 在 `__del__` 里拿锁、写日志、调用业务。解释器关闭期间顺序不可靠。
- 用 `gc.get_objects()` 在生产请求路径上转储全部对象。它会干扰运行，只适合诊断。

## 示例对照

`examples/part_c/c03_gc.py` 先证明无环对象不必 `gc.collect`，再对 `[]` 断言不能弱引用，然后构造环，在 `held` 里保住带回调的弱引用，`gc.collect()` 之后 `set(gone) == {"L", "R"}`。少了 `held`，回调可能根本不运行，这不是 GC 漏了对象。

## 加练

1. 为什么示例在 `del left, right` 之后还要 `gc.collect()`？无环的那个实验为什么不需要？
2. `WeakValueDictionary` 怎样避免缓存把对象留到进程结束？

参考答案：

1. 环不会因为引用计数到 0 而被回收，所以要循环检测器跑一次。无环对象在最后一个强引用消失时已经回收，弱引用立刻变死。
2. 字典的值是弱引用。外部强引用没了，条目自动去掉，缓存不再增加计数。键如果是强引用的字符串，字符串本身还在，值指向的大对象可以走。

## 面试

### Q1. 引用计数、标记清除、分代各管什么？

**考点**：三条机制的分工，不要说成只有 GC。

**回答**：

1. 引用计数是 CPython 的主路径。到 0 立刻回收。收不了环。
2. 循环检测器追踪容器，找出从根不可达的环再回收。算法可以描述成对容器间引用做扣减后的不可达判定。
3. 分代把收集的频率按对象寿命分开，年轻代更常被看。这是调度，不是第三种“会漏掉老对象”的正确性规则。

### Q2. 带 `__del__` 的环现在还会让 GC 罢工吗？

**考点**：PEP 442，以及为什么仍不要依赖 `__del__`。

**回答**：

1. 3.4 之前，环里如果有 `__del__`，解释器无法安全决定顺序，对象可能留在 `gc.garbage`。
2. PEP 442 之后可以回收这类环。
3. 顺序仍不可依赖，复活仍可能。文件和锁用上下文管理器。

### Q3. 哪些对象不能做弱引用？

**考点**：类型是否支持弱引用槽。

**回答**：

1. 内置的 `list`、`dict`、`int`、`str` 不行，`weakref.ref` 抛 `TypeError`。
2. 用户类默认可以。
3. `__slots__` 如果没有 `__weakref__` 且没有 `__dict__`，实例也不能。缓存设计不要假设任意对象都能弱引用。

## 常见错误

- 说“Python 只靠 GC，所以删除是异步的”。没有环的对象在 CPython 里是同步回收的。
- 用 `del 名字` 表示“请马上销毁对象”。`del` 只解绑名字。还有别的引用时对象还在。
- 在 `__del__` 里写日志、拿锁、调用业务方法。它可能发生在任意时刻，也可能在解释器关闭期间，顺序都不可靠。

## 练习

1. 没有环的对象，示例靠什么证明它不必等待 `gc.collect`？
2. 为什么两个 `Node` 必须互相引用，这个实验才能说明循环 GC？
3. 关闭文件应该放在哪里？

参考答案：

1. 删除唯一名字后，弱引用立刻变成 `None`，中间没有 `gc.collect`。
2. 如果没有环，引用计数已经把它们收掉了，看不出循环检测器的作用。
3. `with` 或明确的 `close()`。不要放进 `__del__`。

## 小结

CPython 用引用计数回收不可达且无环的对象，用分代 GC 回收环。弱引用用来观察回收，且不能加在 `list` 和 `int` 上。及时释放资源靠上下文管理器，不靠终结器。
