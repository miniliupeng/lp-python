# C01　执行模型与对象

> 示例：`examples/part_c/c01_execution.py`

## 学完你能做什么

把“函数在运行”拆成代码对象、帧和对象这三样能指认的东西。后面的字节码、GC 和 GIL 都建立在这张图上。

## 代码对象

`def add` 执行完后，`add.__code__` 是一个 `code` 对象。它里面已经没有源码文本，而是：

- `co_code`：字节码，类型是 `bytes`。
- `co_consts`：常量，例如字面量数字和字符串。
- `co_varnames`：局部变量名。示例里前两个是 `left` 和 `right`。
- `co_names`：全局名字和属性名。
- `co_filename`、`co_firstlineno`：回溯用来指出位置。

同一个函数对象共享这份代码对象。每次调用不重新编译。编译发生在函数定义时，或者模块导入时。这就是 A01 说的“先编译再执行”。

交互式解释器每一行也可能单独编译。所以在 REPL 里观察到的常量和在函数里观察到的常量，不一定是同一次编译的结果。比较身份时以脚本里的断言为准。

## 帧

一次调用对应一个帧。帧保存局部变量、上一条指令的位置，以及回到调用者所需的信息。`sys._getframe()` 能拿到当前帧。下划线表示它是实现提供的检查工具，不是业务 API。示例只用它确认当前帧的代码对象名字是 `main`。

递归每深入一层就多一个帧。帧太多会 `RecursionError`。这不是堆内存“用完了”的同义词，默认递归上限是解释器的保护值，可以用 `sys.setrecursionlimit` 调整。调大它不会把一个指数递归变成好算法，只是让它更晚失败。

`return` 把值交给调用者的帧，然后丢掉当前帧。局部名字随之消失。名字消失不等于对象消失：如果返回值还指着它，或者别的容器还指着它，对象还在。下一章和 C03 把“没有名字”与“没有引用”分开。

## 对象在概念上长什么样

CPython 里每个对象都有一块头部：引用计数、类型指针。类型指针说明这个对象是 `int` 还是 `list`。后面才是类型自己的数据，例如整数的数值、列表的元素指针数组。

这是 C 结构，不是 Python 语法的一部分。你不能在纯 Python 里改类型指针。知道它的存在，是为了理解三件事：

1. 类型在对象上，所以名字可以重新绑定到另一种对象。
2. 引用计数在头部里，删掉一个名字通常就是把头里的计数减一。
3. 容器保存的是指针，不是把子对象嵌进自己的字节里。列表的元素是别的对象。

`id(obj)` 在 CPython 里来自对象的内存地址。地址会在对象被回收后复用。所以 `id` 相等只在两个对象都还活着时表示“是不是同一个”。不要把 `id` 存进数据库当永久主键。

## 变量不是盒子

名字在命名空间里。模块的命名空间是一个字典，`globals()` 能看到。函数的局部变量为了快，放在帧里的数组中，不放在一个每次按名字查找的字典里。因此 `locals()` 在函数里的语义要小心：3.13 起（PEP 667）规定，优化作用域（函数、生成器、推导式等）里 `locals()` 返回独立快照，改这个字典不会改局部变量。3.12 的历史行为已经接近“改了也不影响局部变量”，但标准是在 3.13 写清的。不要写依赖 `locals()["x"] = 1` 的代码。

类体执行期间的局部命名空间就是将来的类字典。这是少数你能直接看到“名字到对象”映射的地方。

## 机制

一次函数调用在 CPython 里可以看成四样东西：代码对象、帧、求值栈、对象。

代码对象是编译结果，不可变。它装着字节码、常量、名字、局部变量名。函数对象指向代码对象，另外带着默认值、闭包和全局命名空间。多个函数可以共享结构相同的代码对象，闭包不同。

帧是一次调用的现场。局部变量、指令指针、求值栈、指向上一帧的链接都在这里。递归是一串帧。`sys.getrecursionlimit()` 限制的是这串的长度，不是对象个数。3.11 以后帧的实现有专门化，调试器看到的“帧”仍是这个概念。

对象在概念上有三块：类型指针、引用计数（CPython）、以及类型自己的数据。`int` 的数据是数字，`list` 的数据是指向元素的指针数组，实例通常还有 `__dict__`。变量不是盒子。名字在命名空间里，盒子这个比喻会让人以为赋值会复制。

`PyObject` 是 C API 里的结构名。业务代码碰不到它。面试可以说“每个对象头部有类型和引用计数”，不要编造字段布局随版本会变的细节。自由线程构建为了去掉 GIL，引用计数的实现会更复杂（偏向引用计数等）。那是 3.13 以后的可选构建，不是 3.12 默认对象的布局。

类型对象本身也是对象，类型是 `type`。`type(1) is int`，`type(int) is type`。类语句的结果就是调用元类得到类型对象。

## 会出事的写法

- 用 `id()` 在对象被回收之后比较。数字的 `id` 可能被新对象复用。`id` 只在对象活着时有意义。
- 把帧当成可以随便保存的业务对象。帧会在函数返回后失效。需要的数据复制出来。
- 在追踪回调里分配大量对象，改变了本来要观察的分配行为。
- 把“Python 没有栈”说成绝对事实。帧是栈式分配的调用链。对象在堆上。两句话都要在。

## 加练

1. 函数返回后，局部变量还在吗？怎样证明你不该保存帧？
2. `id(obj)` 相等能否说明以前那个对象一直没死？

参考答案：

1. 不在。局部变量属于帧，返回时帧销毁，引用减少。若这是最后一个引用，CPython 会立刻回收无环对象。把局部对象返回给调用方，是调用方持有引用，不是帧还活着。
2. 不能。对象死后 `id` 可以给新对象。只有两个活着的引用同时存在，`is` 才有意义。

## 面试

### Q1. 代码对象和函数对象有什么差别？

**考点**：编译结果和运行时闭包是分开的。

**回答**：

1. 代码对象是字节码和常量，不含具体的默认值绑定和闭包单元。
2. 函数对象指向代码对象，并带上全局命名空间、默认值和闭包。
3. 所以同一个函数定义在循环里如果做成闭包，代码对象结构相同，捕获的单元不同。

### Q2. 变量在栈上还是堆上？

**考点**：名字和对象分开。

**回答**：

1. 对象在堆上，由引用计数和 GC 管理。
2. 名字在命名空间里。函数的局部命名空间属于帧。
3. 不要说“Python 把变量存在寄存器里所以很快”或“全部在栈上”。赋值是绑定，不是把值拷进栈上的格子。

### Q3. 为什么说万物皆对象，又说 `None` 只有一个？

**考点**：对象模型和单例不矛盾。

**回答**：

1. `None` 是对象，类型是 `NoneType`。
2. 解释器只创建一个，所以 `is None` 稳定。
3. 小整数缓存不是这种语言级单例。数字相等用 `==`。

## 常见错误

- 把 `inspect` 或 `sys._getframe` 用在业务逻辑里取调用者。那是调试和框架的工具，普通调用应当显式传参。
- 认为每一行源码对应一条字节码。一条语句常常是多条指令，编译器还会做常量折叠。
- 把 `id` 当成稳定的对象编号保存下来。

## 练习

1. 打印 `add.__code__.co_varnames`，确认参数名还在代码对象里。
2. 函数返回之后，局部变量的帧还在吗？对象呢？
3. 为什么说“Python 变量没有类型”这句话需要改写？

参考答案：

1. 示例已经断言前两项是 `("left", "right")`。
2. 帧在返回时丢掉。对象如果被返回值或其他名字引用，就还在。
3. 名字没有固定类型，对象有。类型指针在对象上。

## 小结

函数共享一个代码对象，每次调用新建一个帧。对象带类型和引用计数，容器保存指向别的对象的指针。`id` 只在对象存活时有身份意义。`locals()` 不是修改局部变量的 API。
