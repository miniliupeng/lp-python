# C08　描述符、MRO 与元类

> 示例：`examples/part_c/c08_descriptors_mro.py`

## 学完你能做什么

按真实的属性查找顺序解释 `property`、方法和“赋值为什么没写进实例字典”。知道元类存在，并且多数时候用 `__init_subclass__` 就够了。

## 查找顺序

对实例取属性时，`object.__getattribute__` 大致按这个顺序：

1. 在类的 MRO 上找 **数据描述符**。数据描述符同时定义了 `__get__` 和 `__set__`（或 `__delete__`）。
2. 找实例 `__dict__`。
3. 在类的 MRO 上找普通属性和非数据描述符。非数据描述符只有 `__get__`。
4. 还没有，就调用 `__getattr__`，如果类定义了它。

函数是非数据描述符。从实例上取函数时，`__get__` 返回绑定方法。你可以在实例字典里放一个同名对象，盖住类上的函数，因为函数不是数据描述符。

`property` 是数据描述符。实例字典里就算有同名项，也轮不到它，赋值会进 `__set__`。这就是“为什么给 property 赋值不会在 `__dict__` 里出现这个公开名字”。

## 示例里的 `Field`

`Field` 在 `__set_name__` 里记下私有键 `_name`。`__set__` 把值写进 `obj.__dict__[self.private]`，`__get__` 再从那里读。公开名字 `name` 始终走描述符。示例断言 `user.name == "Ada"`，同时实例字典里的键是 `_name` 不是 `name`。

如果数据描述符的 `__get__` 又去 `getattr(obj, self.public)`，就会无限递归，因为公开名字再次进入描述符。存储键必须和公开名字错开，或者对象内部用另一种结构。这是写描述符时的实际约束，不是风格问题。

`__set_name__` 在类创建时被调用，参数是拥有这个描述符的类和属性名。用它，就不必在每个字段上重复写字符串。

## MRO 再看一次

B05 已经走过 `D, B, C, A`。描述符也沿这条线查找。子类的数据描述符盖住基类的同名描述符。`super()` 从 MRO 的下一站开始，所以合作式继承才能穿过菱形。这里没有新的顺序，只是把“方法解析”和“描述符解析”合成同一条规则：都在 MRO 上找。

## `__init_subclass__`

示例的 `Plugin` 在子类被创建时把子类放进 `registry`。基类自己不会因此进列表。注册插件、校验子类属性，优先用这个钩子。它是普通的继承方法，可读，也可调用 `super()`。

## 元类

类的类是 `type`。创建类时，解释器选出元类，准备命名空间，执行类体，然后调用元类。`RequireLabel` 在 `__new__` 里拒绝没有 `label` 的子类。示例因此无法定义 `Missing`。

元类影响它创建的整棵类树，也会和另一个元类冲突：两个不相关的元类不能简单组合成一个子类。能用 `__init_subclass__` 或装饰器解决的，就不要写元类。需要元类的典型场景是框架在类创建期改命名空间、而 `__init_subclass__` 的时机太晚。那是框架作者的工具。

`__slots__` 也在类创建期生效。它阻止实例字典，从而让拼错的属性名立刻失败，并省下字典的内存。槽不会自动包含基类的槽。有槽又想支持弱引用时，把 `__weakref__` 放进槽列表。这些是内存布局决定，不是装饰器能事后补上的。

## 常见错误

- 数据描述符把值存在公开名字下，再通过公开名字去读，造成递归。
- 用元类做“所有类都要记录日志”。那是装饰器或显式调用的事。
- 以为实例字典永远优先。数据描述符优先于实例字典。

## 练习

1. 把 `Field.__set__` 改成保存 `value` 的两倍，实例字典里的 `_name` 和 `user.name` 各是什么？可以自己改一份跑。示例当前保存原值。
2. `JsonPlugin` 在注册表里，`Plugin` 为什么可以不在？
3. 什么情况下两个基类无法同时继承？

参考答案：

1. 如果 `__set__` 写进两倍，`user.name` 和 `_name` 都会是两倍，因为 `__get__` 读的就是那个私有键。
2. `__init_subclass__` 在创建子类时运行，不会在创建 `Plugin` 自己时把它加入自己的表。示例的实现是这样写的。
3. 它们的元类冲突，而且没有一个元类是另一个的子类。解释器无法决定用哪一个来创建新类。

## 小结

数据描述符优先于实例字典，非数据描述符靠后。方法和 `property` 都是这套规则的例子。注册子类用 `__init_subclass__`。元类能在类创建时拒绝不完整的子类，也因此容易和别的元类冲突，默认不要用。
