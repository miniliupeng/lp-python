# A08　列表、元组、字典、集合

> 示例：`examples/part_a/a08_collections.py`

## 学完你能做什么

按语义选择容器，避开共享内层列表、不可哈希键，以及“元组并不保护里面的列表”这三件事。

## 列表是动态数组

`list` 按下标访问是 O(1)，末尾 `append` 均摊 O(1)，在开头插入是 O(n)，因为后面的元素要挪动。它不是链表。排序用 `sorted(nums)` 得到新列表，`nums.sort()` 就地排序并且返回 `None`。就地排序是稳定的：相等元素保持原有相对顺序。

切片 `nums[1:3]` 是新列表。`nums[::-1]` 是反转后的新列表。

最容易犯的共享错误：

```python
aliased = [[0] * 2] * 2
aliased[0][0] = 1
assert aliased == [[1, 0], [1, 0]]
```

`[0] * 2` 里的元素是整数，整数不可变，内层列表这样构造没问题。外层的 `* 2` 复制的是 **对同一个内层列表的引用**。改一处，另一处跟着变。要两行独立的列表，用推导式：

```python
safe = [[0] * 2 for _ in range(2)]
```

推导式在 B02 系统讲。这里先把它当成“每次循环新建一个列表”的写法。

## 元组不可变，元素未必

`(1, 2)` 创建后不能换掉第 0 项。单元素元组必须写成 `(1,)`，`(1)` 只是括号里的整数。

```python
box = ([1],)
box[0].append(2)
assert box == ([1, 2],)
```

元组保护的是“这几个槽位还指着原来的对象”，不保护那些对象的内部。需要整个结构都不可变时，槽位里也得放不可变对象，或者改用别的类型。3.15 的 `frozendict` 才是内置的不可变映射，而且它 **不是** `dict` 的子类；3.12 没有这个内置类型。

元组比列表省一点内存，也能做字典键（前提是里面的元素都可哈希）。“暂时不想被改”不是使用元组的充分理由，列表配约定往往更诚实。多个返回值、固定记录，用元组很合适；字段一多，就改用 B07 的 dataclass，免得记住下标 0 是什么。

## 字典保持插入顺序

从 Python 3.7 起，`dict` 的迭代顺序就是插入顺序，这是 **语言保证**，不是 CPython 的偶然。3.6 的 CPython 已经按插入顺序实现，但当时还不是语言规则。

键必须可哈希。列表不能做键，元组可以，只要元组里每一个元素都可哈希。`scores.get("linus")` 在缺失时给出 `None`，也可以给一个默认值。用 `scores["linus"]` 则会抛 `KeyError`。

`in` 判断的是键，不是值。要看值，显式写 `value in scores.values()`。

覆盖一个已有键不会改变它的位置。删掉再插入，会排到当前顺序的末尾。

## 集合是不重复的键

`set` 无序，语言 **不保证** 遍历顺序。成员检测平均是 O(1)。元素必须可哈希，所以 `{[1]}` 会抛 `TypeError`。需要不可变集合时用 `frozenset`，它可以放进另一个集合或当字典键。

去重且要保持第一次出现的顺序时，不要依赖 `set`。用字典：

```python
unique = list(dict.fromkeys(items))
```

3.7 以后这利用了插入顺序。

## 哈希和相等是一对

能放进集合或当字典键的对象，必须实现稳定的哈希，并且和相等性兼容：如果 `a == b`，那么 `hash(a) == hash(b)`。可变列表的内容会变，所以它拒绝被哈希，这是保护，不是限制你。你自己写的类如果定义了 `__eq__` 却留下默认的按身份哈希，对象会变成不可哈希。B06 和 C02 会回到这个契约。

## 选择

| 需求 | 用 |
| --- | --- |
| 有序、可重复、按下标 | `list` |
| 固定一组字段，整体不可变 | `tuple` 或以后的 dataclass |
| 键值，插入顺序有意义 | `dict` |
| 只关心是否出现过 | `set` |
| 两端频繁插入删除 | `collections.deque`，B11 |

## 机制

列表是动态数组。按下标读取是均摊 O(1)，末尾 `append` 均摊 O(1)，在开头插入是 O(n)，因为后面的元素要搬移。它保持插入顺序，允许重复。

元组的大小固定，槽位不能重新绑定。槽位里的对象如果可变，那个对象仍能改。元组比列表省一点内存，也可以做字典键，前提是里面的元素都可哈希。

字典是插入有序的哈希表。语言从 3.7 起保证遍历顺序等于插入顺序。这不是“排序”。键必须可哈希，并且和 `__eq__` 一致：相等的键必须有相等的哈希。字典的平均查找是 O(1)，哈希冲突和扩容时不是。不要把一次微基准写成“字典永远 O(1)”。

集合是没有值的键集合。`in` 平均 O(1)，列表的 `in` 是 O(n)。集合不保证顺序。需要去重又要保持第一次出现的顺序时，用字典：`dict.fromkeys(items)`。

哈希契约：

1. 生命周期内，参与哈希的内容不能变。所以列表不能做键，元组里套列表也不能。
2. `a == b` 为真时，`hash(a) == hash(b)` 必须为真。
3. 不可哈希的对象放进集合会 `TypeError`。这是好事，它挡住了“以后改了对象、集合就找不回”的坑。

切片是新序列，不共享外层容器，但元素对象仍共享。`items[:]` 是浅拷贝。嵌套列表用 `[:]` 复制外层后，内层仍是同一个列表。

## 会出事的写法

- `grid = [[0] * 3] * 3`。三行是同一个列表。改 `grid[0][0]` 会改掉每一行。正确是 `[[0] * 3 for _ in range(3)]`。
- 遍历字典时增删键。可能抛 `RuntimeError`。先收集要删的键，或者遍历 `list(d)`。
- 用列表当集合做 `in`。数据到十万以后每次查找都扫一遍。成员判断用 `set`。
- 把仍会变化的自定义对象放进集合。你改了参与哈希的字段之后，集合就丢了它。

## 加练

1. 把 `[1, 1, 2, 1]` 去重并保持第一次出现的顺序。
2. `point = (1, [])`，`point[1].append(2)` 之后元组变了吗？`point[1] = []` 呢？

参考答案：

1. `list(dict.fromkeys([1, 1, 2, 1]))` 得到 `[1, 2]`。不要用 `set`，它不保证顺序。
2. 第一句成功，元组仍是原来的对象，里面的列表变成 `[2]`。第二句 `TypeError`，不能给元组槽位重新赋值。

## 面试

### Q1. 列表和元组怎么选？

**考点**：可变性是语义，不只是性能。

**回答**：

1. 长度和内容会变，用列表。记录一组不该被换槽的字段，用元组或 dataclass。
2. 元组可以哈希当键，仅当所有元素都可哈希。
3. 元组不可变不等于深不可变。里面的列表仍能改，改了之后如果这个元组已经当过键，哈希契约就被破坏。不要把含可变元素的元组当键。

### Q2. 字典为什么有序，集合为什么不能依赖顺序？

**考点**：语言保证和实现细节。

**回答**：

1. 字典的插入顺序从 3.7 起是语言保证。
2. 集合没有这个保证。两次运行、两种实现，遍历顺序都可以不同。
3. 需要稳定去重就用 `dict.fromkeys`。需要排序就显式 `sorted`。

### Q3. `in` 对列表和集合的差别？

**考点**：复杂度，以及什么时候微优化是错的问题。

**回答**：

1. 列表是线性扫描，集合是平均常数时间的哈希查找。
2. 元素必须可哈希才能进集合。
3. 数据量小的时候两者都可以。数据量上去、查找在热路径上，用集合。先确认这是热点，再改，见 C09。

## 常见错误

- `row = [0] * n` 没问题，`grid = [[0] * n] * m` 有问题。
- 遍历字典时增删键。需要修改时遍历键的快照：`list(scores)`。
- 认为 `set` 会按插入顺序遍历。不要写依赖这个顺序的代码。

## 练习

1. 为什么 `sorted` 之后原列表的第 0 项还是 `3`？看示例里的 `nums`。
2. 构造一个可以当字典键的“坐标”，并说明为什么列表不行。
3. `d = {}`，依次执行 `d["a"] = 1`、`d["b"] = 2`、`d["a"] = 3`。`list(d)` 是什么？

参考答案：

1. `sorted` 返回新列表。`list.sort` 才就地排序，而且返回 `None`。
2. `(x, y)` 这种全是不可变元素的元组可以。列表可被就地修改，哈希不能跟着内容漂。
3. `["a", "b"]`。更新已有键不改变插入位置。

## 小结

列表是动态数组。元组的不可变只到槽位为止。字典从 3.7 起保证插入顺序，集合不保证顺序。嵌套列表不要用外层乘法复制。键和集合成员必须可哈希，且哈希要与相等性一致。
