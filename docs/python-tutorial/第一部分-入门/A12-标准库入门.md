# A12　标准库入门地图

> 示例：`examples/part_a/a12_stdlib.py`

## 学完你能做什么

遇到常见任务时先去标准库，而不是抄一段来源不清的代码。这一章不是把标准库讲完，那会比整本教程还长。

## 怎么查

官方文档的库参考按模块索引。你本机的版本用 `python -m pydoc json` 或交互式 `help(json)` 查看，避免看错到 3.15 才有的函数然后在 3.12 上调用。

本教程后面会用到、现在先认识的模块：

| 模块 | 用来做什么 | 不要用来做什么 |
| --- | --- | --- |
| `json` | 读写 JSON 文本 | 当配置语言的全部（想要注释和更安全的类型时，TOML 用 3.11 就有的 `tomllib` 读） |
| `pathlib` | 路径 | 手工拼分隔符 |
| `datetime` | 时刻和日历 | 用朴素 datetime 表示“这个瞬间”还不带时区 |
| `math` | 浮点数学 | 精确十进制，那是 `decimal` |
| `statistics` | 均值、中位数 | 代替专业统计推断库 |
| `random` | 模拟、洗牌 | 生成密码、令牌。密码学用 `secrets` |
| `argparse` | 命令行参数 | 在库模块顶层解析 `sys.argv` |

## JSON

`json.loads` 把文本变成 Python 对象：对象变成 `dict`，数组变成 `list`，`null` 变成 `None`。`json.dumps` 反向走。字典的键会变成字符串。不是 JSON 能表示的对象，例如集合、字节、自定义类，需要你自己转换，否则 `TypeError`。

示例里 `sort_keys=True` 是为了断言稳定，不是业务必需。JSON 对象的规范并不关心键顺序；Python 读回来的 `dict` 会保留文本里的顺序。

## 时间

```python
from datetime import UTC, datetime

moment = datetime(2026, 11, 7, tzinfo=UTC)
```

`UTC` 是 3.11 加入 `datetime` 的常量。带 `tzinfo` 的叫 aware，不带的叫 naive。一个表示“事件发生瞬间”的值应该是 aware。只表示“墙上的年月日”可以是 `date`，不必强行变成时刻。

不要用 `datetime.utcnow()`，它产生的是 naive 对象，3.12 已经把它标为弃用。用 `datetime.now(UTC)`。

## 随机

`random.Random(0)` 得到一个独立的生成器，种子固定，测试就可以断言序列。不要用全局的 `random.seed` 影响整个进程，别的库可能也在用它。

示例比较两个同一种子的生成器，序列一致。没有种子的 `random` 不适合放进断言。

## 你现在不必装的东西

HTTP 客户端、数据库驱动、类型校验、Web 框架都有成熟的第三方库。A 阶段用标准库把语言写正确。D05 用标准库的 `http.server` 演示一个最小 HTTP 服务，是为了不把“听懂请求和响应”绑在某一个框架上。真要做服务，再选框架，并单独学那个框架的生命周期。本章不安装、也不调用这些第三方库。

## 机制

标准库随解释器发布。本教程的示例只依赖它，所以 `python examples/run_all.py` 不需要先装第三方包。查标准库的顺序是：先确定问题属于哪一类，再打开对应模块文档，而不是先装一个框架。

入门阶段真正要会用的几块：

| 问题 | 模块 | 不要踩的点 |
| --- | --- | --- |
| JSON 文本 | `json` | 只有 `dict/list/str/int/float/bool/None`。不是 dataclass |
| 时间 | `datetime` | 用带时区的时间。3.11 起有 `datetime.UTC` |
| 随机 | `random` | 模拟可以。令牌和口令用 `secrets` |
| 路径 | `pathlib` | 见 A09 |
| 数学 | `math` | `isnan`、`isclose`。钱不用 `float` |

`json.loads` 接受 `str`，`json.load` 接受文件对象。dump 时 `ensure_ascii=False` 才会直接写出非 ASCII 字符，否则中文会变成 `\uXXXX`，内容仍然正确，只是难读。

`datetime.now()` 不带时区得到的是 naive 时间。它不表示某一个绝对时刻。存事件用 `datetime.now(datetime.UTC)`。和本地时间转换用 `zoneinfo.ZoneInfo`，不要自己加 8 小时。夏令时会让“加 8 小时”在一年里的两天是错的。

`random.Random` 可以传入种子，测试才可重复。全局 `random.seed` 会改进程里所有使用全局生成器的人，包括别人的库。测试里用自己的 `Random` 实例。

你现在不必为了学语言去装 Web 框架、ORM 和校验库。那些是边界上的工具，第四部分会讲它们解决的问题，以及标准库里对应的最小形态。安装与否不改变语言规则。

## 会出事的写法

- `eval` 解析用户传来的 JSON。用 `json.loads`。`eval` 会执行代码。
- 用 `datetime.now()` 存创建时间，换一台时区不同的机器比较大小。用带 UTC 的 aware datetime。
- 用 `random` 生成重置口令。用 `secrets.token_urlsafe`。
- 为了“方便”把整个标准库背下来。会查、会选，比背函数名重要。

## 示例对照

`examples/part_a/a12_stdlib.py` 对 JSON 往返、UTC 时间和独立随机数发生器做断言。它不访问网络。断言失败时先看是不是把 `json.dumps` 的结果当成了 `dict`。

## 加练

1. 把 `{"name": "甲"}` 编成 JSON 再解回来。`ensure_ascii=False` 时输出里能否直接看到“甲”？
2. 为什么两个 `datetime.now()` 相减不能当作跨机器的耗时协议？

参考答案：

1. 能。`loads` 之后键和值都是 `str`，`name` 对应 `"甲"`。默认 `ensure_ascii=True` 时输出是转义形式，`loads` 的结果仍然是同一个字符串。
2. naive 时间没有时区。两台机器的“现在”不能相减得到真实间隔。耗时用 `time.perf_counter()`，时刻用 aware datetime。

## 面试

### Q1. `json` 能直接序列化 dataclass 吗？

**考点**：边界上的类型转换。

**回答**：

1. 不能。`json` 只认识那七种值。
2. 在边界写函数，把 dataclass 变成 `dict`，再 `dumps`。读回来时检查字段类型，再构造 dataclass。
3. 第三方库可以生成这些函数。标准库版本的价值是把转换显式留在边界，而不是让业务对象偷偷变成字典。

### Q2. 为什么口令不用 `random`？

**考点**：可预测性。

**回答**：

1. `random` 是伪随机，给模拟和抽样用。知道种子就能重放。
2. 安全令牌用 `secrets`，它走操作系统的密码学随机源。
3. 比较令牌用 `hmac.compare_digest`，避免逐字符提前返回。D08 有这条基线。

### Q3. 时间该怎么存？

**考点**：aware 与 naive。

**回答**：

1. 绝对时刻用 UTC 的 aware datetime。3.11 起写 `datetime.UTC`。
2. 展示时再转换到用户时区，用 `zoneinfo`。
3. 不要用字符串拼接日期。解析用 `datetime.fromisoformat` 或明确的格式，失败是 `ValueError`，在边界拒绝。

## 常见错误

- 用 `random` 生成会话令牌。用 `secrets.token_urlsafe`。
- `json.loads` 的输入其实是字节，编码还不确定。先按字节来源解码，或者在你知道它是 UTF-8 时再解码。`json.loads` 也接受 UTF-8 字节，但来源不明的二进制不该直接送进去。
- 把本地时间当成 UTC 存进数据库，以后换一台机器就对不上。

## 练习

1. 把 `{"ok": true}` 解析成 Python，并取出布尔值。注意 JSON 的 `true` 会变成 Python 的 `True`。
2. 用种子 `1` 构造 `random.Random`，取两次 `randrange(100)`，再新建一个同样种子的生成器取两次，断言相等。
3. 说出一个不该用 `random` 的场景。

参考答案：

1. `json.loads('{"ok": true}')["ok"] is True`。
2. 两个 `random.Random(1)` 各自取两次，列表相等。不要交叉使用同一个生成器还期待和“新生成器的前两次”以外的序列相同。
3. 密码、重置链接、API 密钥、任何攻击者能预测就有后果的值。

## 小结

标准库覆盖了文本、路径、时间和受控的随机数。查文档时对准 3.12。安全相关的随机数、时区、编码这三件事从一开始就用对的 API，后面就不用返工。
