# A05　运算符与表达式

> 示例：`examples/part_a/a05_operators.py`

## 学完你能做什么

读懂短路、链式比较、增强赋值和解包，而不是只记得“加号能加”。

## 比较可以连写

`1 < 2 < 3` 等价于 `1 < 2 and 2 < 3`，中间的 `2` 只计算一次。它不是 `(1 < 2) < 3`。`(1 < 2) < 3` 会先得到 `True`，再和 `3` 比较，而 `True == 1`，所以那个写法碰巧也为真，含义完全不同。写范围时用链式比较，或者写两个明确的比较。

## `and` / `or` / `not`

`not` 的结果一定是布尔。`and` 和 `or` **返回最后被看的那个操作数**，不一定是 `True` 或 `False`。

```python
assert ("" or "fallback") == "fallback"
assert (0 and 1) == 0
assert (1 and "ok") == "ok"
```

假值包括 `False`、`None`、数值 `0`、空容器和空字符串。除此之外的多数对象为真，包括非空字符串 `"0"` 和非零的 `Decimal`。不要用 `if len(items) > 0` 表达“有没有元素”，`if items` 就是空与否；如果你要区分 `None` 和空列表，再写 `is None`。

短路是规定：`and` 在左边为假时不算右边，`or` 在左边为真时不算右边。这可以用来避免无意义的调用，但别写成很难读的链条。复杂条件用中间变量。

## 增强赋值不一定是重新绑定

对列表，`items += [2]` 会调用就地的 `__iadd__`，对象还是原来那个，所有别名都看得到。对元组没有就地加法，`pair += (2,)` 只能算出新元组再绑回名字，旧元组不变。

这是 A02 练习的答案。看到 `+=` 时先问：这个对象可变吗？

## 海象运算符

`:=` 在表达式里完成赋值，3.8 引入。它适合“算出一个值，既要判断又要使用”的场景，例如读入内容后判断是否为空。不要把它塞进很长的一行来炫耀。示例只确认语法：`(n := 4) * n == 16`。

## 字典合并

3.9 起，`{1: "a"} | {1: "b", 2: "c"}` 得到新字典，右边的键覆盖左边。`|=` 则更新左边。这比先 `copy` 再 `update` 好读。

## 解包

```python
first, *rest = [10, 20, 30]
```

`first` 是 `10`，`rest` 是新列表 `[20, 30]`。星号只能出现一次。函数参数里的 `*` 和 `**` 留到 B01，那是定义参数，不是这里的序列解包。

3.15（PEP 798）允许在推导式里写 `*` 和 `**` 解包。3.12 的推导式没有这个语法，示例不使用它。

## 优先级

一元运算、乘除、加减、比较、`not`、`and`、`or`，大致按这个顺序收紧。记不住就加括号。生产代码里，靠读者背优先级才能看懂的表达式应该拆开。

身份比较 `is` 的优先级低于比较运算里的一些组合，这不是你需要探险的地方。比较对象身份时写成单独的布尔表达式。

## 机制

比较可以连写：`1 < x < 10` 等价于 `1 < x and x < 10`，中间的 `x` 只求值一次。这不是区间对象。任何实现了比较方法的对象都能参与，所以连写的每一段仍是普通比较。

`and` / `or` 返回的是操作数本身，不是 `True` 或 `False`。`0 or "fallback"` 得到 `"fallback"`。`"" and "x"` 得到 `""`。短路意味着右边可能根本不执行。把它们当成布尔运算再去索引，会拿到一个字符串或数字。

增强赋值看左边的对象会不会就地改：

| 对象 | `b += item` 的典型结果 |
| --- | --- |
| `list` | 就地 `extend`，身份不变 |
| `int`、`str`、`tuple` | 算出新对象，名字重新绑定 |

所以 `a = [1]`，`b = a`，`b += [2]` 之后 `a` 也变了。`b = b + [2]` 则一定是新列表。这是 A02 那道练习的答案来源。元组的 `+=` 如果元素层面失败，还可能出现“已经部分绑定”的难查状态；不可变对象不要靠 `+=` 做累积。

海象运算符 `:=` 在表达式里完成赋值，适合 `if (n := len(items)) > 0` 这种“算一次、判断、后面还要用”的写法。它不改变作用域规则。在推导式里使用时，名字泄漏到外层与否跟推导式的作用域有关，B02 再讲。能用普通赋值写清楚的，就不要为了短而用海象。

字典合并：`{**a, **b}` 和 3.9 起的 `a | b` 都是新字典，右边覆盖左边的同名键。`|=` 更新左边。列表没有对应的“按键合并”。

解包：`first, *rest = seq` 要求左边的结构对得上。星号只能有一处。字典解包 `**mapping` 用在函数调用和字典字面量里，键必须是字符串才能进关键字参数。

优先级不要背整张表。用括号写下你要的结合。移位、按位与、成员判断写在一起时，括号是给读者的，不只是给解析器的。

## 会出事的写法

- `if name or "匿名"` 想要缺省值，但名字是合法的空字符串时也会被换掉。缺省应该看 `is None`。
- 对共享列表做 `+=`，调用方的列表被改掉，日志里却写着“我们返回了一个新列表”。
- `a < b < c` 的两边不是同一套排序。自定义对象如果 `__lt__` 不一致，连写只会把混乱藏起来。
- 用 `^` 当乘方。乘方是 `**`。`^` 是按位异或。

## 加练

1. `a = [1]`，`b = a`，执行 `b += [2]` 和再执行一次 `b = b + [3]` 之后，`a` 是什么？`a is b` 呢？
2. `0 or 5 or 7` 和 `5 and 0 and 7` 各是什么？

参考答案：

1. 第一次之后 `a` 是 `[1, 2]` 且 `a is b`。第二次 `+` 造新列表，`b` 变成 `[1, 2, 3]`，`a` 仍是 `[1, 2]`，`a is b` 为假。
2. `5` 和 `0`。`or` 返回第一个真值，`and` 返回第一个假值；后面的操作数不再求值。

## 面试

### Q1. `+=` 对列表和元组为什么不一样？

**考点**：就地修改和重新绑定。

**回答**：

1. 列表实现了就地加法，`+=` 变成 `extend` 一类的操作，对象身份不变，所有别名都看得到。
2. 元组不可变，`+=` 只能算出新元组再重新绑定名字。其他名字仍指向旧元组。
3. 函数参数上的 `+=` 因此也分成两类。要隔离就不要就地改，显式构造新容器。

### Q2. `and` 和 `or` 返回布尔吗？

**考点**：短路和返回值。

**回答**：

1. 不保证。它们返回决定结果的那个操作数。
2. `or` 用来写缺省值时，`0` 和 `""` 会被当成缺失。缺省用 `is None`。
3. 右边有副作用时，短路会跳过副作用。不要把必须执行的检查放在可能被跳过的一边。

### Q3. 链式比较 `a < b < c` 会调用几次 `b`？

**考点**：求值次数。

**回答**：

1. 中间表达式只求值一次，然后分别和左右比较，中间是 `and`。
2. 如果 `b` 是函数调用，它不会为了右边再调用一次。
3. 这不构成事务，也不锁定对象。比较过程中另一个线程改了对象，仍可能看到中间状态。

## 常见错误

- 把 `a < b < c` 理解成两个独立比较的某种平均。它就是 `and`，并且中间值只算一次。
- 认为 `or` 的结果类型一定是 `bool`。只有你再套一层 `bool()` 时才是。
- 对列表使用 `+=` 还以为别的名字看不见。

## 练习

1. `0 or [] or "x"` 的结果是什么？类型是什么？
2. `s = "ab"`，`t = s`，执行 `s += "c"` 后 `t` 是什么？`s is t` 呢？
3. 把 `first, *mid, last = [1, 2, 3, 4]` 的三个名字写出来。

参考答案：

1. 结果是 `"x"`，类型是 `str`。空字符串和空列表都为假，`or` 继续向右看。
2. `t` 仍是 `"ab"`。字符串不可变，`+=` 重新绑定 `s`，`s is t` 为假。
3. `first == 1`，`mid == [2, 3]`，`last == 4`。

## 小结

链式比较是一次 `and`。`and`/`or` 返回操作数并会短路。`+=` 对可变对象可能就地修改。解包和字典 `|` 是日常语法，推导式里的解包要等到 3.15。
