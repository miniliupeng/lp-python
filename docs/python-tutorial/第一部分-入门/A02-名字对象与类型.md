## 赋值是绑定，不是抄一份

Python 里的名字（你习惯叫变量）保存的是 **对对象的引用**。赋值把名字绑到对象上，不负责把对象复制一遍。

```python
shared = [1]
alias = shared
alias.append(2)
assert shared == [1, 2]
assert shared is alias
```

`shared` 和 `alias` 是两个名字，对象只有一个列表。`append` 修改的是这个列表，所以两个名字都看得见。

如果右边是一个新对象，发生的是 **重新绑定**，原来的对象不动：

```python
left = 1
right = left
left = 2
assert right == 1
```

`left = 2` 让名字 `left` 改指整数 `2`。`right` 仍然指着原来的 `1`。整数本身也没有被“改成 2”，因为你根本没有修改那个整数对象。

这不是“传值还是传引用”能干净概括的模型。函数调用时，参数名同样被绑到传入的对象上，和赋值是同一套规则。可变对象在函数里被修改，调用方能看见；对参数名重新赋值，调用方看不见。第二部分会把函数讲完，这里先把模型放对。

## 类型在对象上

`type(1)` 是 `int`，`type("one")` 是 `str`。类型属于对象，不属于名字。所以同一个名字可以先绑整数，再绑字符串：

```python
value = 1
value = "one"
```

这叫 **动态类型**：检查发生在运行时，名字没有固定的静态类型格子。它不等于可以随便把类型混在一个运算里。Python 是 **强类型**：`"1" + 1` 会抛 `TypeError`，解释器不会悄悄把字符串变成整数。需要转换时你自己写 `int("1") + 1`。

`isinstance(True, int)` 为真，是因为 `bool` 是 `int` 的子类，不是因为类型系统含糊。下一章会说明这件事带来的实际后果。

## `is` 和 `==` 从现在就分开

`==` 问“值相不相等”，通常会调用对象的 `__eq__`。`is` 问“是不是同一个对象”。教学示例里用 `is` 暴露别名；业务判断相等时用 `==`。数字和字符串的 `is` 尤其不能当规则用，[C02](../第三部分-运行时/C02-可变性拷贝与身份.md) 会把 CPython 的缓存讲准确。

## 可变和不可变

能否就地修改，是对象的性质：

| 对象 | 能否就地改内容 |
| --- | --- |
| `list`、`dict`、`set`、`bytearray` | 能 |
| `int`、`float`、`str`、`tuple`、`bytes`、`frozenset` | 不能 |

不可变不是“里面的东西永远不变”的递归保证。元组自己的槽位不能换，但槽位里如果放着列表，那个列表仍能改。A08 有例子。

## 常见错误

- 把 `b = a` 理解成深拷贝。那是第二个名字。
- 为了“防止被改”只是再赋一个名字。要拷贝必须显式做，见 C02。
- 看到动态类型就写成“Python 没有类型”。对象一直有类型，只是名字不固定。

## 练习

1. `a = [1, 2]`，`b = a`，`b = b + [3]` 之后 `a` 是什么？`a is b` 呢？
2. 把上一题的 `b = b + [3]` 换成 `b += [3]`，答案变了吗？为什么先别急着背，做完去看 A05。
3. 为什么 `len(1)` 报错，而 `len("1")` 不报错？

参考答案：

1. `a` 仍是 `[1, 2]`。`+` 生成新列表并让 `b` 重新绑定，所以 `a is b` 为假。
2. 对列表来说 `+=` 会就地扩展，`a` 变成 `[1, 2, 3]`，而且 `a is b`。细节在 A05，和“不可变对象的 `+=` 只能重新绑定”对照着记。
3. `len` 要求对象提供长度。整数没有，字符串有。这是对象能力的差别，不是名字的差别。

## 小结

名字绑定对象。赋值不复制。类型在对象上，运算不帮你做隐式的字符串和数字转换。两个名字可以指向同一个可变对象，这是后面绝大多数“我没改过它啊”的来源。
