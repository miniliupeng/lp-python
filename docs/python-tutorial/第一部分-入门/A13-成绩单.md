# A13　小项目：成绩单

> 示例：`examples/part_a/a13_gradebook.py`

## 学完你能做什么

把函数、字典、异常和排序合成一个小程序，并给它划出输入不合法时的行为。这是 A 阶段的综合，不引入新语法。

## 问题

输入是“姓名 → 分数列表”。需要：

- 某人的平均分。空列表是调用方的错误，抛 `ValueError`，不要返回 `0` 假装考了零分。
- 不低于分数线的那些分数。默认分数线 `60`。
- 一份按平均分从高到低的名单。平均分相同就按姓名升序，结果要稳定、可断言。

数据就放在字典里，不写文件。文件读写已经在 A09 练过，塞进这个例子只会让断言变长。

## 实现要点

`average` 用 `sum` 和 `len`。整数除以整数，`/` 得到 `float`。如果这是分数学期报表，浮点误差在这个数量级可以接受。不要为了两个整数的平均去引入 `Decimal`，除非需求写的是货币。

`passed` 返回新列表，不修改原列表。分数线是数字默认值，不可变，定义在参数上是安全的。

`report` 先做成 `(姓名, 平均分)` 的列表，再排序。`sorted` 的 `key` 返回 `(-平均分, 姓名)`：负数让高分排前面，姓名作为第二键。不要先按姓名排再按分数排，除非你很清楚稳定排序的用法；一个键元组更直接。

```python
rows = [(name, average(scores)) for name, scores in book.items()]
return sorted(rows, key=lambda item: (-item[1], item[0]))
```

这里的 `lambda` 是匿名函数，和 `def` 一样产生函数对象。它只有一个表达式。更长的逻辑写成 `def`。

字典按插入顺序迭代，但排序之后输出顺序由键决定，不再依赖原来的插入顺序。测试数据换个构造顺序，排名的第一名仍然是平均分最高的人。

## 错误放在哪里

空成绩在 `average` 里拒绝。`report` 不捕获这个异常，让它传到调用方。捕获以后返回空列表会把“数据坏了”和“没有学生”混成同一种结果。

分数是否必须在 0 到 100 之间，示例没有检查。真实成绩单应该在 **数据进入系统的边界** 检查，而不是在每个读取平均值的函数里重复检查。D03 会把边界说清楚。现在至少不要在 `average` 里默默丢掉非法分数。

## 测试就是断言

`main` 里的断言是这个小项目的规格：

- Ada 的平均分是 85。
- Lin 不低于 60 的分数只剩 70。
- 排名第一是 Grace。
- 空列表抛 `ValueError`。

你改排序规则时，这些断言会失败。失败比“看起来差不多”有用。

## 练习

1. 给 `report` 增加并列时的可解释性：写一行注释说明第二排序键是什么。不要改代码行为。
2. 增加函数 `below(scores, bar=60)`，返回低于分数线的分数。自己补断言。
3. 如果两个学生平均分相同，当前实现谁在前？用一个新字典验证。

参考答案：

1. 第二键是姓名的字典序，小的在前。
2. `return [score for score in scores if score < bar]`。断言用 `[50, 70]` 和分数线 60，结果是 `[50]`。
3. 平均分相同则姓名升序。`{"Bo": [80], "An": [80]}` 的结果是 `An` 在前。

## 小结

A 阶段的程序就是：用名字绑定对象，用函数表达规则，用字典保存记录，用异常拒绝不可能的输入，用断言把例子钉住。下一阶段开始处理函数和类的全部机制，而不是再增加一种容器。
