# A13　小项目：成绩单

> 示例：`examples/part_a/a13_gradebook.py`

## 学完你能做什么

把函数、字典、异常和排序合成一个小程序，并给它划出输入不合法时的行为。这是 A 阶段的综合，不引入新语法。

## 问题

输入是“姓名 → 分数列表”。需要：

- 某人的平均分。空列表是调用方的错误，抛 `ValueError`，不要返回 `0` 假装考了零分。
- 不低于分数线的那些分数。默认分数线 `60`。
- 一份按平均分从高到低的名单。平均分相同就按姓名升序，结果要稳定、可断言。

数据就放在字典里，不写文件。文件读写已经在 A09 练过，塞进这个例子只会让断言变长。

## 实现要点

`average` 用 `sum` 和 `len`。整数除以整数，`/` 得到 `float`。如果这是分数学期报表，浮点误差在这个数量级可以接受。不要为了两个整数的平均去引入 `Decimal`，除非需求写的是货币。

`passed` 返回新列表，不修改原列表。分数线是数字默认值，不可变，定义在参数上是安全的。

`report` 先做成 `(姓名, 平均分)` 的列表，再排序。`sorted` 的 `key` 返回 `(-平均分, 姓名)`：负数让高分排前面，姓名作为第二键。不要先按姓名排再按分数排，除非你很清楚稳定排序的用法；一个键元组更直接。

```python
rows = [(name, average(scores)) for name, scores in book.items()]
return sorted(rows, key=lambda item: (-item[1], item[0]))
```

这里的 `lambda` 是匿名函数，和 `def` 一样产生函数对象。它只有一个表达式。更长的逻辑写成 `def`。

字典按插入顺序迭代，但排序之后输出顺序由键决定，不再依赖原来的插入顺序。测试数据换个构造顺序，排名的第一名仍然是平均分最高的人。

## 错误放在哪里

空成绩在 `average` 里拒绝。`report` 不捕获这个异常，让它传到调用方。捕获以后返回空列表会把“数据坏了”和“没有学生”混成同一种结果。

分数是否必须在 0 到 100 之间，示例没有检查。真实成绩单应该在 **数据进入系统的边界** 检查，而不是在每个读取平均值的函数里重复检查。D03 会把边界说清楚。现在至少不要在 `average` 里默默丢掉非法分数。

## 测试就是断言

`main` 里的断言是这个小项目的规格：

- Ada 的平均分是 85。
- Lin 不低于 60 的分数只剩 70。
- 排名第一是 Grace。
- 空列表抛 `ValueError`。

你改排序规则时，这些断言会失败。失败比“看起来差不多”有用。

## 机制

这一章把前面的语言规则收成一个小程序，而不是引入新语法。成绩单要守住的不变量：

1. 分数是有范围的数。非法输入在进入列表之前失败。
2. 统计函数不修改成绩列表。调用两次平均分，列表仍相同。
3. 空列表没有平均分。这是错误或明确的空结果，不是偷偷返回 `0`。`0` 会和“全是 0 分”分不清。
4. 输出如果写文件，编码是 UTF-8，用 `with` 关闭。

把解析、计算、展示分开。解析接受文本，返回数字或抛异常。计算接受数字序列，返回结果。展示把结果变成字符串。测试可以不碰文件，只测计算。

错误放在边界：一行文本不是数字、分数超出 0 到 100，都在解析函数失败。计算函数假设元素已经是合法分数。如果计算函数还在 `isinstance`，说明边界没有守住。

## 会出事的写法

- 平均分写成 `sum(scores) / len(scores)`，空列表时 `ZeroDivisionError` 冒到最外层，用户看到回溯。
- 解析失败返回 `0`。脏数据变成了及格线以下的合法分数，统计仍然跑完。
- 在计算函数里 `scores.sort()`。调用方的列表顺序变了，导出和原始输入对不上。
- 用 `float` 累加后再和整数比较及格线。分数如果是整数，就用 `int`。如果允许一位小数，用 `Decimal`。

## 示例对照

`examples/part_a/a13_gradebook.py` 构造几条成绩，断言平均、最高和非法输入会失败，并且调用之后原列表不变。阅读顺序：先看失败用例，再看成功用例。成功用例证明不了“空输入安全”。

## 加练

1. 给成绩单加一个“及格人数”。及格线是参数，默认 60。空列表返回 0 还是抛异常？说明理由。
2. 为什么这个数字可以返回 0，平均分却不可以？

参考答案：

1. 及格人数在空列表时是 0，这是计数。函数不修改原列表。非法分数仍在进入列表前被拒绝。
2. 人数 0 不会和“有人考了 0 分”混淆。平均分返回 0 会和“真实平均是 0”混淆。空集合的平均没有定义。

## 面试

### Q1. 一个小脚本怎样才算把错误放对了地方？

**考点**：边界和不变量。这是后面所有服务题的缩小版。

**回答**：

1. 外部文本只在一个函数里变成内部类型。失败在这里结束。
2. 内部函数信任类型，不再返回哨兵混用。
3. 不变量可以写成断言或测试：分数范围、不修改输入、空输入的定义。

### Q2. 为什么统计函数不能改传入的列表？

**考点**：别名。

**回答**：

1. 调用方可能还要按原始顺序导出。
2. 排序会就地修改，所有别名都看得到。
3. 需要排序时对副本排序，或者用 `sorted` 得到新列表。

### Q3. 这个项目还缺什么才敢给别人用？

**考点**：从脚本到工具的差距，不要求上框架。

**回答**：

1. 明确的退出码：成功 0，输入错误是另一种，不和解释器崩溃混在一起。
2. 文件编码和路径固定，临时文件清理。
3. 测试覆盖空输入、越界、正常路径。这些仍只用标准库断言就能写。

## 练习

1. 给 `report` 增加并列时的可解释性：写一行注释说明第二排序键是什么。不要改代码行为。
2. 增加函数 `below(scores, bar=60)`，返回低于分数线的分数。自己补断言。
3. 如果两个学生平均分相同，当前实现谁在前？用一个新字典验证。

参考答案：

1. 第二键是姓名的字典序，小的在前。
2. `return [score for score in scores if score < bar]`。断言用 `[50, 70]` 和分数线 60，结果是 `[50]`。
3. 平均分相同则姓名升序。`{"Bo": [80], "An": [80]}` 的结果是 `An` 在前。

## 小结

A 阶段的程序就是：用名字绑定对象，用函数表达规则，用字典保存记录，用异常拒绝不可能的输入，用断言把例子钉住。下一阶段开始处理函数和类的全部机制，而不是再增加一种容器。
