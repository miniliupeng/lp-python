# A04　字符串、字节与编码

> 示例：`examples/part_a/a04_strings_bytes.py`

## 学完你能做什么

分清文本和字节，正确处理 UTF-8，并用 f-string 格式化。不把编码问题留到文件那一章才第一次碰到。

## `str` 是 Unicode 码位序列

`len("héllo")` 是 5，按码位计，不按字节计。索引、切片得到的仍是字符串，长度为 1 的字符串不是单独的“字符类型”，Python 没有 `char`。

字符串不可变。`text[0] = "H"` 会抛 `TypeError`。要改内容，就构造新字符串。

循环里反复 `s = s + piece` 会不断复制，数据一大就明显变慢。拼接很多段时用 `"".join(parts)`，`join` 可以先算总长度再分配。

## 字节是另一类对象

`bytes` 是 0 到 255 的不可变序列。`bytearray` 是它的可变版本。文本和字节之间必须经过编码：

```python
raw = "héllo".encode("utf-8")
assert raw.decode("utf-8") == "héllo"
```

UTF-8 是本教程默认的文本编码。源码文件请保存为 UTF-8。3.12 打开文件时，如果不写 `encoding`，用的是 **区域设置编码**，不同机器可能不同。3.15 起（PEP 686）默认改为 UTF-8，并用 `PYTHONUTF8=0` 或 `-X utf8=0` 退回旧行为。示例和业务代码都显式写 `encoding="utf-8"`，不把正确性押在默认值上。

编码失败会抛 `UnicodeEncodeError` 或 `UnicodeDecodeError`。不要用“忽略错误”当成默认策略，除非你明确要丢数据，并且这种丢弃是需求的一部分。

## 字面量

- `"a"` 和 `'a'` 相同。3.12 的 f-string（PEP 701）里可以更自由地嵌套引号。
- `r"\n"` 是两个字符 `\` 和 `n`，反斜杠不转义。正则表达式、Windows 路径字面量常用原始字符串。它不能以单个反斜杠结尾。
- `b"ab"` 是字节。`bytearray(b"ab")` 之后可以按下标赋值。
- f-string：`f"{name} {1 + 1}"`。`f"{name=}"` 会带上表达式文本，调试时很有用，这是 3.8 就有的语法，不是 3.12 新造的。

**t-string 不是 f-string。** `t"..."` 从 3.14（PEP 750）才有，求值结果是 `string.templatelib.Template`，保留静态片段和插值，方便你自己做转义。3.12 里 `t"..."` 只是一个名字后面跟了一个字符串，并不会变成模板对象。本教程的示例不使用 t-string。

## 常见操作

`split`、`strip`、`replace`、`startswith`、`lower` 都返回新字符串。判断子串用 `in`。大小写折叠做比较时，简单场景可以用 `casefold`，它比 `lower` 更接近大小写不敏感比较的定义；不要指望它对所有语言的排序都正确，排序和国际化是另一个问题。

多行文本用三引号 `"""`。函数文档字符串就是一个放在函数体开头的字符串字面量，解释器把它存到 `__doc__`。

## 机制

`str` 是 Unicode 码位序列，不是字节，也不是“一个汉字占两个字符”的某种固定宽度。`len("你")` 是 1，因为这是一个码位。一个用户看到的字素可能由多个码位组成，例如带组合音符的字符。`len` 不算屏幕上的字素簇。截断昵称如果按码位切，可能切开一个组合字符。

`bytes` 是 0 到 255 的整数序列。文本和字节之间只有编码：

```text
str  --encode(编码)-->  bytes
bytes --decode(编码)-->  str
```

不存在“字符串的原始字节”这种不带编码的说法。UTF-8 是本教程和示例的默认选择。3.15 起 `open` 不写 `encoding` 时语言默认也是 UTF-8（PEP 686），仍可用 `PYTHONUTF8=0` 退回旧行为。示例从现在起就写 `encoding="utf-8"`，不赌默认值。

编码失败和解码失败是两类错误。`encode` 遇到编码无法表示的码位抛 `UnicodeEncodeError`。`decode` 遇到非法字节序列抛 `UnicodeDecodeError`。网络和文件上的数据是字节，先解码再当文本用。

字面量：

| 写法 | 对象 | 注意 |
| --- | --- | --- |
| `"a"`、`f"{name}"` | `str` | f-string 在运行时把插值转成文本 |
| `b"a"` | `bytes` | 只适合 ASCII 字面量 |
| `r"\n"` | `str` | 反斜杠多半保留，正则常用 |

3.14 的 t-string（PEP 750）得到的是 `string.templatelib.Template`，保留静态片段和插值，不自动做 HTML 转义。安全来自你怎么处理模板，不是来自字母 `t`。3.12 的示例不写这个语法。

## 会出事的写法

- 用 `open(path)` 不写编码，在一台语言环境是 GBK 的机器上读 UTF-8 文件。3.12 仍可能跟着区域设置走。
- 把 `str` 和 `bytes` 用 `+` 拼在一起。这是 `TypeError`，和数字那章的强类型是同一条规则。
- 用 `len` 判断“这个字符串按 UTF-8 存进数据库会不会超 255 字节”。`len` 是码位数。字节长度是 `len(text.encode("utf-8"))`。
- 用 `strip` 或切片处理用户标识，以为大小写和兼容字符已经规范化。需要比较用户名时先规定规范化（例如 Unicode NFC）和大小写规则，不要手写一半。

## 示例对照

`examples/part_a/a04_strings_bytes.py` 检查的是模型，不是字符串 API 大全：`str` 与 `bytes` 互转必须给出编码，拼错类型会失败，f-string 产生的是 `str`。跑完应打印 `ok a04`。文件读写的编码断言在 `examples/part_a/a09_files.py`，两章一起看，避免把“内存里的 str”和“磁盘上的字节”说成同一个东西。

## 加练

1. `"é".encode("utf-8")` 的长度和 `len("é")` 是否相同？
2. 为什么 HTML 模板不能因为用了 f-string 就认为已经转义？

参考答案：

1. `len("é")` 是 1。UTF-8 编码后是两个字节 `C3 A9`。码位长度和字节长度不是一个数。
2. f-string 只是把对象格式化进字符串。`<` 仍是 `<`。转义是另一层责任。3.14 的 t-string 同样不自动转义。

## 面试

### Q1. `str` 和 `bytes` 的差别？什么时候编码？

**考点**：文本边界。

**回答**：

1. `str` 是码位，`bytes` 是字节。两者不能相加。
2. 编码发生在离开进程的时候：文件、套接字、数据库驱动若接收文本，要知道它内部用哪种编码。
3. 一律显式 `encoding="utf-8"`。错误用 `UnicodeDecodeError` 暴露出来，不要用 `errors="ignore"` 把脏数据吞掉，除非产品明确要求丢弃。

### Q2. 为什么按字符切片会切坏用户名？

**考点**：码位、字素簇、字节三级长度。

**回答**：

1. `len` 和切片的单位是码位。
2. 一个视觉字符可能是多个码位。按码位切可能留下孤立的组合记号。
3. 按字节切更危险，会切断 UTF-8 序列，下一次解码直接失败。限制存储用字节长度并在边界拒绝，展示截断要按字素或按产品规定的规则。

### Q3. t-string 是更安全的 f-string 吗？

**考点**：3.14 新语法的真实语义，防止背博客。

**回答**：

1. 不是。t-string 得到模板对象，保留哪一段是字面量、哪一段是插值。
2. 它不调用 HTML、SQL 或 shell 的转义。
3. 安全来自消费这个模板的库。3.12 的代码继续用 f-string，并在各自的边界做转义或参数化。SQL 参数化见 D06，不靠字符串拼接。

## 常见错误

- 把 `bytes` 当 `str` 拼接，得到 `TypeError`。先解码或先编码，方向要明确。
- 用 `len(text.encode())` 当字符数。那是字节数。
- 从网络或文件读到字节后，不声明编码就“当字符串用”。边界上只可能是字节，文本是解码之后的结果。

## 练习

1. `"你".encode("utf-8")` 的长度是多少？`len("你")` 呢？
2. 把 `["2026", "11", "07"]` 拼成 `2026-11-07`。
3. 为什么示例断言 `r"\n" == "\\n"`？

参考答案：

1. UTF-8 下 `"你"` 是 3 个字节，`len("你")` 是 1。
2. `"-".join(["2026", "11", "07"])`。
3. 原始字符串保留反斜杠。普通字符串里要写出一个反斜杠，需要写成 `\\`。两边都是“反斜杠加 n”这两个字符，所以相等。真正的换行符是 `"\n"`，长度为 1。

## 小结

`str` 是文本，`bytes` 是字节，中间隔着一次你必须写出名字的编码。拼接用 `join`，格式化用 f-string。文件和网络相关的代码一律显式 UTF-8，这样 3.12 和 3.15 的默认值差异不会改变你的程序。
