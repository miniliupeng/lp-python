# A03　数字、布尔与 None

> 示例：`examples/part_a/a03_numbers.py`

## 学完你能做什么

选对数字类型，写对负数除法，并且不把 `True`、`None`、`nan` 用错。

## 整数没有固定宽度

`int` 可以大到只受内存限制，不是 C 的 64 位整数。日常加减不用担心溢出。代价是超大整数的运算不再是固定时间，面试里如果有人问“Python 整数加法是不是 O(1)”，答案是：小整数近似是，位数上去以后不是。

## 除法有两种

`/` 是真除法，结果是 `float`：`7 / 2 == 3.5`。`//` 是 **向负无穷取整** 的地板除，不是“向零截断”。

```text
-7 // 2 == -4
-7 % 2 == 1
```

恒等式是 `a == (a // b) * b + (a % b)`。余数的符号跟着除数走。从 C、Java 转过来的人很容易在这里算错。

## 二进制浮点不是十进制

`0.1 + 0.2 != 0.3` 在 IEEE 754 双精度下成立，不是 Python 的 bug。`float` 适合测量、图形、科学计算里本来就是近似的量。钱、税率、需要十进制精确分数的量用 `decimal.Decimal`，并且用字符串构造：

```python
from decimal import Decimal

assert Decimal("0.1") + Decimal("0.2") == Decimal("0.3")
```

`Decimal(0.1)` 会把已经不精确的二进制浮点再包一层，通常不是你想要的。

## `bool` 是 `int` 的子类

`True` 和 `False` 是仅有的两个布尔对象。`True == 1`，`True + True == 2`，`isinstance(True, int)` 为真。这是历史设计，不是建议你拿布尔做算术。需要计数时用整数；需要真假时用布尔。

`False == 0` 和 `False == 0.0` 都为真，因为数值相等不要求类型相同。身份则不同：`False is 0` 为假。

## `None` 是单例

“没有值”用 `None`，不要用 `0`、`""` 或 `False` 代替，除非这些值在你的领域里真的表示缺失。判断缺失写 `x is None` 或 `x is not None`。`None` 在进程里只有一个对象，所以这里用 `is` 是语言习惯，也和实现一致。

示例里有一行 `None == None`，只是为了说明相等性同样成立。风格检查会提醒你改成 `is`。听这个提醒。

## `nan` 不等于自己

`float("nan") != float("nan")`。它还会让一些比较和字典键变得反直觉。不要用 `nan` 当哨兵，缺失用 `None`。检查 NaN 用 `math.isnan`。

## 小整数缓存不是 `257 is 257` 能证明的

**语言不保证** 两个相等的整数是同一个对象。CPython 有两件容易混在一起的实现细节：

1. 启动时准备了 `-5` 到 `256` 这些整数对象。动态造出来的 `int("256")` 和另一个 `int("256")` 是同一个对象；`int("257")` 不是。
2. 编译一个函数时，相同的常量会放进这个代码对象的常量表。`return 257` 每执行一次都取出 **同一格** 常量，所以 `returns_257() is returns_257()` 为真。这不能证明 `257` 进了全局缓存。

业务代码用 `==` 比较数字。只在讲解对象身份时，才用 `int("256")` 这种动态构造观察缓存。

## 机制

`int` 是任意精度整数。小的时候 CPython 用一个紧凑表示，位数变长就变成多 limb 的大整数，运算时间随位数增长。所以“整数加法是 O(1)”只在位数有界时近似成立。溢出不会绕回负数，这是和 C 的 `int64` 最容易被问到的差别。

除法拆开记：

| 运算 | 结果 | 取整方向 |
| --- | --- | --- |
| `/` | `float` | 真除法，`7 / 2` 是 `3.5` |
| `//` | 与操作数相关，整数相除得到 `int` | 向负无穷 |
| `%` | 满足下面的恒等式 | 余数符号跟除数 |

恒等式是 `a == (a // b) * b + (a % b)`。因此 `-7 // 2` 是 `-4`，`-7 % 2` 是 `1`，因为 `-4 * 2 + 1 == -7`。C、Java 的整数除法向零截断，迁过来的代码这里最容易差 1。

`float` 是 IEEE 754 双精度。`0.1` 在二进制里是循环小数，相加后的位模式不是 `0.3` 的位模式。这不是 `print` 的四舍五入问题，示例直接用 `!=` 断言。钱和税率用 `decimal.Decimal`，用字符串或整数构造。`Decimal(0.1)` 会把已经错了的二进制值再包一层。

`bool` 的 MRO 是 `bool, int, object`。`True + True == 2` 是这个继承的结果。需要计数时用 `int`，需要真假时用 `bool`。不要把布尔塞进金额计算。

`None` 在一个进程里只有一个。`is None` 是身份比较，也是风格要求。`float("nan")` 不等于自己，哈希却存在；它不适合当字典键或哨兵。缺失用 `None`，或者用一个专用的哨兵对象。3.15 才有内置 `sentinel`，3.12 继续用 `object()`。

## 会出事的写法

- 用 `float` 累加分，对账差 1 分。改成“分”为单位的 `int`，或 `Decimal`。
- `//` 写分页下标，数据里出现负数时向负无穷取整，切片或页码会偏到另一页。
- `if x` 同时把 `0`、`0.0`、`""`、`[]`、`None` 都当成失败。缺省和合法的零必须分开，缺省用 `is None`。
- 用 `x is 256` 做判断。3.12 对这种字面量比较发出 `SyntaxWarning`。缓存范围也不是语言契约。

## 示例对照

`examples/part_a/a03_numbers.py` 把上面每条都写成了断言：

- `7 / 2 == 3.5`，`7 // 2 == 3`，`-7 // 2 == -4`，`-7 % 2 == 1`，`divmod(-7, 2) == (-4, 1)`。
- `0.1 + 0.2 != 0.3`，同时 `Decimal("0.1") + Decimal("0.2") == Decimal("0.3")`。
- `True + True == 2`，`False == 0`，`None is None`。
- `nan != nan`。
- `int("256") is int("256")` 为真，`int("257") is int("257")` 为假。这是动态构造，绕开了常量表合并。
- `returns_257() is returns_257()` 为真，因为两次返回的是同一个代码对象里的同一项常量，不是因为 257 进了全局小整数池。

## 加练

1. 用恒等式算 `-11 // 4` 和 `-11 % 4`。
2. 为什么 `Decimal("0.10")` 和 `Decimal("0.1")` 相等，但它们的 `as_tuple()` 可能不同？业务上该不该用 `is`？

参考答案：

1. `-11 // 4 == -3`，`-11 % 4 == 1`，因为 `-3 * 4 + 1 == -11`。
2. `Decimal` 会保留有效位的信息，相等比较的是数值。身份仍然不能用来判断两个 Decimal 是不是同一个计算结果。用 `==`。

## 面试

### Q1. 为什么 `0.1 + 0.2 != 0.3`？钱怎么存？

**考点**：IEEE 754，以及精度问题的工程落点。

**回答**：

1. `float` 是二进制浮点。`0.1` 不能用有限二进制小数表示，误差在运算前就已经在。
2. 货币用整数分，或 `Decimal` 且用字符串构造。不要 `Decimal(0.1)`。
3. 科学计算里本来就是近似值时，用 `math.isclose`，并写出绝对或相对公差。不要为了金额去调公差把错账抹平。

### Q2. 负数地板除和取模怎么答？

**考点**：向负无穷，而不是向零。

**回答**：

1. `//` 向负无穷取整。`-7 // 2` 是 `-4`，不是 `-3`。
2. 余数满足 `a == (a // b) * b + (a % b)`，所以 `-7 % 2` 是 `1`。
3. 从 C 迁过来的代码如果依赖向零截断，要改成显式的 `int(a / b)` 并不够，因为那条路径先变成浮点。整数向零除法要自己写，或者清楚说明你为什么需要它。

### Q3. `True == 1` 和 `True is 1` 分别是什么？

**考点**：`bool` 是 `int` 的子类，相等和身份不是一回事。

**回答**：

1. `True == 1` 为真，`True + True == 2`，`isinstance(True, int)` 为真。这是历史继承，不是建议拿布尔做算术。
2. `True is 1` 为假。它们是不同对象。
3. JSON 和表单里的 `1` 不能在边界上当成布尔收下。解析层要把真假的合法写法列出来，而不是依赖 `== 1`。

## 常见错误

- 用 `float` 记账，最后差一分钱。
- 认为 `//` 对负数是向零取整。
- 把 `True` 放进数值接口还觉得“只是布尔”。调用方如果写了 `if flag == 1` 以外的算术，结果会让你吃惊。
- 用 `x is 256` 做判断。3.12 会对这种写法发出 `SyntaxWarning`。

## 练习

1. 计算 `-11 // 3` 和 `-11 % 3`，用恒等式验算。
2. 用 `Decimal` 计算 `1 / 10 + 2 / 10` 的精确十进制结果。注意怎么构造。
3. 说明 `returns_257() is returns_257()` 为真，并不能推出“所有 257 都是同一个对象”。

参考答案：

1. `-11 // 3 == -4`，`-11 % 3 == 1`，因为 `-4 * 3 + 1 == -11`。
2. `Decimal("0.1") + Decimal("0.2")`，或者 `Decimal(1) / Decimal(10) + Decimal(2) / Decimal(10)`。不要从 `float` 转。
3. 两次调用返回的是同一个代码对象里的同一项常量。`int("257") is int("257")` 为假，说明全局并没有把 257 收成单例。

## 小结

整数可以很大，地板除向负无穷取整，钱用 `Decimal`。`bool` 是整数的子类，`None` 用 `is` 判断，`nan` 不等于自己。整数身份是 CPython 细节，比较数值请用 `==`。
