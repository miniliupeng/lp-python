# A06　控制流

> 示例：`examples/part_a/a06_control_flow.py`

## 学完你能做什么

用条件、循环和 `else` 子句表达清楚的控制流，知道 `break` 和 `return` 分别会跳过谁。

## 条件

```python
if n < 0:
    return "neg"
if n == 0:
    return "zero"
return "pos"
```

每个分支的条件按顺序判断，命中一个就离开函数。`elif` 和这种提前返回是同一类结构，函数很短时提前返回往往更平。不要写永远到不了的分支。

Python 没有 `switch` 语句的老语法。3.10 起的 `match` 是结构模式匹配，能做的事比“按整数跳转”多，也比“按整数跳转”容易用错。它放在 [B10](../第二部分-进阶/B10-模式匹配.md)，不要在入门阶段拿它替换每一个 `if`。

## 循环

`while` 在条件为真时重复。条件里的名字要在循环内更新，否则就是死循环。`for` 遍历可迭代对象，不是 C 语言那种“从 0 数到 n”专用的计数器。数次数用 `for i in range(n)`，`range` 不先造出一个装满整数的列表。

`break` 离开这一层循环。`continue` 进入下一次迭代。两者都只作用于最内层循环。

## 循环的 `else`

`for` 和 `while` 可以带 `else`。这个 `else` 在循环 **没有被 `break`** 时执行。它不表示“循环了零次”，也不表示“最后一项”。

```python
for item in values:
    if item < 0:
        break
else:
    return "all-non-negative"
return "found-negative"
```

如果所有元素都非负，循环正常结束，走进 `else`。如果碰到负数并 `break`，`else` 被跳过。很多人不读这个分支，所以真要用它，函数应当很短，并且名字能表达“没被打断”。觉得读者会误会时，改用一个布尔标志，那也很清楚。

## `try` 的 `else`

`try` 里没有异常时执行 `else`，有匹配的异常时走 `except`。把“只有成功后才做”的代码放进 `else`，可以避免 `except` 意外抓住 `else` 里新抛出的异常。完整的异常模型在 A10。

## 不要用异常当普通分支的唯一理由

“文件不存在就创建”这种事，用 `pathlib` 的方法或明确的条件往往更直接。另一方面，把外部输入转成整数时，`try` / `except ValueError` 比先用正则过滤更符合 Python 的习惯：先做，出错再处理。这个习惯叫 EAFP（请求原谅比请求许可容易）。两种风格都能写对，关键是错误类型要具体，见 A10。

## 机制

`if` 看的是真值，不是类型。空容器、`0`、`None`、空字符串为假，其余大多数对象为真。业务判断如果要把 `0` 当成有效数量，写成 `count is not None and count >= 0`，不要写成 `if count`。

`for` 的对象必须可迭代。循环变量是每次从迭代器取出的元素，不是下标，除非你迭代的就是 `range`。`for i in range(len(items))` 通常是把下标语言的习惯搬过来了。需要下标时用 `enumerate`。

`while` 适合“条件在循环体内才变”的场景。条件在开头检查。循环里不更新条件就是死循环。教程示例不写死循环。

`break` 离开这一层循环。`continue` 进入下一次。二者都只作用于最近的 `for` 或 `while`。

循环的 `else` 在循环没有被 `break` 打断时执行。它不是“循环条件为假时的另一支 if”，也不是“出错时”。搜索场景里，`else` 表示“找遍了还没有 break”。很多人读错，所以团队里如果没人习惯它，就改成一个 `found` 标志，把意思写在名字上。

`try` 的 `else` 在 `try` 没有异常时执行，并且这里抛出的异常不会被同一个 `try` 的 `except` 抓住。适合放“成功后才做的事”，避免把成功路径误放进 `try` 导致意外被捕获。`finally` 无论成败都执行，用来释放资源。`finally` 里的 `return` 会吞掉原来的异常或返回值，A10 专门演示，不要学那种写法。

`match` 不是这一章的 `switch`。它是结构模式匹配，名字的绑定规则和 `if` 不同。放在 [B10](../第二部分-进阶/B10-模式匹配.md)。不要在入门阶段拿它替换每一个分支。

## 会出事的写法

- 用异常当普通的“没找到”。偶尔可以，但每个未命中都构造异常对象，并且把真实的 `KeyError` 一起吞掉。找不到用返回值或一个专用异常，捕获时写具体类型。
- `for` 的循环变量在循环结束后仍留在函数局部里，值是最后一次绑定。不要假设它会消失。
- 在循环里改正在迭代的列表长度。可能跳过元素。要删除时迭代副本，或收集下标后再删。
- 三层嵌套 `if` 却没有提前返回。函数读到第 40 行还不知道哪些情况已经结束。提前返回把失败情况先处理掉。

## 加练

1. 写一个函数，在列表里找第一个负数。找到就返回它，找不到返回 `None`。用循环 `else` 和用 `found` 标志各写一版，比较哪一版你的同事能读懂。
2. `for item in items: if item is None: continue` 之后，`item` 在循环外还在吗？

参考答案：

1. 两版都可以。循环 `else` 挂在 `for` 上，没有 `break` 才走。如果团队不熟，用 `found`。行为必须一样：找到的是第一个负数，而不是最后一个。
2. 在。函数局部名字会留着最后一次赋值。不要在循环外使用它，除非你有意保留最后一项。

## 面试

### Q1. `for` 的 `else` 什么时候执行？

**考点**：这个语法的真实触发条件。很多人会答反。

**回答**：

1. 循环正常结束、没有碰到 `break` 时执行。
2. 被 `break` 打断时不执行。异常向外抛出时，循环没有正常结束，`else` 也不执行。
3. 它不表示“循环零次”。零次且没有 `break` 时，`else` 仍然执行。搜索失败是它少数清楚的用途。

### Q2. 为什么不推荐用裸 `except` 包住整个循环？

**考点**：异常层次和可诊断性。

**回答**：

1. 裸 `except` 连 `KeyboardInterrupt` 和 `SystemExit` 一起抓。`except Exception` 也仍然太宽，会把程序错误当成业务分支。
2. 捕获的类型要窄到你准备处理的那一种，例如 `ValueError` 或自定义的 `NotFound`。
3. 未知异常让它冒出去。日志和边界负责呈现，循环负责完成或明确失败。

### Q3. `if items` 和 `if items is not None` 差在哪？

**考点**：真值和缺失。

**回答**：

1. `if items` 把空列表当成假。空列表常常是合法结果。
2. `is not None` 只排除缺失。空容器仍然进入处理。
3. 数量 `0` 同理。分页偏移、金额、计数都不能用真值判断代替比较。

## 常见错误

- 在 `for` 循环里修改正在遍历的列表长度，跳过或重复元素。需要修改时遍历副本，或另外收集结果。
- 认为循环 `else` 是“空序列时执行”。空序列确实没有 `break`，所以会执行 `else`；非空但从未 `break` 时也会执行。
- 用多层嵌套 `if` 复制同一段善后逻辑。善后更适合 `finally` 或 `with`，后面两章会讲。

## 练习

1. 写一个循环，求 `1` 到 `n` 里所有奇数的和。`n = 5` 时结果是 `9`。
2. 解释示例里 `while` 累加时为什么结果是 `4` 而不是 `6`。
3. 什么情况下循环 `else` 不会执行？

参考答案：

1. `total = sum(i for i in range(1, n + 1) if i % 2)`，或者普通 `for` 加判断。`n = 5` 时奇数是 1、3、5。
2. `n == 2` 时 `continue` 跳过了 `total += n`，所以只加了 1 和 3。
3. 循环被 `break` 离开时。`return` 会直接离开函数，`else` 同样不会执行。

## 小结

条件按顺序匹配，`for` 遍历可迭代对象。循环的 `else` 表示“没有 break”。成功后的代码可以放在 `try` 的 `else` 里。模式匹配先留到 B10。
