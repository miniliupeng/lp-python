# A09　文件与路径

> 示例：`examples/part_a/a09_files.py`

## 学完你能做什么

用 `pathlib` 定位文件，用 `with` 保证关闭，并用 UTF-8 读写文本。不在字符串上手工拼接路径。

## 路径是对象

`pathlib.Path` 表示一条路径。`/` 运算符拼接片段，会按当前系统处理分隔符：

```python
path = root / "notes" / "hello.txt"
```

常用属性：`name`（文件名）、`suffix`（扩展名，带点）、`parent`、`stem`（去掉扩展名）。`relative_to` 求相对路径，前提是它确实在那个目录之下，否则抛 `ValueError`。

`mkdir(parents=True, exist_ok=True)` 用来创建目录。示例里父目录确定不存在，所以只调用了一次 `mkdir()`。已经可能存在时加上 `exist_ok=True`，避免和别的进程互相撞出 `FileExistsError`。

遍历目录用 `iterdir()`。它不是递归的。3.12 的 `Path.walk()` 才提供类似 `os.walk` 的递归遍历。示例只用了一层。

## 文本要写编码

```python
path.write_text("你好\n第二行\n", encoding="utf-8")
path.read_text(encoding="utf-8").splitlines()
```

`splitlines()` 按行切开并去掉行尾，平台的 `\n` 和 `\r\n` 都覆盖。不要用 `split("\n")` 处理来自 Windows 的文件，除非你确定内容里只有 `\n`。

更细的控制用 `with path.open("r", encoding="utf-8") as handle:`。`with` 离开代码块时关闭文件，包括块里发生异常的情况。A10 和 B08 解释它背后的协议。现在先当成“申请资源，用完一定还”的语法。

二进制用 `"rb"` / `"wb"`，这时没有文本编码，读写的是 `bytes`。图片、压缩包、任何不是文本的格式都走二进制。不要先当文本读进来再 `encode` 回去。

## 临时文件

示例用 `tempfile.TemporaryDirectory()`。离开 `with` 后目录被删掉，测试不会在仓库里留下 `note.txt`。库代码如果需要持久文件，路径应该由调用方传入，不要写死到家目录或当前目录。

当前工作目录取决于你在哪里启动进程，不是取决于 `.py` 文件放在哪。脚本旁边的数据文件用 `Path(__file__).resolve().parent` 定位，不要假设用户正好在那个目录里执行。

## 机制

路径用 `pathlib.Path`，不要用字符串拼接斜杠。`Path` 知道当前系统的分隔符，`/` 运算符在 `Path` 上是拼接，不是除法。`path.resolve()` 会规范化 `.` 和 `..` 并尽量变成绝对路径。它不检查你有没有权限。

文本文件是编码后的字节。`Path.read_text(encoding="utf-8")` 和 `open(path, encoding="utf-8")` 都要写编码。3.12 不写编码时仍可能跟随区域设置。3.15 才把默认改成 UTF-8。教程两边都写死。

`with` 离开块时关闭文件，包括块里发生异常的情况。关闭走的是上下文管理协议，不是垃圾回收。CPython 引用计数往往很快回收文件对象，但那不是语言保证，PyPy 更不能赌。文件用 `with`。

写入想要“要么全有要么全无”时，先写临时文件，再 `os.replace` 到目标名字。`os.replace` 在同一文件系统上是原子改名。直接 `write_text` 到目标，进程在中途死掉会留下半截文件。示例如果使用临时目录，结束时应删掉，不把垃圾留在工作区。

`Path.walk` 是 3.12 的方法，用来遍历目录树。它比自己递归 `iterdir` 少写一层。跟随符号链接与否要显式决定，否则备份脚本会把链接当目录走进去，或者把同一棵树走两遍。

二进制用 `"rb"` / `"wb"`，得到 `bytes`。不要对图片做 `decode("utf-8")`。

## 会出事的写法

- `open(user_path)` 里的 `user_path` 含有 `..`。先把根目录 `resolve`，再把拼接结果 `resolve`，确认结果仍在根目录之下。D08 把这个检查写成断言。
- 用当前工作目录拼相对路径。服务的工作目录由启动脚本决定，不是由源码位置决定。数据文件用 `Path(__file__).resolve().parent` 定位，或者用配置里的绝对路径。
- 打开文件后在异常分支忘记关。用 `with`。不要在 `__del__` 里关。
- 把口令写进仓库里的配置文件再 `read_text`。配置来自环境或仓库外的文件，日志不打印内容。

## 示例对照

`examples/part_a/a09_files.py` 在临时目录里写文本、按 UTF-8 读回、用 `Path` 拼接，并在结束时清理。断言比较的是读回的字符串，不是 `print`。如果断言里出现编码错误，优先检查是不是漏了 `encoding`。

## 加练

1. 为什么 `Path("a") / "b" / "c.txt"` 比 `"a" + "/" + "b"` 好？
2. 写一个函数，把文本写到路径，中途崩溃时读者不能看到半截新内容。说出关键的两个调用。

参考答案：

1. `Path` 的 `/` 处理分隔符和类型，读起来是路径。字符串拼接在 Windows 和多余的斜杠上容易错。
2. 写到同一目录的临时文件，写完 `flush` 并在需要时 `fsync`，然后 `os.replace` 到目标。替换是同一文件系统上的原子步骤。

## 面试

### Q1. 为什么读写文本必须写编码？

**考点**：3.12 和 3.15 的默认值差别，以及跨机器。

**回答**：

1. 磁盘上是字节。文本是解码后的码位。
2. 3.12 的默认编码仍可能随区域设置变化。3.15 起 PEP 686 把默认改成 UTF-8，但显式写出的代码在两种版本上意思相同。
3. 示例和库代码都写 `encoding="utf-8"`。失败让 `UnicodeDecodeError` 出现，不要 `errors="ignore"`。

### Q2. `with open(...)` 保证了什么，不保证什么？

**考点**：上下文管理器和持久化原子性。

**回答**：

1. 保证离开块时调用 `close`，包括异常路径。
2. 不保证数据已经落到磁盘。那要 `flush` 和 `os.fsync`。
3. 不保证替换目标文件是原子的。原子替换用临时文件加 `os.replace`。

### Q3. 怎样防止用户路径逃出根目录？

**考点**：路径规范化后的前缀判断。

**回答**：

1. 根目录 `resolve()`，用户路径与根拼接后再 `resolve()`。
2. 用 `relative_to` 判断结果仍在根下。失败是拒绝，不是把 `..` 删掉就算安全。
3. 符号链接会在 `resolve` 时被解开。根外面的链接不能因为拼接时看起来在里面就放行。

## 常见错误

- 用 `"../" + name` 拼接用户输入。这既不跨平台，也会在 D08 变成路径穿越问题。
- 打开文件后不关闭。小脚本有时能靠进程退出混过去，库代码不行。用 `with`。
- 省略 `encoding`。3.12 跟区域设置走，3.15 默认 UTF-8。显式写出，两边都正确。

## 练习

1. 给定 `Path("/tmp/a/b.txt")`，`name`、`suffix`、`parent` 各是什么？在你自己的机器上用绝对路径试，不要假设盘符。
2. 写一段代码，把三行文字写到临时文件再读出来，行列表应当和写入前一致。
3. 为什么示例可以在断言之后不再调用 `unlink`？

参考答案：

1. `name` 是 `b.txt`，`suffix` 是 `.txt`，`parent` 是 `/tmp/a`。Windows 上根不一样，但这三个属性的含义相同。
2. 结构就是示例里的 `write_text` / `read_text` / `splitlines`。
3. `TemporaryDirectory` 的 `__exit__` 会删除整个目录，文件一起消失。

## 小结

路径用 `Path` 拼接和查询。文本读写显式 UTF-8。资源用 `with` 关闭。不要依赖进程的当前目录去找包在仓库里的文件。
