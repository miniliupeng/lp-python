# A01　安装、运行，以及 Python 到底在执行什么

> 示例：`examples/part_a/a01_run_model.py`。本章示例在 CPython 3.12 上运行。

## 学完你能做什么

装好解释器，用三种方式运行代码，并说清“Python 不是逐行读源码然后立刻做运算”这件事。

## 安装与确认

本教程的可执行示例锁定 **CPython 3.12**。2026 年 11 月的最新稳定版是 3.15，但示例故意不使用 3.13 及以上的语法，这样在 3.12 上就能原样跑通。更高版本的增量放在 [C07](../第三部分-运行时/C07-自由线程与新版本.md)。

```bash
python3 --version
python3 examples/part_a/a01_run_model.py
```

看到 `Python 3.12.x` 和 `ok a01` 即可。如果系统里的 `python` 和 `python3` 不是同一个程序，后文统一写 `python`，你在本机把它换成实际可用的命令。

不要用操作系统自带的、且低于 3.12 的 Python 来跑本教程。类型联合 `int | None`、`list[int]` 这些写法我们会直接用，它们从 3.9 / 3.10 起可用，但教程整体按 3.12 讲述。

## 三种运行方式

1. **交互式解释器**。终端输入 `python` 回车，出现 `>>>`。适合验证一个表达式。退出用 `exit()` 或 Ctrl-D。
2. **脚本**。把代码放进 `hello.py`，执行 `python hello.py`。解释器会把该文件当成 `__main__` 模块执行。
3. **以模块方式运行**。`python -m 包名` 会按导入规则找这个包并执行它。后面讲包的时候会用到。和“随便给一个文件路径”相比，`-m` 的当前包上下文是明确的。

交互式适合提问，脚本适合保存。教程里的结论都以脚本里的 `assert` 为准：断言失败，进程以非零状态退出，`examples/run_all.py` 会把它算作错误。

## 源码会先变成字节码

CPython 执行一个函数时，大致是：

1. 解析源码，生成抽象语法树。
2. 编译成 **字节码**，放进代码对象（`code` object）。函数的 `__code__` 就是它。
3. 解释器在一个 **帧**（frame）里执行这些字节码。函数调用会压入新的帧。

所以“Python 是解释型语言”这句话太粗。更准确的说法是：CPython 先把源码编译成字节码，再由虚拟机执行。3.11 起这个虚拟机带有自适应的特化指令；3.13 起还有实验性的 JIT，而且默认不开。这些是后话，A 阶段只需要留下这个模型：

```text
源码 → 字节码（代码对象）→ 虚拟机在帧里执行
```

你现在不需要读字节码。需要拆开看的时候去 [C04](../第三部分-运行时/C04-字节码与解释器.md)。

## 语句和表达式

表达式算出一个值，例如 `1 + 2`、`add(2, 3)`。语句完成一件事，例如 `assert`、赋值、`def`、`if`。

函数由 `def` 定义。定义本身是一条语句，执行到它时，Python 创建一个函数对象，并把名字绑到这个对象上。因此函数可以赋给另一个名字，也可以当参数传递。`a01` 里的 `bound = add` 就是在做这件事。

```python
def add(left: int, right: int) -> int:
    return left + right

bound = add
assert bound(10, 1) == 11
```

冒号后面的 `int` 是 **注解**，给人和类型检查器看。CPython 3.12 不会因为你传入字符串就在调用时抛出类型错误。注解什么时候求值，[B09](../第二部分-进阶/B09-类型注解.md) 再讲。现在不要把注解理解成自动校验。

## `if __name__ == "__main__"`

一个文件被 `python file.py` 直接运行时，模块名是 `"__main__"`。它被别的文件 `import` 时，模块名是文件名。把演示和断言放进 `main()`，再用下面的判断调用，这个文件就既能当脚本跑，也能被导入而不自动跑演示。

```python
if __name__ == "__main__":
    main()
```

## 缩进是语法

Python 用缩进表示块，同一块里的缩进必须一致。本教程和示例使用 4 个空格，不使用 Tab。冒号 `:` 引出一个新块：`def`、`if`、`for`、`while`、`with`、`class` 都是这样。

## 机制

CPython 跑的不是你看到的那一排字符。`python file.py` 时，解释器大致做完这些事才开始产生你能观察的结果：

1. 读入源码字节，按编码解码成文本。文件开头的编码声明、`-X utf8` 和 3.15 起的默认 UTF-8，影响的是这一步，不是整数加法。
2. 解析成抽象语法树，再编译成代码对象。模块有一个代码对象，每个函数再各有一个。`函数.__code__.co_filename`、`co_names`、`co_consts` 都挂在这个对象上。
3. 为这次执行建一个帧：局部名字、求值栈、上一个帧的指针。调用函数就是压入新帧，`return` 弹出帧并把值交给调用方。
4. 虚拟机取字节码执行。3.11 起有自适应特化；3.13 起的 JIT 仍是实验，而且默认构建通常不包含或默认关闭。A 阶段不要把“解释执行”理解成“没有编译”。

所以这三句话要分开：

| 说法 | 对不对 |
| --- | --- |
| Python 源码被逐行解释，没有编译 | 错。先编译成字节码 |
| CPython 默认把函数编译成机器码并当生产 JIT 用 | 错。到 3.15 JIT 仍是实验特性 |
| 函数定义执行时创建函数对象 | 对。`def` 是运行时语句 |

`python -m 包` 和 `python 路径/文件.py` 的差别在模块搜索和 `__package__`。`-m` 按 `sys.path` 找包，相对导入有明确的包上下文；直接给文件路径时，这个文件就是 `__main__`，它旁边的包关系经常是空的。教程后面的循环导入示例用的是“把目录塞进 `sys.path` 再导入”，不是 `-m`。

交互式的 `>>>` 每读完一块就编译并执行。脚本是整份模块编译一次再执行。两边的语言规则相同，入口不同。把 `>>>` 抄进文件会得到 `SyntaxError`。

## 会出事的写法

- 用操作系统里名叫 `python` 的 3.8 跑 3.12 教程，然后把 `list[int]` 或 `X | Y` 的语法错误当成教程写错。先看 `python3 --version`。本环境是 CPython 3.12.3。
- 把类型注解当成运行时门卫。`add("2", "3")` 在示例那种函数里会做字符串拼接，不会抛类型错误。校验放在系统边界，见 D03。
- 模块顶层放连接数据库、起线程、读生产配置。导入就是执行顶层。测试和 `python -c "import 模块"` 都会触发它。演示放进 `main()`，用 `__name__ == "__main__"` 调用。
- 混用 Tab 和空格。`TabError` 或缩进相关的 `IndentationError` 是语法错误，发生在执行之前。本教程统一 4 个空格。

## 示例对照

`examples/part_a/a01_run_model.py` 把三件事钉死：

- `add(2, 3) == 5`：函数调用求值，返回值是对象。
- `__name__ == "__main__"`：这个文件是被直接运行的，不是被导入的。
- `bound = add` 且 `bound(10, 1) == 11`：名字绑的是函数对象，调用看对象，不看名字是不是 `add`。
- `f"{label=}"` 在 3.8 以上会带上名字，示例断言字符串是 `label='py'`。这只是调试格式，不是类型检查。

示例没有测量启动时间。启动慢通常是导入了太多模块，不是“Python 先编译所以慢”。那是后话，C04 和 C09 再拆。

1. 下面两段，哪一段在 `import` 时会打印？

```python
print("顶层")

def main():
    print("里面")

if __name__ == "__main__":
    main()
```

2. 为什么教程示例锁定 3.12 语法，却仍要单开一章讲 3.14 和 3.15？

参考答案：

2. 可执行示例必须在 3.12 上原样通过。更高版本的语法和运行时变化是事实，但写进 3.12 源码会直接无法运行。版本地图放在 C07，并标明哪一句还不是 3.12。

## 面试

### Q1. Python 是解释型语言还是编译型语言？

**考点**：能不能把宣传口号和 CPython 的真实流水线分开。

**回答**：

1. 语言本身没有规定必须解释或必须编译。CPython 的实现是：源码编译成字节码，虚拟机执行字节码。
2. 字节码存在代码对象里。函数的 `__code__` 就是它。`dis.dis` 能看到指令，但指令名会随版本变，不要背 opcode。
3. 3.11 的自适应特化、3.13 起的实验 JIT，都还在这条流水线后面。到 3.15，JIT 仍不是默认的生产编译器。简历上不要写“我们的 Python 默认把热点编译成机器码”。

### Q2. `if __name__ == "__main__"` 在防什么？

**考点**：导入的执行模型，以及副作用该放哪。

**回答**：

1. 直接运行文件时，模块名是 `"__main__"`。被 `import` 时，模块名是包路径里的名字。
2. 导入会执行模块顶层，否则 `def` 和 `class` 不会发生。顶层的打印、网络、写文件因此也会发生。
3. 把演示、`argparse` 和进程入口放进 `main()`，再用这个判断调用。库模块被别人导入时就不会把入口再跑一遍。多进程在 spawn 模式下重新导入主模块，这个判断还能避免子进程递归启动。

### Q3. 类型注解写了 `int`，传入 `str` 为什么往往不报错？

**考点**：静态检查和运行时是两套系统。

**回答**：

1. 注解存在函数的 `__annotations__` 里，给人和类型检查器看。CPython 3.12 不会在调用时按注解插入检查。
2. 3.12 在定义函数时求值注解；3.14 起默认改成延迟求值。两种都不等于校验。细节在 B09。
3. 外部输入要在边界解析成内部类型。注解替代不了这一步。

## 常见错误

- 把交互式里的 `>>>` 抄进脚本。那是提示符，不是代码。
- 认为“装了 Python 就等于装了本仓库的 FastAPI 等依赖”。本教程 `examples/` 只使用标准库。
- 用 `python` 跑 2.7 或 3.8 的解释器，然后觉得教程代码“不能运行”。先看 `--version`。

## 练习

1. 写一个函数 `triple(n)`，返回 `n * 3`。用断言检查 `triple(4) == 12`。
2. 把这个函数赋给名字 `f`，通过 `f` 调用它。
3. 解释：为什么把文件导入进另一个程序时，顶层的 `print` 会执行，而放在 `main()` 里且由 `__name__` 判断保护的 `print` 不会。

参考答案：

1. `def triple(n): return n * 3`，再 `assert triple(4) == 12`。
2. `f = triple`，`assert f(4) == 12`。两个名字指向同一个函数对象。
3. 导入会执行模块顶层语句，用来完成定义。`__name__` 只有在直接运行时才是 `"__main__"`，所以那一层保护下的调用不会在导入时发生。

## 小结

安装的是 CPython 3.12。脚本、交互式和 `python -m` 是三条入口。函数是对象。解释器执行的是编译后的字节码，不是源码文本本身。
