# B12　测试与打包入门

> 示例：`examples/part_b/b12_testing_packaging.py`

## 学完你能做什么

用标准库 `unittest` 把一个纯函数的规格固定下来，并读懂 `pyproject.toml` 里和版本有关的那几行。本教程的示例不安装第三方包，所以这里不用 pytest 也能跑。pytest 是同一类想法的另一种写法：调用函数，比较结果。

## 测行为，不测打印

`ClipTests` 做了三件事：区间内不变、高于上界被夹住、上下界写反时抛 `ValueError`。测试方法名说明的是行为。断言比较的是返回值或异常类型，不是一整段日志。

示例自己加载测试套件并 `assert result.wasSuccessful()`，这样 `examples/run_all.py` 不依赖 pytest 的收集规则。你在本地也可以对这个文件运行 `python -m unittest examples.part_b.b12_testing_packaging`，不过那个命令要求当前目录在导入路径上。直接 `python examples/part_b/b12_testing_packaging.py` 是教程保证的入口。

一个测试只让一个理由失败。`test_bad_range` 不用再断言返回值，它的规格就是“必须抛”。`assertRaises` 接住指定类型，别的异常仍会让测试失败。

## 什么值得测

纯函数最适合开这个头：同样的输入，同样的输出，没有时钟、没有网络。边界是测试的主体，不是添头。`clip` 的边界就是上界、下界和非法区间。

有副作用的代码把副作用推到边缘。读写文件时用临时目录，用完即删，A09 那样。当前时间不要在测试里 `sleep`。D02 会把时钟当参数传进去。

不要为了覆盖率去断言私有属性。私有属性一改名，测试就碎，而用户可见的行为可能没变。覆盖率是提醒你哪条路径没走到，不是目标本身。

## 打包文件在声明什么

示例用 `tomllib` 解析一段内嵌的项目声明，断言：

- 项目名是 `gradebook`。
- `requires-python` 是 `>=3.12`。

`tomllib` 从 3.11 起在标准库里，只能读，不能写。本教程目录没有自己的 `pyproject.toml`，因为这些示例不需要安装依赖。把同样的文本存成文件，就是一个最小项目声明。

一个现代项目的 `pyproject.toml` 至少说明：项目叫什么、需要哪一档 Python、依赖有哪些。锁文件记录某一次解析出来的具体版本，用来让别人安装到同一组依赖。入门阶段要分清这两件事：`requires-python` 是语言版本下限，锁文件是第三方包的具体版本。两者都不是“注释”，安装工具会读它们。

虚拟环境是一个独立的目录，里面有自己的解释器和第三方包。系统 Python 留给操作系统。项目依赖装进虚拟环境。本教程示例只用标准库，是为了让你没有虚拟环境也能把 `examples/run_all.py` 跑完。真要做需要第三方库的服务时，再单独建环境并锁版本。那一步不属于这些示例的运行条件。

## 机制

测试断言行为：给定输入，得到输出或得到某一种异常。不断言打印文案，不断言私有属性，除非那个属性就是对外契约。示例用 `assert` 和 `unittest`。工业项目常用 pytest：失败信息更清楚，`tmp_path`、参数化、fixture 用来建隔离环境。本分支不安装 pytest，所以示例不导入它。概念是一样的：每个测试独立，不依赖执行顺序。

什么值得测：不变量、边界、失败路径。不值得测：语言本身（`1+1`）、第三方库的 README 示例、私有实现的每一行。

打包的声明写在 `pyproject.toml`。PEP 621 的 `[project]` 表里有名字、版本、`requires-python`、依赖。`requires-python = ">=3.12"` 告诉安装器不要在更旧的解释器上装。它不是虚拟环境，也不会自动升级用户的 Python。

锁文件把依赖解析结果固定到具体版本和哈希。声明是范围，锁是一次解析的结果。应用要提交锁。库通常提交声明，由应用在自己的锁里固定传递依赖。本教程的示例不读取仓库里的 `uv.lock`，因为这个空分支没有那份文件。`tomllib.loads` 接收的是 `str`，不是 `bytes`。示例里的 TOML 是字符串常量。

虚拟环境是一套独立的 `site-packages` 和解释器入口。它解决“这个项目的依赖不要写进系统 Python”。`uv`、`venv` 都能创建。教程运行示例不需要激活虚拟环境，因为只用标准库。

## 会出事的写法

- 测试依赖上一个测试插入的全局列表。单独跑就失败。
- 用 `time.sleep` 等异步结果。慢且仍会抖。用事件、直接调用回调，或注入时钟。
- 把 `requires-python` 写成 `==3.12.3`。补丁版本不该卡死整个依赖图，除非你有非常具体的解释器缺陷。
- `tomllib.loads` 传入 `bytes`。它的实现按字符串处理换行，会得到难以理解的类型错误。二进制文件用 `tomllib.load`。

## 示例对照

`examples/part_b/b12_testing_packaging.py` 用 `unittest` 测一个纯函数，并用 `tomllib.loads` 解析一段项目声明，断言名字和 `requires-python`。这段声明是样本，不是本仓库的安装配置。

## 加练

1. 为一个“夹取到区间内”的函数列三条测试，其中一条是失败输入。
2. 声明和锁文件各回答哪个问题？

参考答案：

1. 中间值不变；低于下界变成下界；上界小于下界时抛 `ValueError`。不要测函数的局部变量名字。
2. `requires-python` 和依赖范围回答“可以在什么环境装”。锁文件回答“这次确定装了哪些精确版本”。

## 面试

### Q1. 为什么测试不该 `sleep`？

**考点**：确定性。

**回答**：

1. 睡眠把测试时间拉长，而且在慢机器上仍可能不够。
2. 要测的是“超时后的行为”，就注入一个假时钟，或直接调用超时分支。
3. 真正的集成测试如果必须等端口，等待条件是“端口可连接”，带上限，而不是固定睡几秒。

### Q2. `pyproject.toml` 里的 `requires-python` 保证了什么？

**考点**：声明不是运行时检查。

**回答**：

1. 它告诉安装器这个发行版支持哪些解释器。
2. 它不会阻止你用旧解释器直接跑源码目录。
3. 运行时若依赖 3.12 语法，在 3.11 上会在解析阶段就失败。声明和语法要一致。

### Q3. 库和应用程序的锁文件策略为什么不同？

**考点**：依赖解析的责任方。

**回答**：

1. 应用需要可重复构建，所以锁定全部传递依赖。
2. 库如果也锁死传递依赖，会把限制推给所有调用方。
3. 库声明兼容范围，应用在自己的锁里选定具体版本。

## 常见错误

- 测试里复制一份生产逻辑，两边一起错。测试应当写预期的输入输出，让生产代码去满足它。
- 依赖测试运行顺序。每个测试自己准备数据。
- 把 `requires-python` 理解成“只是给读者看的”。安装工具会用它拒绝过旧的解释器。

## 练习

2. 示例里的项目名是从哪一张 TOML 表读出来的？

参考答案：

2. `[project]` 表的 `name`，代码里是 `data["project"]["name"]`。

## 小结

用测试把边界行为写成可执行的规格。`unittest` 足够开始。`pyproject.toml` 声明语言版本和依赖，锁文件固定解析结果，虚拟环境把它们装到项目自己的目录里。
