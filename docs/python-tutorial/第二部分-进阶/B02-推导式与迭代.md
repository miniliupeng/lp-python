# B02　推导式与迭代协议

> 示例：`examples/part_b/b02_iterables.py`

## 学完你能做什么

说清 `for` 实际调用了什么，区分可迭代对象和迭代器，并用推导式写出过滤后的新容器。

## `for` 在做什么

`for item in obj` 大致是：

1. 调用 `iter(obj)`，得到迭代器。
2. 反复 `next(iterator)`。
3. 迭代器抛 `StopIteration` 时结束。这个异常由 `for` 接住，不会冒到你的业务代码。

可迭代对象实现 `__iter__`，每次 `iter()` 可以给出一个新迭代器。列表就是这样：`list(data)` 做两遍，两遍都完整。

迭代器实现 `__next__`，通常 `__iter__` 返回自己。它有状态，耗尽之后再 `next` 只会继续抛 `StopIteration`。示例把列表的迭代器取走一个元素，剩下的 `list(iterator)` 只有后半段，而且再调用 `next` 会失败。

所以：列表可以反复遍历；从它得到的迭代器不行。生成器表达式、文件对象、`map` 的返回值多数是一次性的。把一个迭代器传给两个消费者，第二个会看到空的。

## 自己写可迭代对象

`CountDown` 的 `__iter__` 是生成器函数。每次 `iter()` 都从 `start` 重新开始。这是“可重复遍历”的关键：`__iter__` 不要返回一个已经走了一半的共享迭代器，除非你有意这样做。

不要自己用 `raise StopIteration` 从生成器里结束迭代。生成器里的 `return` 会转换成 `StopIteration`。在生成器里直接 `raise StopIteration` 会被解释器当成别的错误（3.7 起是 `RuntimeError`）。用 `return`。

## 推导式

```python
[n * n for n in range(4) if n % 2 == 0]
```

这是新列表。`if` 是过滤，不是三元表达式。集合推导式用 `{}`，字典推导式是 `{键: 值 for ...}`。空集合不是 `{}`，`{}` 是空字典；空集合写 `set()`。

生成器表达式把方括号换成圆括号，结果是迭代器，不立刻把元素都算出来。它适合交给 `sum`、`any`、`max` 这种只遍历一次的函数。如果后面要遍历两遍，先做成列表，或者接受重新创建生成器。

推导式有自己的作用域。推导式里的循环变量不会漏到外面。这和 Python 2 不同，也和普通 `for` 不同：普通 `for` 的循环变量在循环结束后仍然存在。

3.15（PEP 798）允许在推导式里写 `*` 和 `**` 解包。3.12 没有这个语法。要拼平一层嵌套，3.12 用循环或 `itertools.chain.from_iterable`。

## 机制

`for` 并不要求对象是列表。它调用 `iter(obj)`。如果对象实现 `__iter__`，就用它返回的迭代器。否则如果实现了 `__getitem__`，解释器会从 0 开始取，直到 `IndexError`。迭代器必须实现 `__next__`，耗尽时抛 `StopIteration`。`for` 捕获这个异常来结束，你自己的代码不要靠捕获 `StopIteration` 来结束业务。

自己写迭代器时，`__iter__` 返回 `self`，`__next__` 前进。可迭代对象和迭代器可以是两个类：容器的 `__iter__` 每次返回一个新迭代器，这样就能遍历两遍。如果 `__iter__` 返回 `self` 且自身会耗尽，第二次 `for` 就是空的。

推导式是创建列表、字典、集合的表达式。它有自己的局部作用域。推导式里的循环变量不会泄漏到函数局部，这和普通 `for` 不同。生成器表达式用圆括号，不一次建成列表，适合大序列的管道。

`enumerate` 给出下标和元素。`zip` 在最短的那个结束。3.10 起 `zip(..., strict=True)` 在长度不同时抛异常。默默截断经常把数据对齐错误藏起来。

## 会出事的写法

- 在 `__next__` 里 `raise StopIteration`。从生成器里这样写会变成 `RuntimeError`。用 `return` 结束生成器。手写迭代器类可以抛 `StopIteration`，因为那是协议本身。
- 推导式里做 I/O 或复杂分支。它应该是表达式。复杂了就写 `for`。
- 遍历时删除列表元素。迭代副本或收集后删除。
- 把迭代器传给两个消费者。第二个什么都拿不到。需要两遍就传入可重复迭代的容器。

## 加练

1. 写一个 `Countdown`，`for x in Countdown(3)` 得到 3、2、1。它应该能遍历两次。
2. 用推导式从单词列表里取出长度大于 3 的单词的小写形式。再说一个不该用推导式的情况。

参考答案：

1. `__iter__` 返回一个新的迭代器对象，计数从 3 开始。不要把耗尽状态存在 `Countdown` 自己身上。
2. `[word.lower() for word in words if len(word) > 3]`。里面要 `try` 或要记录日志时，改成普通循环。

## 面试

### Q1. 可迭代对象和迭代器有什么差别？

**考点**：协议，而不是“有没有 `__iter__`”一句话。

**回答**：

1. 可迭代对象能给出迭代器。迭代器能给出下一项。
2. 容器每次 `__iter__` 返回新迭代器，就能遍历多次。
3. 迭代器的 `__iter__` 通常返回自己。文件对象就是这样，读完再 `for` 不会重新打开。

### Q2. `for` 内部发生了什么？

**考点**：`iter` 和 `StopIteration`。

**回答**：

1. `iter` 得到迭代器。
2. 反复 `next`，把 `StopIteration` 当作结束。
3. 循环变量是普通赋值。循环结束后名字还在，值是最后一次成功取出的元素。

### Q3. 推导式的循环变量会泄漏吗？

**考点**：作用域版本差异不要答成旧版本。

**回答**：

1. 在 Python 3 的列表、字典、集合推导式里，循环变量在推导式自己的作用域中，不泄漏到函数。
2. 这和 `for` 不同。`for` 的名字留在函数局部。
3. 生成器表达式同样不泄漏。不要用旧博客里“Python 2 推导式会泄漏”来描述 3.12。

## 常见错误

- 对一个迭代器调用两次 `list`，第二次是空的，还以为数据丢了。
- 用推导式做有副作用的事情，比如在里面 `append` 到外部列表。推导式是表达式，副作用放进普通循环更清楚。
- 写 `{x for x in items}` 只为了去重，然后依赖遍历顺序。集合不保证顺序。要保持首次出现的顺序，用 A08 的 `dict.fromkeys`。

## 练习

1. 写一个函数，判断可迭代对象里有没有负数。不要把它整个变成列表。
2. 解释 `squares = (n * n for n in range(3))` 之后，为什么 `next` 一次再 `list` 一次，结果里没有 `0`。
3. 字典推导式怎么从 `[("a", 1), ("b", 2)]` 得到 `{"a": 1, "b": 2}`？

参考答案：

1. `return any(n < 0 for n in values)`。`any` 碰到第一个真值就停止。
2. 生成器表达式是一次性迭代器。`0` 已经被 `next` 取走了。
3. `{key: value for key, value in pairs}`。

## 小结

`for` 是 `iter` 加 `next`。可迭代对象可以重新开始，迭代器通常不能。推导式制造新容器，生成器表达式制造一次性管道。过滤条件写在 `for` 后面。
