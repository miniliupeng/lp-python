# B06　特殊方法与协议

> 示例：`examples/part_b/b06_dunder.py`

## 学完你能做什么

让自己的类型支持 `+`、`==`、`len` 和字典键，并且不破坏哈希契约。

## 特殊方法由解释器去找

`len(obj)` 会找 `obj` 所属类型上的 `__len__`。语法 `a + b` 会找 `a` 的类型上的 `__add__`。你几乎不要自己写 `obj.__len__()`，写 `len(obj)`。自己调用特殊方法会绕过一些内置类型的优化和检查，也让代码看起来像在钻实现。

这些方法必须定义在类上，不能运行时塞进实例的 `__dict__` 就指望 `+` 会看见。解释器是在类型上找它们。

## `NotImplemented` 不是 `NotImplementedError`

`Vec.__add__` 遇到不是 `Vec` 的对象时返回 `NotImplemented`。这是一个值，告诉解释器：“我不会加，请试试另一边的 `__radd__`”。两边都不会，才抛 `TypeError`。

`raise NotImplementedError` 是另一回事，表示子类还没实现这个方法。不要把这两个弄混，也不要在 `__add__` 里对类型不对的情况抛 `TypeError`。返回 `NotImplemented` 给另一边机会。

## 相等和哈希是一套契约

如果 `a == b`，那么 `hash(a) == hash(b)` 必须成立，只要它们会被放进集合或当字典键。哈希还应当在对象作为键的期间保持不变。

`Vec` 的相等性看坐标，哈希也用坐标。因此 `Vec(1, 2)` 可以当字典键，另一个坐标相同的 `Vec` 能取回同一个值。

只写 `__eq__` 不写 `__hash__` 时，Python 会把类标记成不可哈希。这是保护：你已经改变了相等性，默认的“按身份哈希”不再和相等性兼容。可变对象如果按内容比较，就不要提供哈希。元组能当键，是因为它的槽位不能改，而且里面的元素也必须能哈希。

`__eq__` 对不认识的类型应返回 `NotImplemented`，让对方的比较方法有机会运行。返回 `False` 会把“我不知道”说成“不相等”，有时会挡住合理的比较。

## 协议是一组方法

迭代协议是 `__iter__` / `__next__`。上下文协议是 `__enter__` / `__exit__`。映射、序列、可调用各自有约定的方法。你不需要继承某个特定的基类才能被 `for` 使用，实现约定的方法即可。这是鸭子类型。

鸭子类型的边界是：调用方依赖的方法要真的符合约定，包括异常类型和返回值。只是碰巧有个叫 `__iter__` 的方法、却不返回迭代器，那不是协议，是陷阱。

类型注解里的 `Protocol` 把这种约定写给类型检查器。运行时的 `@runtime_checkable` 只做很浅的检查。D03 再区分这两层。

## 机制

特殊方法由解释器在类型上找，不在实例字典里找。你给实例赋值 `__len__ = lambda self: 1` 不会改变 `len(obj)`。`len` 看的是 `type(obj).__len__`。这是为了让内建操作稳定，也让解释器能走快路径。

协议是一组这样的方法。容器看 `__len__`、`__iter__`、`__getitem__`。可调用看 `__call__`。上下文管理器看 `__enter__` 和 `__exit__`。数值看 `__add__` 等。解释器按协议调用，你按协议实现。

`__eq__` 如果返回 `NotImplemented`，解释器会试对面的 `__eq__`。这和抛 `NotImplementedError` 完全不同。后者是异常，表示“子类应该覆盖但没覆盖”。比较方法返回 `NotImplemented` 表示“我不认识对方的类型”。

相等和哈希是一套契约。定义了 `__eq__` 却不定义 `__hash__`，类会变成不可哈希，不能进集合。如果相等看业务键，哈希也必须只看同一组键，并且键不能变。

`__str__` 给人看，`__repr__` 给开发者看，最好能看出类型和关键字段。没有 `__str__` 时退到 `__repr__`。容器的 `repr` 会调用元素的 `repr`。

鸭子类型的边界：协议方法在不在，决定内建函数能不能用。它不检查语义。一个有 `__len__` 却返回负数的对象会让 `len` 抛 `ValueError`。类型检查器的 `Protocol` 是另一层，见 D03。

## 会出事的写法

- 只写 `__eq__` 不写 `__hash__`，然后把对象放进 `set`，得到 `TypeError`。或者反过来，相等变了哈希没变。
- 在实例上动态替换 `__getitem__`，以为切片语法会跟着变。
- `__add__` 里修改 `self` 并返回 `self`。`+` 的调用方以为得到新对象。就地改用 `__iadd__` 并写清楚。
- `__bool__` 和 `__len__` 互相矛盾。真值会优先用 `__bool__`，没有才看长度是否非零。

## 示例对照

`examples/part_b/b06_dunder.py` 应断言比较、哈希或不可哈希、以及 `NotImplemented` 的回退。不要用打印 `repr` 当测试。断言相等关系和能否进集合。

2. 为什么 `len(obj)` 看不到你赋在实例上的 `__len__`？

参考答案：

2. 因为查找发生在类型上。要改变行为就在类上定义方法。

## 面试

### Q1. 特殊方法为什么不从实例字典里找？

**考点**：解释器的查找规则。

**回答**：

1. 内建运算在类型上找特殊方法，保证行为由类型决定。
2. 实例字典里的同名对象只是普通属性，`len` 不会调用它。
3. 显式调用 `obj.__len__()` 才会走普通属性查找。两者不要混用。业务代码用 `len(obj)`。

### Q2. `NotImplemented` 和 `NotImplementedError`？

**考点**：返回值和异常。

**回答**：

1. `NotImplemented` 是比较和算术方法返回的哨兵，让解释器去试反向运算。
2. `NotImplementedError` 是异常，表示抽象方法没实现。
3. 在 `__eq__` 里抛异常会让 `==` 失败。不认识对方的类型时应返回 `NotImplemented`。

### Q3. 自定义对象放进 `set` 的条件？

**考点**：哈希契约。

**回答**：

1. 必须可哈希，且生命周期内哈希不变。
2. 相等的对象哈希相等。
3. 定义 `__eq__` 后默认失去哈希。要进集合就同时定义 `__hash__`，或者明确不要哈希、只用 `==`。

## 常见错误

- 定义了 `__eq__` 又去把对象当字典键，然后对 `TypeError` 感到意外。
- `__add__` 修改 `self` 再返回。加法应当返回新对象，就地修改用 `__iadd__`，而且名字要让人想得到。
- 为了打印好看只写 `__str__`，调试时容器里看到的仍是默认表示。调试用 `__repr__`，它应当尽量无歧义。`__str__` 留给给用户看的句子。

## 练习

1. 给一个二维向量增加 `__repr__`，让 `repr(Vec(1, 2))` 包含两个坐标。示例不必改，自己在解释器里试。
2. 为什么示例可以把 `Vec` 放进字典？
3. `Vec(1, 2) + "no"` 为什么是 `TypeError` 而不是返回 `NotImplemented` 给调用方？

参考答案：

1. `return f"Vec({self.x}, {self.y})"`。
2. `__eq__` 和 `__hash__` 都基于坐标，契约成立，对象又不会在当键之后修改坐标。示例没有提供修改坐标的方法。
3. 两边都返回了“不会处理”，解释器把这个结果转成 `TypeError`。`NotImplemented` 不是给业务代码看的返回值。

## 小结

特殊方法定义在类上，由对应的语法去调用。不支持的运算返回 `NotImplemented`。一旦按内容定义相等，就要同时决定哈希：要么和相等性一致，要么拒绝哈希。
