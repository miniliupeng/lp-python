# B05　类与对象

> 示例：`examples/part_b/b05_classes.py`

## 学完你能做什么

写一个有继承关系的小类层次，用 `super()` 沿着 MRO 调用下一站，而不是写死父类名字。

## 类体在定义时执行

`class Dog(Animal)` 执行类体，把类体里的名字收进一个命名空间，再用这个命名空间创建类对象。类对象本身也是对象，`Dog` 这个名字指向它。`Dog()` 创建一个实例。

实例查找属性时，先看实例自己的 `__dict__`（如果有），再沿着类和基类找。方法存在类上，不在每个实例上复制一份。`self.speak` 取到的是绑定方法：函数的第一个参数已经绑上这个实例。这是描述符做的事，C08 会拆开。现在知道“方法调用会把实例传给 `self`”就够了。

## 继承是查找顺序

`Dog` 没有写构造函数，就用 `Animal` 以至 `object` 的。`Dog.speak` 覆盖了 `Animal.speak`。覆盖不是删除：`super().speak()` 还能找到下一站。

示例里 `Dog().speak()` 是 `"woof..."`。`super()` 不是“父类”的简写。它从 **当前实例的 MRO** 里，当前类的下一站开始找。在单继承里，下一站就是你写在括号里的那个类，所以口误还能蒙对。多继承就不是。

## C3 线性化

`D(B, C)`，而 `B` 和 `C` 都继承 `A`。MRO 是：

```text
D, B, C, A, object
```

示例断言了这个顺序，以及 `D().ping()` 等于 `"DBCA"`。每一层都调用 `super().ping()`，于是沿着 MRO 走一遍，`A` 只出现一次。这就是合作式继承。

如果 `B.ping` 写成 `A.ping(self)`，它会跳过 `C`。菱形继承里这是错的。要参与 `super()` 链条，每一层都应该调用 `super()`，包括中间层。

C3 保证：子类在基类前面；基类列表里左边的在右边的前面；每个类只出现一次。违反单调性的基类声明会在定义类时抛 `TypeError`，而不是运行到一半才发现。能定义成功的类，`类型.__mro__` 就是权威顺序。

## 不要为了继承而继承

“是一个”比“想复用三行代码”更适合做继承的理由。复用三行代码，用一个函数。继承把两个类型的查找顺序焊在一起，以后改基类会影响所有子类。

组合是把一个对象放进另一个对象的属性里，由外层方法去调用它。库存系统里的“仓库拥有一组货位”用组合，不要让仓库去继承货位。

## 常见错误

- 覆盖方法时改了参数意义，调用方仍然按基类的约定调用。
- 在 `__init__` 里忘记调用 `super().__init__()`。子类和父类都要初始化时，用 `super()`，不要点名父类，否则多继承又会漏。
- 用类属性当默认可变容器：`class Bag: items = []`。所有没在实例上覆盖 `items` 的实例共享这个列表。可变默认状态放在 `__init__` 里，每个实例新建一个。

## 练习

1. 画 `D` 的 MRO，不看示例输出，再对照 `D.__mro__`。
2. 如果 `C.ping` 不调用 `super()`，直接返回 `"C"`，`D().ping()` 变成什么？
3. 为什么示例的 `Animal` 不需要 `__init__`？

参考答案：

1. `D, B, C, A, object`。
2. `"DBC"`。`B` 的 `super()` 仍然会找到 `C`，但 `C` 不再把查找继续到 `A`。
3. 它没有每个实例都要保存的状态。`object` 的初始化够用。

## 小结

类体执行一次，用来制造类对象。实例方法通过绑定把实例放进 `self`。多继承的下一站由 MRO 决定，`super()` 按这个顺序走。能用函数或组合解决的，不必做类层次。
