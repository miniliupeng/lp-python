# B05　类与对象

> 示例：`examples/part_b/b05_classes.py`

## 学完你能做什么

写一个有继承关系的小类层次，用 `super()` 沿着 MRO 调用下一站，而不是写死父类名字。

## 类体在定义时执行

`class Dog(Animal)` 执行类体，把类体里的名字收进一个命名空间，再用这个命名空间创建类对象。类对象本身也是对象，`Dog` 这个名字指向它。`Dog()` 创建一个实例。

实例查找属性时，先看实例自己的 `__dict__`（如果有），再沿着类和基类找。方法存在类上，不在每个实例上复制一份。`self.speak` 取到的是绑定方法：函数的第一个参数已经绑上这个实例。这是描述符做的事，C08 会拆开。现在知道“方法调用会把实例传给 `self`”就够了。

## 继承是查找顺序

`Dog` 没有写构造函数，就用 `Animal` 以至 `object` 的。`Dog.speak` 覆盖了 `Animal.speak`。覆盖不是删除：`super().speak()` 还能找到下一站。

示例里 `Dog().speak()` 是 `"woof..."`。`super()` 不是“父类”的简写。它从 **当前实例的 MRO** 里，当前类的下一站开始找。在单继承里，下一站就是你写在括号里的那个类，所以口误还能蒙对。多继承就不是。

## C3 线性化

`D(B, C)`，而 `B` 和 `C` 都继承 `A`。MRO 是：

```text
D, B, C, A, object
```

示例断言了这个顺序，以及 `D().ping()` 等于 `"DBCA"`。每一层都调用 `super().ping()`，于是沿着 MRO 走一遍，`A` 只出现一次。这就是合作式继承。

如果 `B.ping` 写成 `A.ping(self)`，它会跳过 `C`。菱形继承里这是错的。要参与 `super()` 链条，每一层都应该调用 `super()`，包括中间层。

C3 保证：子类在基类前面；基类列表里左边的在右边的前面；每个类只出现一次。违反单调性的基类声明会在定义类时抛 `TypeError`，而不是运行到一半才发现。能定义成功的类，`类型.__mro__` 就是权威顺序。

## 不要为了继承而继承

“是一个”比“想复用三行代码”更适合做继承的理由。复用三行代码，用一个函数。继承把两个类型的查找顺序焊在一起，以后改基类会影响所有子类。

组合是把一个对象放进另一个对象的属性里，由外层方法去调用它。库存系统里的“仓库拥有一组货位”用组合，不要让仓库去继承货位。

## 机制

`class` 语句执行时，解释器先创建一个命名空间，把类体当普通代码执行，再把这个命名空间交给元类（默认 `type`）造出类对象。所以类体里的赋值、函数定义甚至循环都会在定义时发生。类属性因此是类对象上的名字，实例查找不到自己的属性时才去类上找。

实例属性一般在 `__init__` 里通过 `self.x = ...` 放进实例的 `__dict__`。`__init__` 不返回实例。构造过程是 `__new__` 先造出对象，再调用 `__init__` 初始化。你几乎总是只写 `__init__`。需要不可变类型或缓存同一对象时才写 `__new__`。

方法函数存在类上。通过实例取出时，解释器绑定 `self`，得到方法对象。通过类取出时拿到的是函数，需要自己传实例。

继承的查找沿着 MRO。`super()` 不是“父类”，它按当前实例的 MRO，从当前类的下一个开始找。合作式多重继承要求每层都调用 `super()`，并且签名兼容。示例里如果 `D(B, C)`、`B(A)`、`C(A)`，MRO 是 `D, B, C, A, object`。各层 `ping` 都调用 `super` 时，结果是沿着这条链拼出来的字符串，而不是“只调用 B”。

不要为了复用两三行就继承。组合是把协作者当属性拿着。继承表示“是一种”，并且子类必须能出现在任何使用父类的地方。做不到就不要继承。

## 会出事的写法

- 类体里写可变类属性 `items = []`，所有实例共享这个列表。需要每实例一份就放在 `__init__`。
- 覆盖了方法却不调用 `super()`，父类的初始化没发生，对象半成品。
- 多重继承里有的分支调 `super`，有的直接写父类名。MRO 被绕开，某个 `__init__` 会执行两次或零次。
- 在类体里做网络请求。导入模块时类体就会执行。

## 示例对照

`examples/part_b/b05_classes.py` 应断言实例属性不共享、MRO 的顺序，以及 `super()` 链的结果。把 `Class.__mro__` 打出来和断言对照。如果结果是 `DBCA` 一类的拼接，那就是合作式 `super`，不是深度优先。

## 加练

1. 为什么 `class Bag: items = []` 然后 `self.items.append(x)` 会在实例之间串数据？改一版。
2. `super()` 在 `D.ping` 里找到的下一个类一定是 `B` 吗？

参考答案：

1. `items` 在类上，所有实例找到的是同一个列表。改成 `__init__` 里 `self.items = []`。
2. 对 `D` 的 MRO 来说，`D` 的下一个是 `B`。如果从 `B.ping` 里调用 `super()`，下一个是 `C` 而不是 `A`。所以 `super` 依赖的是实例的整条 MRO，不是写死的父类。

## 面试

### Q1. `__new__` 和 `__init__` 谁先执行？

**考点**：对象生命周期。

**回答**：

1. `__new__` 负责创建对象，通常返回该类的实例。
2. 返回的是该类实例时，解释器再调用 `__init__`。
3. `__init__` 返回非 `None` 会 `TypeError`。不可变类型要在 `__new__` 里把值定下来，因为创建之后不能改。

### Q2. `super()` 找的是父类吗？

**考点**：C3 MRO。

**回答**：

1. 不是字面上的“第一个基类”。它从当前类在 MRO 中的下一个继续找。
2. 合作式继承里每一层都要 `super()`，菱形继承才不会重复或漏掉。
3. 直接写 `Parent.method(self)` 会绕过 MRO。只有你明确不要合作式调用时才这么写。

### Q3. 类属性和实例属性怎么选？

**考点**：共享可变状态。

**回答**：

1. 常量、方法、所有实例相同的不可变配置放类上。
2. 会变的每实例数据放 `__init__`。
3. 实例 `__dict__` 里的同名属性会遮住类属性。读和写不是对称的：`self.x = 1` 写的是实例，即使 `x` 原来在类上。

## 常见错误

- 覆盖方法时改了参数意义，调用方仍然按基类的约定调用。
- 在 `__init__` 里忘记调用 `super().__init__()`。子类和父类都要初始化时，用 `super()`，不要点名父类，否则多继承又会漏。
- 用类属性当默认可变容器：`class Bag: items = []`。所有没在实例上覆盖 `items` 的实例共享这个列表。可变默认状态放在 `__init__` 里，每个实例新建一个。

## 练习

1. 画 `D` 的 MRO，不看示例输出，再对照 `D.__mro__`。
2. 如果 `C.ping` 不调用 `super()`，直接返回 `"C"`，`D().ping()` 变成什么？
3. 为什么示例的 `Animal` 不需要 `__init__`？

参考答案：

1. `D, B, C, A, object`。
2. `"DBC"`。`B` 的 `super()` 仍然会找到 `C`，但 `C` 不再把查找继续到 `A`。
3. 它没有每个实例都要保存的状态。`object` 的初始化够用。

## 小结

类体执行一次，用来制造类对象。实例方法通过绑定把实例放进 `self`。多继承的下一站由 MRO 决定，`super()` 按这个顺序走。能用函数或组合解决的，不必做类层次。
