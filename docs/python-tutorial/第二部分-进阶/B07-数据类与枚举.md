# B07　dataclass 与枚举

> 示例：`examples/part_b/b07_dataclass_enum.py`

## 学完你能做什么

用 dataclass 表达一条记录，知道它什么时候能当字典键；用 `Enum` 表达一组固定取值，而不是散落的字符串。

## dataclass 生成什么

`@dataclass` 根据注解生成 `__init__`、`__repr__` 和 `__eq__`。你仍然可以自己写方法。它不是另一个类型系统，生成的是普通的类。

```python
@dataclass(frozen=True, slots=True)
class Point:
    x: int
    y: int
```

`frozen=True` 时，生成的类拒绝给字段赋值，并且因为相等性已经按字段定义、对象又不能改，dataclass 会生成 `__hash__`。示例里两个 `Point(1, 2)` 的哈希相同。

`slots=True` 让实例不再带 `__dict__`，属性写在固定的槽里，省内存，也防止随便挂新属性。`hasattr(Point(1, 2), "__dict__")` 为假。继承时，如果基类没有 `__slots__`，子类就算写了 `slots=True` 也仍然会从基类那里得到实例字典。要么整条链都规划槽，要么不要为了省那点内存去开槽。

## 默认可变字段

`items: list[str] = []` 这个写法 dataclass 会直接拒绝，因为那和函数的可变默认参数是同一个坑。正确写法是：

```python
items: list[str] = field(default_factory=list)
```

每个实例调用一次工厂，得到自己的列表。示例里往 `first.items` 追加，`second.items` 仍是空的。

## 比较了就会失去默认哈希

`@dataclass(eq=True)` 是默认行为。类可以变（没有 `frozen`）时，dataclass 把 `__hash__` 设为 `None`，实例不可哈希。示例对 `MutablePoint` 调用 `hash` 会得到 `TypeError`。

这是对的。可变且按内容比较的对象，放进集合之后再改字段，集合就坏了。如果你确定字段在当键期间不会变，可以 `unsafe_hash=True`，名字里的 unsafe 是认真的。多数业务对象不需要哈希，让它不可哈希即可。

`eq=False` 时不会生成相等方法，哈希保持对象默认的按身份哈希。很少需要这个组合。

## 枚举成员是单例

```python
class Color(Enum):
    RED = auto()
    BLUE = auto()
    CRIMSON = RED
```

`Color.RED is Color.CRIMSON`。相同的值做成了别名，不是第二个成员。遍历枚举时别名不会再出现一次。比较用 `is` 或 `==` 都可以，因为成员的相等就是身份。不要拿成员去和 `auto()` 背后的整数比，那些整数是实现分配的，不是你的 API。

需要和字符串配置文件互通时，用 `enum.StrEnum`（3.11 起）或者显式写出字符串值，并在边界上做一次转换。不要让 `"red"` 和 `Color.RED` 在整个程序里混用。边界上转一次，内部只用枚举。

`IntEnum` 的成员同时是整数，能参加算术。这很方便，也很容易把枚举漏回裸整数的世界。没有算术需求就用普通 `Enum`。

## 机制

`@dataclass` 根据类注解生成 `__init__`、`__repr__`、`__eq__` 等。它不是“更强的字典”，而是少写样板的类。字段顺序就是参数顺序。有默认值的字段必须排在没有默认值的后面，和函数参数一样。

可变默认值用 `field(default_factory=list)`。写 `items: list = []` 会被 dataclass 拒绝或造成共享，正确是工厂。每个实例调用一次工厂。

`frozen=True` 使赋值抛 `FrozenInstanceError`，并在字段可哈希时生成 `__hash__`。没有 `frozen` 但生成了 `__eq__` 的 dataclass 默认不可哈希。这是安全的默认：可变对象不该进集合。

`slots=True` 不再使用实例 `__dict__`，属性写错名字会立刻失败，实例更省内存。和冻结一起用时，对象可以既不可变又可哈希。`slots` 不表示线程安全。

`order=True` 会生成比较方法，按字段顺序做词典序。字段类型没有顺序时不要开。

枚举成员是单例。`Color.RED is Color.RED`，身份比较有意义。值可以相同仅当 `enum.auto` 或你明确使用允许别名的定义。函数式 API 和类语法都能建枚举。需要纯整数位标记用 `IntFlag`。普通 `Enum` 不是 `int`，不能拿去当数字加，除非用 `IntEnum`。`IntEnum` 因为是 `int` 的子类，会和整数相等，容易让非法整数混进来。新代码更常用 `Enum` 加显式值，比较成员而不是比较裸整数。

## 会出事的写法

- `tags: list[str] = []` 当字段默认值。所有实例共享。
- 可变 dataclass 当字典键。定义后一旦改字段，查找失败。
- 用枚举的值做持久化，又随意改成员的值。存库的是值，改值等于改了历史数据的含义。可以改成员名字，迁移值要单独做。
- `IntEnum` 和任意整数比较通过了校验。边界上仍要检查它是不是成员：`Color(n)` 会在非法值时抛 `ValueError`。

## 示例对照

`examples/part_b/b07_dataclass_enum.py` 应断言工厂每次给出新列表、冻结对象不能赋值、未冻结且有 `__eq__` 的对象不能哈希，以及枚举成员身份。这些断言就是契约，不要在业务里再“灵活”地破坏。

## 加练

1. 写一个冻结 dataclass `Money(currency: str, cents: int)`，使它能放进集合。
2. 为什么持久化枚举时要写迁移，而不是依赖成员定义顺序？

参考答案：

1. `@dataclass(frozen=True)`，两个 `str`/`int` 字段都可哈希，生成的 `__hash__` 可用。`cents` 不要用 `float`。
2. 成员顺序和 `auto()` 的编号都可能因插入新成员而变。数据库里应存稳定的值，并在代码里保留旧值的解释。

## 面试

### Q1. dataclass 生成了什么，没有生成什么？

**考点**：不要把它当成校验框架。

**回答**：

1. 默认生成初始化、表示和相等。可选冻结、顺序、slots、哈希。
2. 不生成运行时的范围校验。分数仍可以是 `-1`，除非你在 `__post_init__` 里拒绝。
3. 注解仍然是注解。外部 JSON 不会自动变成 dataclass。

### Q2. 为什么有 `__eq__` 就默认不能哈希？

**考点**：可变性和哈希契约。

**回答**：

1. 相等如果看字段，字段又能改，哈希就会变，集合立刻失效。
2. dataclass 因此不给可变实例提供 `__hash__`。
3. `frozen=True` 且字段可哈希时才恢复哈希。这是选择，不是装饰器的副作用可以忽略。

### Q3. 枚举为什么用身份比较？

**考点**：成员单例。

**回答**：

1. 成员在枚举类上创建一次，进程内是单例。
2. `is` 可以用于成员。值的相等不一定唯一，别名会让两个名字共享一个成员。
3. 不要用 `Enum` 成员去代替未校验的整数。从外部构造用 `Color(value)`，捕获 `ValueError`。

## 常见错误

- 给 dataclass 一个列表默认值，然后不理解为什么装饰器报错。用 `default_factory`。
- 把 `frozen` 理解成深冻结。字段本身如果是列表，列表里面仍能改。`frozen` 只是不许给字段重新赋值。
- 用 `Color.RED == 1` 判断颜色。把枚举当整数用，调用方就再也不会改成更合适的取值方式。

## 练习

1. 写一个冻结的 `Money(amount: Decimal, currency: str)`。金额用字符串构造 `Decimal`。
2. 两个空的 `Bag` 互不影响，靠的是哪一个参数？
3. `CRIMSON` 为什么不增加第三种颜色？

参考答案：

1. `@dataclass(frozen=True)`，字段类型分别是 `Decimal` 和 `str`。构造时写 `Decimal("1.20")`。
2. `field(default_factory=list)`。每个实例拿到新列表。
3. 它的值写成了 `RED`，枚举把它收成 `RED` 的别名，`is` 为真。

## 小结

dataclass 适合字段清楚的记录。可变且按字段比较的实例默认不能哈希；冻结之后可以。列表字段用工厂函数。枚举成员是单例，别名不会变成新成员。内部状态用枚举，字符串留在边界。
