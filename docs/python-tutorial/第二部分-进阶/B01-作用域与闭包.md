# B01　参数、作用域与闭包

> 示例：`examples/part_b/b01_scopes.py`。可执行示例仍是 CPython 3.12。

## 学完你能做什么

读懂一个名字在函数里指的是谁，写出不会在调用之间串数据的默认参数，以及不会把循环变量漏给所有闭包的 lambda。

## LEGB

解析一个名字时，Python 按这个顺序找：

1. **L**ocal：当前函数的局部变量。
2. **E**nclosing：外层函数的局部变量，给闭包用。
3. **G**lobal：模块全局。
4. **B**uiltin：`len`、`print` 这些内置名字。

赋值默认把名字变成局部变量。函数里只要出现 `count = ...`，`count` 在整个函数里都是局部的，包括这一行之前的读取。那种“先读全局再赋值”会得到 `UnboundLocalError`，不是“前半段用全局”。

要在函数里给全局名字重新绑定，必须写 `global name`。要给外层函数的名字重新绑定，必须写 `nonlocal name`。只是读取外层变量时，两个声明都不要写。

`global` 和 `nonlocal` 都是重新绑定的开关，不是“把对象引进来”的开关。你很少需要 `global`。需要在闭包里累加计数时，`nonlocal` 是对的工具。

## 默认值只算一次

```python
def bad_append(item, bucket=[]):
    bucket.append(item)
    return bucket
```

`[]` 在定义函数时创建。之后每次省略 `bucket`，用的都是同一个列表。示例里连续两次调用会得到 `[1]` 然后 `[1, 2]`。这不是实现事故，语言就是这样规定的。

可变对象不要放在默认值里。用 `None` 当“调用方没传”的标记，在函数体内再创建新列表：

```python
def append_item(item: int, bucket: list[int] | None = None) -> list[int]:
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

如果 `None` 本身是合法业务值，就用一个模块级的哨兵对象：`MISSING = object()`，再用 `is` 判断。3.15 才有内置的 `sentinel` 类型，3.12 用 `object()` 即可。不要用某个“看起来不会出现的字符串”当哨兵。

## 闭包抓住的是名字

`make_multiplier` 返回的内部函数记住外层的 `factor`。这是你想要的闭包。

循环里写 `lambda: number` 时，每个 lambda 记住的是 **同一个** `number`。循环结束后它是最后一次的值，于是三个函数都返回 `2`。修法是在定义时把当前值绑进默认参数，默认参数在那时求值：

```python
funcs.append(lambda number=number: number)
```

示例把两种形态都跑了。默认参数这一写法是惯用法，不是技巧比赛。函数更长时，直接写 `def read(number=number)`，别挤在一行 lambda 里。

## `/` 和 `*`

3.8 起，参数列表里的 `/` 左边只能按位置传递，`*` 右边只能按关键字传递。

```python
def add(left: int, right: int, /) -> int:
    return left + right

def greet(*, name: str) -> str:
    return name
```

`add(left=1, right=2)` 抛 `TypeError`。这样可以保留以后改参数名的自由，调用方没有写成关键字。`greet` 强制写出 `name=`，调用点更不容易把参数传错位置。标准库里 `range`、`len` 很多参数都是位置仅限的，所以你不能写 `len(obj=items)`。

完整的合法顺序是：位置仅限参数、普通参数、`*args`、仅限关键字参数、`**kwargs`。入门阶段先把 `/` 和 `*` 的分界看懂，不必每次都写全。

## 机制

名字查找按 LEGB：局部、外层函数、全局、内建。赋值目标默认是局部。函数里给一个名字赋值，这个名字在整个函数里都算局部，哪怕赋值写在后面。于是在赋值之前读取它，是 `UnboundLocalError`，不是去外层找。

要改外层函数的名字，用 `nonlocal`。要改模块全局，用 `global`。两者都是声明“赋值不要变成新的局部”。读不需要声明。类体不是函数作用域，推导式在 3.12 里有自己的局部作用域，和旁边的函数局部不是一回事。B02 会见到循环变量和推导式的差别。

闭包保存的是外层名字的绑定，不是定义那一瞬间的值。`make_multiplier` 返回的函数以后仍去读 `factor`。这是对的，因为 `factor` 在外层函数返回后仍然被闭包引用着。循环里不带默认参数的 `lambda: number` 是错的用法：所有 lambda 都读循环结束后的那一个 `number`。示例里 `broken_late_binding()` 因此得到 `[2, 2, 2]`。修法是默认参数 `lambda number=number: number`，默认值在每次循环的 `def`/`lambda` 创建时求值，于是把当时的值抄进函数对象。

`/` 和 `*` 是签名语法。`add(left, right, /)` 不能用关键字调用，示例断言 `TypeError`。`greet(*, name)` 必须写出 `name=`。

## 会出事的写法

- 在循环里创建回调，回调里直接读循环变量。界面、服务器注册路由时都会中招。
- `global` 用来在函数之间共享可变状态。那是模块级对象或实例属性的工作。`global` 让测试无法隔离。
- 闭包里做 `factor += 1` 却忘了 `nonlocal`。这会变成 `UnboundLocalError`。
- 用可变默认参数模拟闭包里的缓存。默认列表是函数属性级别的共享，和调用者是否相同无关。

## 示例对照

`examples/part_b/b01_scopes.py` 的断言顺序就是机制本身：

- `make_multiplier(3)(4) == 12`：闭包读到了外层的 `factor`。
- `append_item` 两次不传列表，得到两个互不干扰的 `[1]` 和 `[2]`。传入同一个 `shared` 才会累积。
- `bad_append` 是反例：第二次调用得到 `[1, 2]`。
- `late_binding()` 用默认参数得到 `[0, 1, 2]`。`broken_late_binding()` 的泄漏版本得到 `[2, 2, 2]`。
- `add(left=1, right=2)` 失败。`greet(name="Ada")` 成功。

## 加练

1. 改 `broken_late_binding` 的泄漏部分，让它返回 `[0, 1, 2]`，不许改循环范围。
2. 函数里写 `count = count + 1`，外层有 `count`，会发生什么？怎样才真的改外层？

参考答案：

1. `leaked.append(lambda number=number: number)`。默认值在创建 lambda 时绑定当前整数。
2. `UnboundLocalError`，因为函数里有赋值，`count` 被当成局部，右边读取时还没有绑定。要改外层函数的 `count` 用 `nonlocal`。要改模块全局用 `global`。

## 面试

### Q1. 闭包里的循环变量为什么都一样？

**考点**：名字绑定和默认参数求值时机。

**回答**：

1. 闭包持有的是名字，查找发生在调用时。循环结束后名字留在最后一个值。
2. 默认参数在定义时求值，可以在那一刻把值冻结进函数对象。
3. 另一种写法是工厂函数 `def make(n): return lambda: n`。每次调用 `make` 有自己的局部 `n`。

### Q2. LEGB 和 `UnboundLocalError` 是什么关系？

**考点**：编译期就决定了名字是不是局部。

**回答**：

1. 函数体里只要有对名字的赋值，这个名字就是局部，包括赋值在读取之后的写法。
2. 读取发生在赋值之前，局部还没有绑定，于是 `UnboundLocalError`，不会继续往外找。
3. `global` 和 `nonlocal` 改变的是“赋值写到哪一层”。它们不改变对象的可变性。

### Q3. 仅位置和仅关键字解决什么生产问题？

**考点**：API 稳定性。

**回答**：

1. 仅位置允许以后改参数名而不破坏调用方。
2. 仅关键字强迫调用点写出 `flag=`，避免一串布尔值。
3. 违反约定是 `TypeError`，在调用时就失败，不会悄悄把关键字收进 `**kwargs`。

## 常见错误

- 用可变默认值缓存结果，还觉得这是巧妙的记忆化。那是共享状态。记忆化用 `functools.cache`，见 B11。
- 在闭包里对循环变量只读，然后对结果感到惊讶。
- 给只需要读取的外层变量加 `nonlocal`。没有重新赋值就不需要它。

## 练习

1. 写 `make_adder(n)`，返回一个函数，把参数加上 `n`。
2. 解释为什么 `def f(x, items=[])` 在静态检查里会被标出来。示例对这一行使用了明确的忽略标记，只为了把坑跑给你看。
3. `def scale(value, /, *, factor)` 可以怎样调用，不可以怎样调用？

参考答案：

1. 内部函数 `return value + n`，返回这个内部函数。
2. 默认列表在定义时只创建一次，调用之间会共享。检查器在阻止这个坑。
3. `scale(3, factor=2)` 可以。`scale(value=3, factor=2)` 不行，因为 `value` 在 `/` 左边。`scale(3, 2)` 也不行，因为 `factor` 在 `*` 右边。

## 小结

名字按 LEGB 解析。默认值求值一次，所以列表不要做默认值。闭包绑定的是变量，循环里要用默认参数抓住当前值。`/` 和 `*` 把参数分成只能按位置、可混合、只能按关键字三段。
