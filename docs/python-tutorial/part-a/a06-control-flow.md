# A06　控制流

> 示例：`examples/part_a/a06_control_flow.py`

## 学完你能做什么

用条件、循环和 `else` 子句表达清楚的控制流，知道 `break` 和 `return` 分别会跳过谁。

## 条件

```python
if n < 0:
    return "neg"
if n == 0:
    return "zero"
return "pos"
```

每个分支的条件按顺序判断，命中一个就离开函数。`elif` 和这种提前返回是同一类结构，函数很短时提前返回往往更平。不要写永远到不了的分支。

Python 没有 `switch` 语句的老语法。3.10 起的 `match` 是结构模式匹配，能做的事比“按整数跳转”多，也比“按整数跳转”容易用错。它放在 [B10](../part-b/b10-pattern-matching.md)，不要在入门阶段拿它替换每一个 `if`。

## 循环

`while` 在条件为真时重复。条件里的名字要在循环内更新，否则就是死循环。`for` 遍历可迭代对象，不是 C 语言那种“从 0 数到 n”专用的计数器。数次数用 `for i in range(n)`，`range` 不先造出一个装满整数的列表。

`break` 离开这一层循环。`continue` 进入下一次迭代。两者都只作用于最内层循环。

## 循环的 `else`

`for` 和 `while` 可以带 `else`。这个 `else` 在循环 **没有被 `break`** 时执行。它不表示“循环了零次”，也不表示“最后一项”。

```python
for item in values:
    if item < 0:
        break
else:
    return "all-non-negative"
return "found-negative"
```

如果所有元素都非负，循环正常结束，走进 `else`。如果碰到负数并 `break`，`else` 被跳过。很多人不读这个分支，所以真要用它，函数应当很短，并且名字能表达“没被打断”。觉得读者会误会时，改用一个布尔标志，那也很清楚。

## `try` 的 `else`

`try` 里没有异常时执行 `else`，有匹配的异常时走 `except`。把“只有成功后才做”的代码放进 `else`，可以避免 `except` 意外抓住 `else` 里新抛出的异常。完整的异常模型在 A10。

## 不要用异常当普通分支的唯一理由

“文件不存在就创建”这种事，用 `pathlib` 的方法或明确的条件往往更直接。另一方面，把外部输入转成整数时，`try` / `except ValueError` 比先用正则过滤更符合 Python 的习惯：先做，出错再处理。这个习惯叫 EAFP（请求原谅比请求许可容易）。两种风格都能写对，关键是错误类型要具体，见 A10。

## 常见错误

- 在 `for` 循环里修改正在遍历的列表长度，跳过或重复元素。需要修改时遍历副本，或另外收集结果。
- 认为循环 `else` 是“空序列时执行”。空序列确实没有 `break`，所以会执行 `else`；非空但从未 `break` 时也会执行。
- 用多层嵌套 `if` 复制同一段善后逻辑。善后更适合 `finally` 或 `with`，后面两章会讲。

## 练习

1. 写一个循环，求 `1` 到 `n` 里所有奇数的和。`n = 5` 时结果是 `9`。
2. 解释示例里 `while` 累加时为什么结果是 `4` 而不是 `6`。
3. 什么情况下循环 `else` 不会执行？

参考答案：

1. `total = sum(i for i in range(1, n + 1) if i % 2)`，或者普通 `for` 加判断。`n = 5` 时奇数是 1、3、5。
2. `n == 2` 时 `continue` 跳过了 `total += n`，所以只加了 1 和 3。
3. 循环被 `break` 离开时。`return` 会直接离开函数，`else` 同样不会执行。

## 小结

条件按顺序匹配，`for` 遍历可迭代对象。循环的 `else` 表示“没有 break”。成功后的代码可以放在 `try` 的 `else` 里。模式匹配先留到 B10。
