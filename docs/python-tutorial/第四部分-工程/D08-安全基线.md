# D08　安全基线

> 示例：`examples/part_d/d08_security.py`

## 学完你能做什么

在应用代码里守住四条基线：路径不出根目录、摘要用恒定时间比较、令牌用 `secrets` 生成、SQL 参数化。不在这里讨论攻击步骤。

## 路径

`safe_join` 拒绝绝对路径，拒绝任何 `..` 片段，再 `resolve` 之后确认结果仍在根目录之下。示例在临时目录里接受 `notes/a.txt`，拒绝 `../secret`。

`resolve` 会解析符号链接。只检查字符串里有没有 `..` 是不够的，链接可以把一个看起来合法的名字指到根外面。所以既拒绝 `..`，也检查解析后的父目录。根目录自己作为结果是否允许，由你的规格决定。示例允许“文件在根之下”，不把根目录本身当成文件路径。

不要用请求里的路径直接 `open`。文件名来自用户时，先经过这样的函数，再打开。

## 比较和令牌

`secrets.token_bytes` 适合做密钥材料。`random` 不适合。示例用它生成 HMAC 的键，对消息做 SHA-256，再用 `hmac.compare_digest` 比较十六进制摘要。相等的消息通过，差一个字节的消息不通过。

`==` 比较字符串时可能在第一个不同字符处返回，时间差可以被用来猜内容。`compare_digest` 用来比较长度已知、内容敏感的摘要和令牌。长度不同时它仍然会告诉你不相等，所以不要假设它能隐藏长度。令牌应当固定格式。

HMAC 的键是秘密，消息摘要可以公开。不要自己把密钥和消息拼接后做一次哈希就当成 MAC，拼接方式有经典的设计错误。用 `hmac`。

## SQL

D06 已经用占位符把数据传给 SQLite。这条基线在这里重复一次，是因为它是安全要求，不只是数据库风格：语句结构来自你的代码，值来自参数。动态列名走白名单。

## 不要做的反序列化

`pickle` 能重建对象图，包括在反序列化过程中调用对象。不可信的字节不能交给 `pickle.loads`。配置用 JSON 或 TOML，任务参数用你自己解析的字段。需要交换数据时用明确的模式，而不是 Python 对象图。示例甚至不去调用 `pickle`，避免把“能跑起来的 loads”留在教学脚本里。记住这条禁令即可。

`eval` 和 `exec` 执行字符串。它们不是配置语言。用户输入、缓存内容、数据库里的文本，都不要送进去。

## 日志和错误

D04 不记录令牌。错误响应不包含回溯和内部路径。路径拒绝时给客户端的是“文件名不合法”，日志里可以记拒绝这件事，不必把拼接后的绝对路径回显给调用方。

## 机制

这一章是基线，不是渗透清单。每条都对应一个已经能在示例里跑的拒绝方式。

路径：根目录 `resolve` 之后，用户路径拼接再 `resolve`，用 `relative_to` 确认仍在根内。失败就拒绝。不要字符串替换 `..`。符号链接会被 `resolve` 解开。

比较令牌用 `hmac.compare_digest`。普通 `==` 在发现第一个不同字符时返回，时间差可以被用来猜。`compare_digest` 要求长度处理得当，类型是字符串或字节，两边要先确认类型再比。

SQL 用参数化，见 D06。即使用户字符串像语句，也只是一格数据。

反序列化：不可信字节不能 `pickle.loads`。pickle 可以在还原时调用任意可调用对象，等于远程代码执行。示例不演示 `loads`。进程内的可信对象要用别的格式跨边界：JSON 加上 D03 的解析。需要签名的令牌用标准格式并验证签名，不要自己拼 `base64` 就相信内容。

日志和错误：异常细节留在日志，响应里给错误码。不要把密钥写进查询字符串，那会进访问日志。

调试端点、目录列出、交互式控制台不能出现在生产配置里。默认关闭。

依赖有已知漏洞时要升级。锁文件让你知道自己装了什么。这是流程，不是一个函数能完成的。

## 会出事的写法

- `os.path.join(root, user)` 就打开文件。`join` 在用户传入绝对路径时会丢掉根。
- 手写逐字符比较口令。
- 为了缓存方便 `pickle` 用户上传的内容。
- 在错误响应里返回文件路径和 SQL。

## 加练

1. 用户传入 `/etc/passwd` 或 `../secret` 时，检查函数应在哪一步失败？
2. 为什么 `compare_digest("ab", "a")` 之前最好先判断类型和用途，而不是拿它比较任意对象？

参考答案：

1. `resolve` 之后 `relative_to(root)` 抛 `ValueError`，函数把它变成拒绝。不要打开文件之后再看路径。
2. 它防止的是比较过程的提前返回。调用方仍要保证两边是预期的 `str` 或 `bytes`。业务上还要防止把用户名和口令哈希用同一种方式乱比。口令存储用专门的口令哈希，不是一次 `compare_digest` 能替代的。

## 面试

### Q1. 路径穿越怎么防？

**考点**：规范化之后的包含关系。

**回答**：

1. 根和候选路径都 `resolve`。
2. 用 `relative_to` 确认候选仍在根下。
3. 失败是 400 或 404，按合同选定，不要把异常文本回给用户。不要用替换 `..` 代替规范化。

### Q2. 为什么不可信数据不能 `pickle.loads`？

**考点**：反序列化即代码执行。

**回答**：

1. pickle 的还原过程可以调用任意对象。
2. 攻击者构造的字节不是“数据”，是程序。
3. 跨信任边界用 JSON 或另有签名的格式，再做模式校验。进程内部的 pickle 也要能说清字节从哪来。

### Q3. 参数化之后就没有注入了吗？

**考点**：动态标识符。

**回答**：

1. 值可以被参数化，注入的主要路径被堵住。
2. 表名、列名、排序方向不能当值绑定。它们必须来自白名单。
3. 二次注入仍然可能：你把存进去的数据又拼进另一条 SQL。每条语句都参数化。

## 常见错误

- 只过滤 `../` 这四个字符，放过编码后的变体或符号链接。解析后再检查根。
- 用 `random.choice` 生成重置链接。
- 把密钥提交进仓库。密钥放在环境或密钥管理里，仓库里只有读取它的代码。

## 练习

1. `notes/a.txt` 为什么可以通过？
2. `compare_digest` 比较的两份摘要，示例怎样让其中一份失败？
3. 为什么教程不用 pickle 演示“危险的字节长什么样”？

参考答案：

1. 它不是绝对路径，片段里没有 `..`，解析后的路径仍在临时根目录之下。
2. 同一函数、同一把键，消息从 `body` 改成 `bode`，摘要不相等。
3. 教学脚本不需要一份可执行的不可信反序列化入口。禁令是：不要对不可信字节调用 `loads`。

## 小结

路径解析后必须仍在根内。令牌来自 `secrets`，摘要用 `compare_digest` 和 `hmac`。SQL 用参数。不可信数据不进 `pickle`、`eval` 和 `exec`。
