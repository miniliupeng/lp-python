# D10　四个设计案例

> 示例：`examples/part_d/d10_system_design.py`。示例实现的是可以单测的核心，不是分布式系统的全部。

## 学完你能做什么

把短链、限流、缓存和任务队列讲成有不变量的小设计，并指出 Python 进程在其中的位置。

## 短链

内部用整数编号，外部用更短的字母表编码。示例的字母表是 36 个字符，`encode` / `decode` 互逆，0 编码成 `"0"`。负数拒绝。这不是安全措施，编码结果可以被枚举。短链如果指向私密地址，权限仍要在打开时检查，不能靠“别人猜不到编号”。

真正的服务还要有：编号生成（数据库序列或发号器，避免多进程冲突）、编号到原始 URL 的存储、原始 URL 的校验（只允许预期的方案，拒绝内部地址，如果你的产品有这个要求）。校验是业务规则，要单独写，不放进进制转换里。

冲突策略要选一种。数据库唯一约束是最后一道：插入冲突就换号或返回错误。先查再插，中间仍可能有别人插入。唯一约束不会有这个空窗。

## 限流

`TokenBucket` 有容量和恢复速率。`allow(now)` 先按流逝时间补令牌，上限是容量，再尝试扣 1 枚。示例在时刻 0 连续通过两次、第三次失败；时刻 1 恢复一枚，又可以通过。时间由参数传入，所以测试不必睡眠。

令牌桶允许短时间的突发到容量为止。漏桶更强调匀速流出。固定窗口计数实现简单，窗口交界处可能放进将近两倍的流量。讲设计时要说出自己选的是哪一种，以及状态存在哪。

状态放在进程内存里，只对这个进程有效。多进程或多机器时，每台机器各限一遍，总限额是机器数乘以单机限额，除非把计数放到共享存储。共享存储的每次请求都要原子更新，否则限流自己就有竞态。

拒绝时返回明确的 429，并考虑 `Retry-After`。不要让客户端无间隔重试，D07 说过原因。

## 缓存

示例的 `LRU` 用 `OrderedDict`。`get` 把命中的键移到末尾，`put` 超出容量时从开头丢掉。容量是 2 时，写入 `a`、`b`，访问 `a`，再写入 `c`，被丢掉的是 `b`。这就是“最久未使用”。

缓存是加速，不是事实来源。事实在数据库。缓存里的值会旧。要规定失效：写成功后删除对应键，或给记录一个版本。只靠 TTL 时，要接受 TTL 内读到旧值，并把这个延迟写进设计。

三个常见故障要分清：

- **穿透**：查询的键永远不存在，请求一次次打到数据库。可以缓存“不存在”，并给这个否定结果较短的 TTL。
- **击穿**：一个很热的键刚好过期，大量请求同时去填它。单进程里用锁或“正在填充”的标志；多进程要有共享的互斥或请求合并。
- **雪崩**：很多键同时过期，或缓存进程重启后全空。TTL 加抖动，避免同一秒集体过期；重启时要能承受打到数据库上的流量，而不是假设缓存永远热。

示例没有 TTL，也没有负缓存。它把淘汰策略测清楚。加上 TTL 时，时钟仍然要注入，不要在测试里睡眠。

## 任务队列

生产者把任务放进有界队列，工作者取走执行。D07 已经有线程版。设计上补这几句：

- 任务内容是数据，不是代码字符串。工作者根据类型字段调用本地函数。
- 至少一次投递时，任务必须幂等。至多一次则可能丢。选一种，不要承诺“恰好一次”却没有去重存储。
- 失败进入有次数上限的重试，超过后进入死信，让人能看见。不要失败了只记一条日志就消失。
- 工作者的数量按任务是 I/O 还是 CPU 来定。CPU 密集在默认 GIL 下用进程工作者。队列本身可以仍在外部系统里，不在某个 Python 列表里。

## Python 进程放在哪

无状态的 API 进程可以水平扩展。有状态的限流和缓存如果只在内存里，扩容不会共享状态。数据库是共享的事实来源，连接池要有上限。CPU 密集的任务不要和延迟敏感的请求抢同一个默认构建里的 GIL，拆到单独的工作者进程。

这些选择比具体的云厂商名词稳定。面试里先画数据谁是主人、请求失败时用户看到什么、状态在不在进程内，再谈组件名字。

## 机制

四个案例共用一张问法：数据的主人是谁，合同是什么，失败时用户看到什么，Python 进程具体跑哪一段。

短链。键是短码，值是目标 URL。生成短码时避免可猜测的计数器，除非内部使用。重定向是 302 或 301，按是否永久写进合同。解析目标 URL 时只允许 http 和 https，拒绝 `javascript:` 和文件路径。热点短码可以缓存，缓存失效时回源数据库。统计点击是附加写入，不能让统计失败导致重定向失败。

限流。固定窗口实现简单，窗口边界会放进两倍流量。令牌桶允许突发，补充速率是平均速率。限流器的状态如果在进程内存里，多副本各自计数，限制会被乘以副本数。要全局限制就把计数放进共享存储，并接受存储失败时的策略：失败开放会放过流量，失败关闭会把存储故障变成全站拒绝。策略写进合同。

缓存。缓存是加速，不是事实来源。先写数据库再删缓存，或用明确的失效。读到旧值时用户应当看到“可能稍旧”，而不是把旧余额当成可花费的钱。余额这种强一致数据不要用“先改缓存再异步写库”。LRU 只解决进程内的容量。`functools.lru_cache` 没有跨进程失效。键要包含影响结果的全部参数。

任务队列。入队和业务写入放在同一个事务里，或者用外盒表：先在数据库插入“待发送”，提交后再投递，投递成功再标记。进程在中间崩溃，恢复程序会重新投递。所以消费者必须幂等。可见性超时要大于处理时间，否则两个工人会同时做同一件。失败进死信队列，而不是无限重试。

Python 进程放在哪：请求处理、校验、编排。重 CPU 放进程池或单独的工作者。不要在 Web 进程里跑无限循环还不让出事件循环。

再往前一步，是 2026 年常见的模型应用形态。它们仍是上面的合同，不是新的内存模型。

检索增强。把文档切成块，每块做向量，查询时把问题也变成向量，取最相近的若干块，再交给模型。向量相近不是事实正确。块切在句子中间会让两边都失去主语。回答里要能回到块的来源。没有命中时应该说没有证据，而不是补一段。嵌入模型和生成模型是两个组件，版本要固定在配置里，否则同一句话的向量空间会变，旧索引失效。

工具调用。模型产出的是“调用哪个工具、参数是什么”的结构化数据，不是直接改你的数据库。宿主校验参数、执行、再把结果送回去。工具名单是白名单。模型文本里出现的 SQL 不能直接执行。

MCP。它是宿主和工具服务器之间的协议，用 JSON-RPC 发现工具、资源和提示并调用它们。价值是换模型宿主时不必为每个工具重写一种私有插件格式。风险和任何插件系统一样：服务器返回的内容是不可信输入，参数仍要按 D03 校验，权限仍要按用户而不是按模型。

流式输出。服务端用 SSE：`Content-Type: text/event-stream`，事件之间空行分隔，`data:` 放载荷。客户端断开时，生产者必须停止，否则模型费用和队列会继续涨。流式不是事务。写库的结果要在流开始前提交，或者明确告诉用户“尚未保存”。不要在每个 token 上提交一次事务。

## 会出事的写法

- 短链允许任意 scheme。重定向变成开放跳转。
- 限流状态只放内存，扩容后限制失效，还以为算法错了。
- 缓存失败就 500。缓存挂了整站挂。读路径应回源。
- 队列工人不幂等。可见性超时一到就双写。
- 把模型的工具参数直接拼进 SQL 或 shell。

## 示例对照

`examples/part_d/d10_system_design.py` 用内存结构实现短码、令牌桶或固定窗口、LRU、以及至少一次投递的幂等消费。断言：未知短码失败、超限被拒绝、LRU 容量不超过上限、同一任务投递两次只生效一次。它不连接外网，也不加载模型。模型相关的合同写在上面，不假装本地跑了一个向量库。

## 加练

1. 令牌桶和固定窗口各选一个场景。
2. 客户端在 SSE 中途断开，服务端最少要停掉什么？

参考答案：

1. 登录失败次数用固定窗口或更严格的锁定。允许用户短时翻页、平均速率有限，用令牌桶。
2. 停掉这次生成和对应的计费。不要继续往已断开的套接字写。不要留下一个无人等待的任务还占着模型并发额度。

## 面试

### Q1. 设计短链，你先说哪几句？

**考点**：合同和安全，而不是先说哈希算法。

**回答**：

1. 短码到 URL 的映射，重定向状态码，未命中是 404。
2. 只允许 http/https，拒绝开放跳转。
3. 存储是事实来源，缓存是加速。点击统计失败不影响跳转。生成短码要考虑冲突和可猜测性。

### Q2. 缓存和数据库不一致时，用户该看到什么？

**考点**：哪一类数据允许旧。

**回答**：

1. 允许稍旧的读模型要写明最大延迟。
2. 余额、库存、权限不允许用“先改缓存”。
3. 失效策略和回源策略一起说。缓存挂了要能回源，而不是全站 500。

### Q3. 工具调用和 MCP 的安全边界在哪？

**考点**：模型不是权限系统。

**回答**：

1. 模型只提议调用。宿主按白名单校验参数并执行。
2. MCP 统一了发现和调用的形状，不代替认证。工具服务器的返回值仍是不可信输入。
3. 写操作要有幂等键和用户权限。不要执行模型给出的原始 SQL 或 shell。

## 练习

1. `encode(36)` 再 `decode`，结果是多少？字母表长度是 36，所以 36 应当是 `"10"`。
2. 令牌桶容量 2、速率 1，在时刻 0 用掉 2 枚之后，时刻 0.5 能通过吗？
3. LRU 容量为 1 时，依次 `put("a")`、`put("b")`，`get("a")` 是什么？

参考答案：

1. `36`。`"10"` 在 36 进制里是 `1 * 36 + 0`。
2. 不能。只恢复了 0.5 枚，不足 1。示例没有写 0.5 这个点，可以用同样的类试。
3. `None`。容量 1 时第二次写入淘汰了 `a`。

## 小结

短链是编码加唯一约束，不是保密。限流要讲清算法和状态放在哪。缓存要讲清淘汰和失效，并分清穿透、击穿、雪崩。队列要有界、任务要幂等、失败要可见。进程内的字典不会随水平扩展自动变成全局状态。
