# B12　测试与打包入门

> 示例：`examples/part_b/b12_testing_packaging.py`

## 学完你能做什么

用标准库 `unittest` 把一个纯函数的规格固定下来，并读懂 `pyproject.toml` 里和版本有关的那几行。本教程的示例不安装第三方包，所以这里不用 pytest 也能跑。本仓库其他目录使用 pytest，那是同一类想法的另一种写法。

## 测行为，不测打印

`ClipTests` 做了三件事：区间内不变、高于上界被夹住、上下界写反时抛 `ValueError`。测试方法名说明的是行为。断言比较的是返回值或异常类型，不是一整段日志。

示例自己加载测试套件并 `assert result.wasSuccessful()`，这样 `examples/run_all.py` 不依赖 pytest 的收集规则。你在本地也可以对这个文件运行 `python -m unittest examples.part_b.b12_testing_packaging`，不过那个命令要求当前目录在导入路径上。直接 `python examples/part_b/b12_testing_packaging.py` 是教程保证的入口。

一个测试只让一个理由失败。`test_bad_range` 不用再断言返回值，它的规格就是“必须抛”。`assertRaises` 接住指定类型，别的异常仍会让测试失败。

## 什么值得测

纯函数最适合开这个头：同样的输入，同样的输出，没有时钟、没有网络。边界是测试的主体，不是添头。`clip` 的边界就是上界、下界和非法区间。

有副作用的代码把副作用推到边缘。读写文件时用临时目录，用完即删，A09 那样。当前时间不要在测试里 `sleep`。D02 会把时钟当参数传进去。

不要为了覆盖率去断言私有属性。私有属性一改名，测试就碎，而用户可见的行为可能没变。覆盖率是提醒你哪条路径没走到，不是目标本身。

## 打包文件在声明什么

示例用 `tomllib` 读取仓库根目录的 `pyproject.toml`，断言：

- 项目名是 `lp-python`。
- `requires-python` 是 `>=3.12`。

`tomllib` 从 3.11 起在标准库里，只能读，不能写。教程不去改这个文件。它属于既有的 Python 工程，不是这份教程的私有配置。

一个现代项目的 `pyproject.toml` 至少说明：项目叫什么、需要哪一档 Python、依赖有哪些。锁文件（本仓库是 `uv.lock`）记录某一次解析出来的具体版本，用来让别人安装到同一组依赖。入门阶段要分清这两件事：`requires-python` 是语言版本下限，锁文件是第三方包的具体版本。两者都不是“注释”，安装工具会读它们。

虚拟环境是一个独立的目录，里面有自己的解释器和第三方包。系统 Python 留给操作系统。项目依赖装进虚拟环境。本教程示例只用标准库，是为了让你没有虚拟环境也能把 `examples/run_all.py` 跑完。真的要做 Web 服务时，再按仓库自己的 `Makefile` 同步依赖，那一步不属于本教程的可执行规格。

## 常见错误

- 测试里复制一份生产逻辑，两边一起错。测试应当写预期的输入输出，让生产代码去满足它。
- 依赖测试运行顺序。每个测试自己准备数据。
- 把 `requires-python` 理解成“只是给读者看的”。安装工具会用它拒绝过旧的解释器。

## 练习

1. 为 `clip` 补一个下界测试：`clip(-1, 0, 5)` 应当是 `0`。你可以改示例，改完跑一遍。
2. `pyproject.toml` 里的项目名是从哪个表读出来的？
3. 为什么这个文件不 `import pytest`？

参考答案：

1. `self.assertEqual(clip(-1, 0, 5), 0)`。
2. `[project]` 表的 `name`，代码里是 `data["project"]["name"]`。
3. pytest 不是标准库。教程示例要在只有 CPython 3.12 的环境里跑。断言风格是一样的：调用函数，比较结果。

## 小结

用测试把边界行为写成可执行的规格。`unittest` 足够开始。`pyproject.toml` 声明语言版本和依赖，锁文件固定解析结果，虚拟环境把它们装到项目自己的目录里。
