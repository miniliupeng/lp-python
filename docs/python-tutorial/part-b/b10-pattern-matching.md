# B10　模式匹配

> 示例：`examples/part_b/b10_match.py`

## 学完你能做什么

用 `match` 按结构拆开元组、列表和字典，并避开“字符串也是序列”这个坑。

## 它不是 C 的 switch

`match value` 从上往下试每个 `case`。第一个匹配的分支执行，然后结束，不需要 `break`，也不会掉进下一个分支。`case _` 匹配任何东西，所以它必须放在最后。放在前面的话，后面的分支都到不了，这是语法错误级别的“不可反驳模式”问题：`_` 和单独的捕获名字不能独占一个并非最后的分支。

匹配的是模式，不是一串 `==`。`case (x, y)` 表示“长度为 2 的序列，把两项分别绑到 `x` 和 `y`”。绑到名字之后还可以加守卫：`if x == y`。守卫失败就继续试下一个 `case`，不是直接失败退出。

## 示例在分什么

`describe` 的顺序是有意的：

1. `case str()`：类模式，匹配字符串。
2. `case (x, y) if x == y`：两项相等的序列。
3. `case (_, _)`：任意两项序列。`_` 匹配但不绑定，可以重复使用。
4. `case {"ok": True, "n": int(n)}`：字典里有这些键。映射模式 **不要求** 没有别的键，所以多一个 `"extra"` 仍然匹配。`int(n)` 是类模式，既要求值是 `int`，又把它绑到 `n`。
5. `case [0, *rest]`：序列模式，第一项是字面量 `0`，其余收进 `rest`。
6. `case _`：剩下的。

示例断言 `"no"` 走文本分支，而不是被当成两个字符的序列。如果删掉 `case str()`，`"no"` 会匹配 `(x, y)`，因为字符串实现了序列协议。这是模式匹配里最常见的意外。先把 `str` 和 `bytes` 从序列分支里摘出去。

## 名字的两种身份

`case (x, y)` 里的 `x` 是捕获。`case (x, 1)` 这种写法里，单独的名字永远是捕获，不会去和外面的变量 `x` 比较。想按某个已有的值匹配，用点号形式的值模式，例如 `case Point(x=0)`，或者守卫里写 `if x == expected`。常量放进类属性或枚举里，用 `case Color.RED`。

类模式 `Point(x, y)` 按 `__match_args__` 决定位置参数对应哪个字段。dataclass 会生成这个元组。普通类要自己声明，否则只能写 `Point(x=1, y=2)` 这种关键字模式。

## 什么时候不要用

只有两个分支、条件又是一个布尔表达式时，`if` 更短。`match` 适合结构本身有好几层、每个分支形状不同的时候：解析命令、拆开异构的消息、处理 AST。不要把它当成“更高级的 if”到处替换。

## 常见错误

- 捕获名字拼错，变成一个什么都能匹配的模式，下面的字面量分支变成死代码。
- 以为映射模式会拒绝额外的键。它不会。要限制键集合，在守卫里检查 `value.keys()`。
- 用 `match` 匹配类型时写成 `case int`。那是捕获名字，不是类型。类型用 `case int()`。

## 练习

1. 不看函数体，预测 `describe([0])` 和 `describe([1, 2])`。
2. 为什么 `{"ok": True, "n": 4, "extra": 1}` 仍然返回 `ok-4`？
3. 把“两项元组”从“两个字符的字符串”里区分开，示例用了哪个分支？

参考答案：

1. `[0]` 是 `lead0-0`。`[1, 2]` 不是以类模式处理的字符串，也不是映射，序列第一项不是 `0`，两项序列会在 `(_, _)` 匹配，结果是 `"pair"`。列表在这里满足序列模式。
2. 映射模式只要求列出的键匹配，允许多余的键。
3. 放在序列模式前面的 `case str()`。

## 小结

`match` 按模式从上到下匹配，命中即停止。名字是捕获，不是外部变量的相等比较。字符串会撞上序列模式，需要的话先单独匹配 `str`。映射模式不拒绝额外的键。
