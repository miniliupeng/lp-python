# E05　工程实践题

> 对照示例：`examples/part_e/e05_engineering.py`

### 1. `requires-python` 和锁文件有什么区别？

**常见错法：** 两者都是“建议的版本”，安装时可以忽略。

**回答：** `requires-python` 是语言版本下限，安装工具会拒绝更旧的解释器。依赖范围写直接依赖。锁文件记录一次解析出的完整闭包和哈希，用来重复安装。手改锁文件不是升级流程。

### 2. 为什么测试不该 `sleep`？

**常见错法：** 睡 0.1 秒足够稳定。

**回答：** 调度忙时 0.1 秒不够，测试就开始闪烁。时间应当是注入的值。示例所在的工程章节用一个可拨动的时钟判断过期，断言在一次调用内完成。随机数用显式种子的 `Random` 实例，不改全局种子。

### 3. 类型注解、Protocol、运行时校验各干什么？

**常见错法：** 三者重复，留一个就行。或者 `runtime_checkable` 能验证参数类型。

**回答：** 注解给类型检查器，运行时不自动生效。`Protocol` 描述结构。`runtime_checkable` 的 `isinstance` 只看方法在不在，很浅。外部输入在边界上解析成内部类型，失败就拒绝。内部函数信任已经解析的值。

### 4. 日志为什么不直接 `print`？

**常见错法：** `print` 更简单，上线前再换成日志。

**回答：** 日志有级别、记录器名字和可替换的 handler。库不应当 `basicConfig`。应用入口决定格式和去向。测试可以把 handler 指到 `StringIO`。示例断言一条普通启动日志里没有令牌字符串。秘密从一开始就不要传给日志，而不是依赖事后替换。

### 5. 配置放哪里？

**常见错法：** 写进源码，用 if 判断是不是生产机器的主机名。

**回答：** 同一份源码，不同环境变量。集中解析，缺必填项就启动失败，不要在业务深处返回空字符串再去连接。测试传入字典，不修改真实的 `os.environ`。默认值只属于本地开发。示例的 `load_port` 在没有 `PORT` 时用 8000，并拒绝越界端口。

### 6. 异常和日志怎么分工？

**常见错法：** 捕获所有异常，打一行日志，返回 `None`。

**回答：** 异常表示这条控制流失败了。日志记录需要留下来的事实。边界上可以记录并转换成用户能看的错误，同时保留 `raise ... from` 的原因。不要把回溯发给客户端。不要吞掉 `CancelledError` 和 `KeyboardInterrupt`。

### 7. 参数化 SQL 为什么是工程要求而不只是风格？

**常见错法：** 自己先替换掉引号就安全了。

**回答：** 语句结构留在你的字符串里，值通过占位符传递。这样数据没有机会变成 SQL。列名不能用占位符替换，动态列名必须走白名单。一元参数写成 `(value,)`。事务保证几步修改一起提交或一起回滚。`sqlite3` 的 `with connection` 负责提交或回滚，但不关闭连接。

### 8. 为什么不可信数据不能 `pickle.loads`？

**常见错法：** pickle 只是 Python 版的 JSON。

**回答：** pickle 重建对象图，反序列化过程可以执行被序列化对象里的调用。它只适合你完全信任的字节，例如同一程序刚刚写出、并且没有离开信任边界的数据。配置和外部任务用 JSON、TOML 或你自己的字段解析。教程的可执行示例不调用 `loads`。

### 9. 路径拼接怎样才算做完？

**常见错法：** 去掉用户输入里的 `../` 子串即可。

**回答：** 拒绝绝对路径和 `..` 片段，`resolve` 之后再确认结果仍在指定根目录之下。`resolve` 会跟着符号链接走，所以只做字符串过滤不够。给客户端的错误不要回显服务器上的绝对路径。

### 10. 虚拟环境解决什么？

**常见错法：** 它让代码跑得更快。

**回答：** 它把项目的解释器和第三方包装进独立目录，避免污染系统 Python，也避免两个项目的依赖互相覆盖。教程示例为了可重复阅读，只使用标准库；原有专题的 Web 依赖留在仓库自己的环境里，不要求本教程先安装它们。

### 11. 测试应该断言私有属性吗？

**常见错法：** 断言越多越好，包括循环变量和私有列表的长度。

**回答：** 断言用户可见的行为：返回值、异常类型、持久化之后的查询结果。私有属性一重构测试就碎，还没抓住规格。覆盖率只说明哪行没走到，不说明边界测全了。一个测试只让一个理由失败。

### 12. 服务的错误码为什么不要一律 200？

**常见错法：** HTTP 200 加上 `{"ok": false}` 更统一。

**回答：** 中间件、客户端和监控把 2xx 当成功。失败应当是 4xx 或 5xx。404 表示没有这个资源，400 表示请求不合法，409 或 429 表达冲突和限流。响应正文不要带内部回溯。健康检查应当便宜，不要在里面做写操作。

### 13. 怎样停止一个进程而不丢掉一半写入？

**常见错法：** 收到 `SIGTERM` 就 `os._exit`。

**回答：** 信号处理器里只设置标志。主循环停止接收新工作，把已经收下的任务做完，事务提交或回滚，再退出。工作者不要做成守护线程。第二次信号才考虑立即退出。就绪检查在关闭开始后变为失败，好让外部停止送新流量。

### 14. 依赖注入是不是必须上一个框架？

**常见错法：** 没有容器就无法测试。

**回答：** 把时钟、配置字典、数据库连接当参数传进去，就是测试需要的依赖注入。容器解决的是对象特别多时的装配。小服务先保持构造过程显式。参数超过你能读懂的程度时，再考虑集中装配，而不是先选框架。

## 展开

### 声明、环境和锁

1. `requires-python` 是安装器看的版本范围。锁文件是一次解析的精确版本。两者都不是虚拟环境。
2. 虚拟环境隔离 `site-packages`。应用锁全部传递依赖。库声明范围，由应用去锁。
3. `tomllib.loads` 接收 `str`。二进制文件用 `load`。

### 测试

1. 断言输入输出和不变量，不断言私有属性。
2. 时间做成参数。`sleep` 不是规格。
3. 替身要窄，并遵守真实系统的关键失败语义。少量合同测试才碰真实数据库。

### 校验三层

1. 注解给定检查器。Protocol 的运行时检查只看属性在不在。
2. 外部数据在边界解析。Pydantic v2 用 `model_validate`、`field_validator`、`model_validator`，核心在 pydantic-core。倍数不要背死。
3. 解析失败不要变成默认端口。

### 日志、配置、安全

1. `logging` 有级别和去向。`print` 关不掉。不要记录密钥。用参数形式而不是提前 f-string。
2. 必填配置非法就启动失败。
3. SQL 参数化。路径 `resolve` 后做 `relative_to`。令牌用 `compare_digest`。不可信字节不要 `pickle.loads`。

### 关闭

1. 信号处理器只设标志。
2. 停止接收，等待在途工作到期限，再关池。
3. 健康检查便宜，就绪检查才看依赖。不要在健康检查里写数据库。

### 加练

1. 为什么错误响应不能返回 `str(exc)`？
2. 依赖注入一定要框架吗？

参考答案：

1. 异常文本里有路径、SQL 和内部结构。对用户给错误码，细节进日志。
2. 不一定。函数参数传入仓库和时钟就是注入。框架的 `Depends` 负责请求级的 DAG 和 `yield` 清理。没有框架时用参数和上下文管理器，不要用全局单例假装注入。
