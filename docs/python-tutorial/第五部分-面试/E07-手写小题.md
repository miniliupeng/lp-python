# E07　手写小题

> 示例：`examples/part_e/e07_drills.py`。先自己写，再对照。题目都避免依赖网络和睡眠。

手写题看的是不变量和边界，不是背下某一份模板。下面每题给出规格、一种干净的实现要点，以及示例是怎么断言的。

### 1. 有上限的重试

**规格：** 装饰一个可能抛 `RuntimeError` 的函数。最多调用 `times` 次。某一次成功就返回。全部失败则把最后一次异常抛出去。不要捕获 `CancelledError` 或其他 `BaseException`。

**要点：** 循环里只 `except RuntimeError`。把异常记在局部变量里，循环结束后再抛。用 `functools.wraps`。不要在装饰器里 `sleep`，间隔应当是另一个参数，测试时换成空操作。

示例的 `Flaky` 前两次失败，第三次返回 `"ok"`，调用次数是 3。

### 2. 分组

**规格：** 输入 `(键, 值)` 的列表，输出字典，值按出现顺序收成列表。不要依赖 `itertools.groupby`，因为调用方不一定先排序。

**要点：** `setdefault(key, []).append(value)` 或 `defaultdict(list)`。这是一次线性扫描。`groupby` 只合并相邻键，题目没承诺相邻，所以不适合直接用。

示例断言 `a` 的值是 `[1, 3]`，中间夹了 `b` 也不会拆掉字典里的列表。

### 3. 生成器管道

**规格：** 只把偶数的平方交出去，奇数丢弃。不要先建成完整列表再过滤，除非调用方要求随机访问。

**要点：** 一个 `yield` 就够。生成器只能走一遍。测试要一次消费完，或者重新创建生成器。

示例对 `[1, 2, 3, 4]` 得到 `[4, 16]`。

### 4. 令牌桶

**规格：** 构造时给定速率、容量和当前时间。`allow(now)` 先按时间补令牌，不超过容量，再尝试扣 1。时间不回拨。

**要点：** 不要在函数里读系统时钟，时间由参数进入，测试才能不睡眠。补令牌和扣减都基于实例状态。容量是突发上限。

参考实现在 `examples/part_d/d10_system_design.py`。容量 2、速率 1 时，同一时刻只能通过两次。

### 5. LRU

**规格：** `get` 命中时把键变成最近使用。`put` 超出容量时丢掉最久未使用的键。更新已有键也算一次使用。

**要点：** `OrderedDict` 的 `move_to_end` 和 `popitem(last=False)` 足够。容量小于 1 要拒绝。这个缓存不是线程安全的，多线程要加锁或只由一个主人访问。它也不是数据库。

示例在 `e06_design.py`：容量 1 时，第二个键淘汰第一个。

### 6. 安全的路径拼接

**规格：** 给定根目录和用户给的相对路径。绝对路径、带 `..` 的路径一律拒绝。结果必须仍在根目录内。

**要点：** 用 `pathlib`。拒绝之后再 `resolve`，用 `parents` 确认没有逃出根。不要只做字符串替换。

参考实现在 `examples/part_d/d08_security.py`。

### 7. 夹取函数

**规格：** `clip(value, low, high)` 把值限制在闭区间。`low > high` 时抛 `ValueError`。不要改输入。

**要点：** `max(low, min(high, value))`。边界用测试固定：区间内、上界、下界、非法区间。

参考实现在 `examples/part_b/b12_testing_packaging.py`，用 `unittest` 跑了三条。

### 8. 库存流水

**规格：** 入库和出库数量都必须是正数。出库不能让库存变负。失败时原来的数量不变。

**要点：** 方向用枚举。先算新值，合法再写回。冻结流水对象，避免事后改数量。这是单线程内存模型，并发版本应当把流水交给一个队列主人，或改成数据库条件更新。

参考实现在 `examples/part_b/b13_inventory.py`。

### 9. 读配置里的端口

**规格：** 字典里没有 `PORT` 时返回默认值。有则解析成整数，超出 1 到 65535 就抛 `ValueError`。

**要点：** 不要在这个函数里读全局环境。调用方把环境交给它。默认值是参数。

参考实现在 `examples/part_e/e05_engineering.py`。

### 10. 幂等的“只做一次”

**规格：** 给定任务编号和函数。同一个编号第二次调用时不再执行函数，返回第一次的结果。

**要点：** 用字典记下编号到结果。函数有副作用时，这个记忆就是幂等的关键。先想清楚失败要不要记：如果记了失败，重试会被挡住；如果不记，失败可以重试，但成功必须记。两种都说得通，面试时选一种并讲清。不要用“执行过的编号集合”却忘了保存结果，调用方就拿不到第一次的返回值。

参考形状：

```python
def once(store: dict[str, object], key: str, fn):
    if key in store:
        return store[key]
    result = fn()
    store[key] = result
    return result
```

这里没有捕获异常，所以失败不会写入 `store`，重试还能再执行。若规格要求失败也占住编号，就要把异常信息存进去，并在第二次把同一种失败返回或抛出。

## 写完之后怎么检查

1. 跑 `python examples/part_e/e07_drills.py`。
2. 再跑 `python examples/run_all.py`，确认没有为了手写题改坏前面的断言。
3. 口头讲出每个结构的不变量：重试次数、分组顺序、缓存淘汰、库存不为负、路径不出根。讲不出不变量的实现，只是一段能跑的循环。

## 展开

手写题按同一张清单收尾：不变量、失败时状态不变、复杂度和依赖。下面给七道题补上追问时要补的那句。

### 重试

次数有上限。每次失败的等待用注入的时钟，不 `sleep`。最后一次失败把最后的异常抛出去，不要返回一个看起来像成功的空值。

### 分组

稳定。相同键的元素保持原顺序。不要用会打乱顺序的集合当唯一结构。键不存在时的空组不要突然变成 `None`。

### 生成器管道

每一段只 `yield` 需要的元素。调用方提前停止时，`with` 仍要关闭文件。不要在管道里 `list()` 整个输入。

### 令牌桶

桶有容量。取令牌不足就拒绝，而不是把桶减成负数。补充按时间差计算，时间由参数传入。多副本时说明这个桶只在单进程有效。

### LRU

容量是上限。`get` 和 `put` 都更新“最近”。超限删最久未使用。值如果是可变对象，调用方改动会影响缓存，文档要写明，或者存副本。

### 路径

`resolve` 之后 `relative_to`。用户给绝对路径或 `..` 都拒绝。不要先 `open` 再检查。

### 幂等

成功的结果要存下来，第二次返回第一次的结果。失败是否占用键必须选一种：示例形状是失败不占用，所以异常发生在写入 `store` 之前。若失败也要占键，就把失败存进去并在第二次原样失败。

### 加练

1. 库存流水的手写函数，在数量不足时要断言哪两件事？
2. 夹取函数要不要接受 `low > high`？

参考答案：

1. 余额不变，流水条数不变。只断言抛了异常还不够，因为可能已经写了一半。
2. 不接受就抛 `ValueError`。接受的话要定义语义，例如交换两端。选一种写进断言，不要静默返回 `low`。
