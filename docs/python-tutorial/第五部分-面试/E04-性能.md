# E04　性能题

> 对照示例：`examples/part_e/e04_performance.py`

### 1. 优化的第一步是什么？

**常见错法：** 先把所有循环改成推导式，再谈测量。

**回答：** 先定义慢在哪：延迟、吞吐还是内存。再用分析器看时间实际花在哪个函数。改一处，用同一输入证明结果没变。`cProfile` 是 3.12 的确定性分析器。3.15 的 `profiling.tracing` 是它的新位置，`cProfile` 仍是别名；`profiling.sampling` 才是可以附着到进程的采样分析器。没有 3.15 就不要声称自己在用 Tachyon。

### 2. 列表和 `deque` 怎么选？

**常见错法：** `deque` 全面快于列表，应当替换所有列表。

**回答：** 列表按下标是 O(1)，末尾追加均摊 O(1)，头部插入是 O(n)。`deque` 两端是 O(1)，按下标访问中间是 O(n)。队列和滑动窗口用 `deque`。随机访问用列表。示例只检查两端弹出的语义，不断言某次耗时。

### 3. 字符串为什么不要在循环里反复 `+=`？

**常见错法：** 字符串可变，`+=` 是就地追加。

**回答：** 字符串不可变。循环拼接会反复复制。段数一多，用 `"".join`。两者结果应当相同，示例对两个片段做了这个断言。具体快多少用 `timeit` 测，不要背一个倍数。少量固定的几段，可读性优先，编译器对常量折叠也让“永远不准写加号”变得教条。

### 4. 字典查找是不是永远 O(1)？

**常见错法：** 哈希表最坏也是 O(1)，所以任何键都安全。

**回答：** 平均 O(1)，最坏会退化成线性。自己的 `__hash__` 如果很差，或者相等性很贵，热路径会被拖垮。不可信的键不要配一个常数哈希。语言对 `str` 的哈希做了随机化，这不是你省略复杂度分析的理由。

### 5. `in` 对列表和集合有什么差别？

**常见错法：** 两者都是 O(1)，因为语法一样。

**回答：** 列表的成员测试是线性的。循环里反复测试，先做成集合。集合要求元素可哈希，并且不保留你能依赖的顺序。如果还要原顺序，用字典插入顺序或单独保留一个列表。

### 6. `__slots__` 是性能开关吗？

**常见错法：** 给所有类加槽，QPS 就会上去。

**回答：** 槽减少实例字典的内存，也可能改善缓存局部性。收益只在你有大量这种实例时才测得到。它增加继承和弱引用的约束。先看分析器是不是把时间或内存花在这些实例上。

### 7. 全局变量为什么可能比局部变量慢？

**常见错法：** 名字都是字典查找，没有差别。

**回答：** 局部变量在帧里按下标加载（`LOAD_FAST`）。全局名字要做字典查找（`LOAD_GLOBAL`）。3.11 之后的自适应特化会缩小热点上的差距。这是一条“可以注意”的事实，不是把所有函数改成把全局复制进局部的理由。循环里重复的属性查找，提到循环外，通常更清楚，也更便宜。

### 8. `@cache` 的代价是什么？

**常见错法：** 缓存只会使函数更快，没有行为变化。

**回答：** `functools.cache` 用参数当键，结果永久留在进程里。参数必须可哈希。有副作用的函数会只执行一次副作用。结果空间很大时要改用有 `maxsize` 的 `lru_cache`，否则缓存本身把内存吃完。实例方法会把 `self` 算进键，可能把实例留在缓存里。

### 9. `tracemalloc` 看不到什么？

**常见错法：** 它等于进程的 RSS。

**回答：** 它追踪 Python 分配器看到的分配，用来比较快照、找出哪一行在涨。扩展模块直接向操作系统申请、又没有暴露成 Python 对象的内存，不一定出现在里面。进程到底占了多少，看操作系统的指标。

### 10. 微基准怎样才不算自欺？

**常见错法：** 用 `time.time()` 包住一次很短的调用，差 0.0001 秒就下结论。

**回答：** 用 `timeit`，多次重复，把数据准备放进 `setup`。确认两次实现的结果相等。注意第一次运行还没经过自适应特化。不要在开着调试器或额外追踪时得出生产倍数。

### 11. I/O 慢的时候，改字节码有用吗？

**常见错法：** 服务慢就是 Python 慢，应该换实现或加 JIT。

**回答：** 如果时间花在数据库、下游 HTTP 或磁盘上，换循环写法没有帮助。先让等待可见：超时、请求号、下游耗时。并发模型决定等待时能不能做别的事，不减少单次查询的成本。索引、查询次数和负载才是那一类问题的杠杆。

### 12. 嵌套列表 `[[0] * n] * m` 为什么既是正确性问题也是性能烟幕弹？

**常见错法：** 它只是“省内存的技巧”。

**回答：** 外层乘法复制的是内层列表的引用，改一行会改掉所有行。这是错的结构，不是优化。要独立的行，用推导式每次新建内层列表。示例断言了独立行的改写不会波及第二行。真正想省的内存，用分析器证明之后再谈。

### 13. 3.15 的 JIT 数字能不能直接写进优化方案？

**常见错法：** 官方说快了约 8%，所以我们的接口也会快 8%。

**回答：** 那是 pyperformance 一类基准的几何平均，而且 JIT 仍是实验开关，不是所有构建的默认行为。几何平均掩盖了有的测试变慢、有的测试变快。方案里应当写：在目标版本上对这条热路径做 A/B 测量，再决定是否打开 `PYTHON_JIT`。
