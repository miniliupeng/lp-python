# E03　并发与运行时题

> 对照示例：`examples/part_e/e03_concurrency.py`。3.13 及以后的行为以 C07 的版本边界为准，不要和默认构建混答。

### 1. GIL 是什么？

**常见错法：** GIL 让 Python 没有数据竞争，所以线程里不用锁。另一极端：有 GIL 就完全不能用线程。

**回答：** 在默认 CPython 构建里，同一解释器中只有持有 GIL 的线程能执行 Python 字节码。它保护解释器内部，不保护你的列表和计数器。`+=` 是多条字节码，中间可能让出。I/O 和一部分 C 代码会释放 GIL，所以线程适合等待。纯 Python 的 CPU 计算加线程，通常不能按核数扩展。

### 2. 切换间隔能当锁用吗？

**常见错法：** 默认 5 毫秒内的代码是原子的。

**回答：** `sys.getswitchinterval()` 默认 `0.005` 秒，只影响解释器大约多久切换一次线程。它不把你的几行代码变成临界区。共享不变量要用 `Lock` 或交给一个主人线程。示例只检查这个默认值，提醒你它是调度参数。

### 3. 线程、进程、asyncio 怎么选？

**常见错法：** asyncio 在默认构建里能把 CPU 计算并行到多个核。

**回答：** 等待 I/O：线程或 asyncio。大量连接用 asyncio 更省线程。少量阻塞函数用 `asyncio.to_thread`。纯 Python CPU：进程，或在 3.14 且依赖允许时评估子解释器。不要为了“高级”把没有 `await` 的计算放进协程，那会卡住循环。

### 4. `asyncio` 何时切换任务？

**常见错法：** 事件循环像操作系统一样抢占协程。

**回答：** 协程运行到 `await` 才可能让出。没有 `await` 的循环会独占循环，超时和取消都要等它回到等待点。`time.sleep` 会卡住循环，等待要用 `await asyncio.sleep`。阻塞库调用不要直接放在协程里。

### 5. `CancelledError` 为什么不容易被 `except Exception` 吃掉？

**常见错法：** 它是普通 `Exception`，捕获后返回一个默认值就行。

**回答：** 从 3.8 起它继承 `BaseException`，不继承 `Exception`。示例断言了这一点。清理用 `finally`，清理完要让取消继续传播。吞掉它会破坏 `TaskGroup`：组以为任务成功结束了。

### 6. `TaskGroup` 解决什么问题？

**常见错法：** `create_task` 之后不需要等待，任务会自己完成。

**回答：** 裸任务容易泄漏，异常发生在你已经离开那段代码之后。`TaskGroup` 从 3.11 起把一组任务圈在 `async with` 里，离开前全部结束；其中一个失败，其余被取消，错误以异常组的形式抛出。新代码优先用它，而不是手工维护任务列表。

### 7. 进程池为什么要求顶层函数？

**常见错法：** 闭包和 lambda 也能交给 `ProcessPoolExecutor`。

**回答：** 参数和函数要被序列化到另一个解释器。子进程用导入路径找回函数，所以它必须是模块顶层的具名函数。入口放在 `if __name__ == "__main__"` 里，避免 spawn 方式下递归启动。返回值也必须可序列化。

### 8. 自由线程在 2026 年是什么状态？

**常见错法：** Python 3.13 已经默认删除 GIL。3.15 的 macOS 安装包“默认带上自由线程支持”等于默认解释器没有 GIL。

**回答：** 3.13 的自由线程是实验构建。3.14 起它是官方支持的可选构建，不是默认解释器。PEP 779 把“改为默认”留作未来的 PEP。3.15 的 macOS 官方包默认包含这种构建，不表示你当前的 `python` 关掉了 GIL。3.13 及以上看 `sys._is_gil_enabled()`。自由线程下数据竞争更容易出现，锁不能少。3.14 文档还写明那种构建当时不支持 JIT。

### 9. JIT 能写进“我们的生产解释器默认就开着”吗？

**常见错法：** 3.13 之后 Python 默认用 JIT，速度已经接近静态语言。

**回答：** 到 3.15，JIT 仍是实验特性。3.13 的普通构建默认没有它。3.14 的官方 macOS 和 Windows 二进制可以用 `PYTHON_JIT=1` 打开。3.15 的基准有个位数到十几个百分点的几何平均提升，随平台和负载变化。先对具体服务测量，再决定开不开。

### 10. 子解释器和进程有什么差别？

**常见错法：** 3.12 的标准库就能创建子解释器，而且和线程一样共享对象。

**回答：** 3.12 起每个子解释器有自己的 GIL，可以并行执行 Python，但当时主要是 C API。3.14 的 `concurrent.interpreters` 才进标准库。它们默认隔离，不像线程那样共享堆。比进程轻，但启动成本和扩展兼容性仍是限制。第三方扩展没准备好时，进程更稳。

### 11. `queue.Queue` 和列表有什么线程语义差别？

**常见错法：** 有 GIL，列表的 `append` 就可以当队列用。

**回答：** `queue.Queue` 明确保证线程之间的放入和取出，还能有上限。上限满了，`put_nowait` 抛 `queue.Full`，这是背压。列表没有这个合同。示例把容量为 1 的队列第二次放入断言为失败。

### 12. asyncio 的锁和线程的锁能混用吗？

**常见错法：** `asyncio.Lock` 也能挡住另一个操作系统线程。

**回答：** 不能。`asyncio.Lock` 只调度同一事件循环里的协程。线程之间用 `threading.Lock`。两边都要改的数据，应当只有一个主人，其他人通过队列提交操作。

### 13. 守护线程适合做什么？

**常见错法：** 把写数据库的线程标成 daemon，主线程结束时它会安全收尾。

**回答：** 进程退出时守护线程会被直接停掉，`finally` 不保证执行。它只适合“停掉也没有关系”的后台任务。正常工作者不要设成守护线程，主线程应当发停止信号并 `join`。

### 14. 上下文变量会自动进新线程吗？

**常见错法：** `ContextVar` 和全局变量一样，所有线程看见同一份当前值；或者相反，所有版本都会自动复制给子线程。

**回答：** 上下文变量跟随当前执行上下文。asyncio 任务会复制它。3.12 里新线程不会自动拿到调用者的上下文，需要显式复制或把值当参数传。不要用它代替函数参数来隐藏必填数据，它适合请求号这种诊断上下文。

## 展开

### GIL，追问到 2026 年

1. 默认构建仍有 GIL。执行 Python 字节码前要持有它。它保护解释器，不保护你的余额。
2. 阻塞 I/O 会放开它，所以线程适合等待。纯 Python 计算用进程。
3. 自由线程是 3.13 实验、3.14 起受支持的可选构建。默认化要另写 PEP。看当前进程用 `sys._is_gil_enabled()`，3.12 没有这个函数。不要说“Python 3.15 已经去掉 GIL”。

### 切换间隔

1. 默认 `0.005` 秒，是调度提示。
2. 它不把几条字节码合成原子操作。`+=` 仍要锁。
3. 不要为了正确性去调小间隔。那只增加切换成本。

### asyncio

1. 只在 `await` 时切换。CPU 循环会堵住循环。
2. `CancelledError` 继承 `BaseException`，`except Exception` 抓不住。清理后要重新抛出。
3. `TaskGroup` 把一组任务的失败和取消收成结构化并发。锁用 `asyncio.Lock`，不要在协程里拿线程锁再 `await`。

### JIT 和子解释器

1. JIT 到 3.15 仍是实验，默认不靠它做容量规划。公开的提升是基准套件上的大约 7% 到 12%，平台不同。
2. 3.14 的自由线程构建不支持当时的 JIT。
3. 子解释器从 3.12 起可以各有一把 GIL，3.14 才有 `concurrent.interpreters`。它们默认不共享对象，扩展也不一定支持。

### 加练

1. 四条线程各对共享计数 `+=` 1000 次，为什么测试只断言有锁的 4000？
2. `contextvars` 会自动进新线程吗？

参考答案：

1. 无锁结果依赖调度，有时碰巧正确，测试会闪。正确性只钉有锁的结果。
2. 不会。它跟随 Task 拷贝。新线程要显式复制上下文，否则日志里的请求号会丢。
