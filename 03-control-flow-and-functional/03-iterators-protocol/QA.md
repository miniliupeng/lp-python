# 大厂高频面试题精讲 (02-03-iterators-protocol)

---

### Q1: 简述可迭代对象（Iterable）与迭代器（Iterator）在 Python 数据模型中的本质区别。

#### 🎯 面试官考点
- Python 抽象基类（collections.abc）、双重魔术方法协议与状态机模型。

#### 💡 满分回答模板
1. **协议方法实现的本质差异**：
   - **可迭代对象（Iterable）**：实现了 **`__iter__()`** 方法（或历史支持的 `__getitem__()`），其唯一职责是：被调用时**返回一个崭新的迭代器对象**；
   - **迭代器（Iterator）**：必须**同时实现两个方法**：
     - **`__iter__()`**：必须返回其 **self 自身**；
     - **`__next__()`**：返回序列中的下一个元素；当元素耗尽时，无条件抛出 **`StopIteration`** 异常终止。
2. **状态维护的区别**：
   - 可迭代对象（如 `list`, `dict`）通常是静态的数据容器，它可以被多次反复遍历（每次调用 `iter(obj)` 都获得一个从头开始的全新迭代器）；
   - 迭代器是**带有实时游标位置的有状态数据流**，具有一次性消费特性。

### Q2: Python 的 for 循环在底层字节码层面是如何运作的？

#### 🎯 面试官考点
- CPython 虚拟机执行循环评估、字节码指令（`GET_ITER`, `FOR_ITER`）。

#### 💡 满分回答模板
1. **字节码执行拆解**：
   当执行 `for item in collection:` 时，CPython 编译器将其翻译为核心字节码指令流：
   - **`GET_ITER` 指令**：调用内置函数 `iter(collection)`，在栈顶换取该容器的专用迭代器对象；
   - **`FOR_ITER <jump_target>` 指令**：循环入口。自动调用该迭代器的 `__next__()` 方法并将返回值压栈；
   - **退出机制**：当 `__next__()` 内部抛出 `StopIteration` 异常时，`FOR_ITER` 字节码在 C 层面**静默捕获该异常（消除异常开销）**，并驱动指令计数器跳出循环体跳转到 `<jump_target>`，继续向下执行。

### Q3: 为什么迭代器是一次性消费的（Exhaustible）？如何让一个自定义类既能节约内存又能重复遍历？

#### 🎯 面试官考点
- 迭代器生命周期、生成器封装与迭代器模式最佳工程实践。

#### 💡 满分回答模板
1. **一次性消费的本质**：
   - 迭代器本质上维护着单向递增的状态指针（如文件流读取指针、网络游标）。为了保持极简与极速，它不会缓存已经访问过的历史数据；
2. **实现可重复遍历的标准解法**：
   - **保持外层容器与内部迭代器分离**：将自定义类设计为 **可迭代对象（Iterable）** 而非自身直接充当迭代器；
   - 在类的 `__iter__()` 方法中，**使用生成器（Generator）按需实时构造并返回新迭代器**：
     ```python
     class ReusableDataStream:
         def __init__(self, filepath: str):
             self.filepath = filepath
         
         def __iter__(self):
             with open(self.filepath, "r") as f:
                 for line in f:
                     yield line.strip()
     ```
   - 这种设计每次调用 `for x in stream:` 都会触发 `__iter__` 重新打开文件创建全新生成器，既保证了每次遍历都是恒定 O(1) 内存流式处理，又完美支持无限次重复遍历。
