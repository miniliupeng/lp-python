# 大厂高频面试题精讲 (02-01-modern-pattern-matching)

---

### Q1: Python 3.10 引入的结构化模式匹配与传统语言（如 C/Java）的 switch-case 有何本质区别？

#### 🎯 面试官考点
- 语言范式演进洞察、值匹配（Value Matching）与模式解构（Destructuring Pattern）的本质跨越。

#### 💡 满分回答模板
1. **匹配维度的代差**：
   - **传统 switch-case**：本质是**标量值跳转表（Jump Table）**，只能比对基本整数、字符或枚举值；
   - **Python match-case**：是借鉴自函数式语言（如 Rust, Scala, OCaml）的**结构化解构模式系统**。它不仅比对值，更是对数据结构的“形状（Shape）”、类型（Type）和属性组合进行立体解构。
2. **就地变量捕获绑定能力**：
   - 当模式声明为 `case [x, y, *rest]:` 时，它不仅验证被匹配对象是否为至少含 2 个元素的序列，还在匹配成功的瞬间自动将第 1、2 个元素以及剩余元素切片就地赋值给新变量 `x`, `y`, `rest`，省去了所有繁复的手工索引提取与切片操作。

### Q2: 为什么在 case 语句中直接使用大写常量名（如 case NOT_FOUND:）会引发严重的逻辑 Bug？正确做法是什么？

#### 🎯 面试官考点
- PEP 634 词法绑定规则（Capture Patterns vs Value Patterns）核心陷阱。

#### 💡 满分回答模板
1. **Bug 机制根源（命名捕获优先）**：
   - 在 Python 模式匹配规范中，**任何未带点号（`.`）的纯变量名（即使是大写的 `NOT_FOUND`）都会被统一识别为“捕获模式（Capture Pattern）”**；
   - 这意味着它不会拿变量的值去比对，而是**将当前被匹配的值无条件赋值给这个名为 `NOT_FOUND` 的新局部变量**！
   - **后果**：无论传入什么，该 `case` 都会 100% 恒命中，且原本定义的常量值被无意覆写！
2. **生产标准解法**：
   - **带点号访问（Dot notation）**：将常量收敛在枚举类或命名空间对象内，使用 `case HttpStatus.NOT_FOUND:`；
   - 只有包含点号的表达式才会被编译器识别为“值比对（Value Pattern）”。

### Q3: 为什么说结构化模式匹配大幅提升了大型微服务接口的安全性？

#### 🎯 面试官考点
- 复杂非受信输入边界防御、类型收窄（Type Narrowing）与解耦。

#### 💡 满分回答模板
1. **严苛的类型与形态联合校验**：
   - 模式匹配可以在一行内声明字段存在性、类型强约束与子字段约束（如 `case {"code": int(c), "data": list(items)}:`）；
   - 只要有任意一个字段类型不符（例如前端传入了字符串类型的数字），该分支就会自然穿透，绝不会在分支内部执行到一半抛出 `TypeError` 导致服务 500；
2. **穷举性与防御兜底**：
   - 强制开发者或架构师通过 `case _:` 显式思考对非法入参、畸形协议的防御兜底方案，显著增强系统对野数据的韧性。
