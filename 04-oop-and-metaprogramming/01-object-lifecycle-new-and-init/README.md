# 专题 01：对象生命周期解耦（__new__ 与 __init__）与单例模式设计

在初学 Python 时，很多开发者误将 `__init__` 称为“构造函数”。然而在 CPython 严格的对象模型中，**构造阶段（`__new__`）** 与 **初始化阶段（`__init__`）** 是完全物理分离的。理解 `__new__` 是掌控不可变对象创建、类级元编程拦截以及编写线程安全单例模式的核心门槛。

---

## 一、 痛点驱动：不可变类型定制与全局唯一单例控制

1. **不可变对象（如 tuple, int, str）无法在 `__init__` 中修改**：
   - 继承 `tuple` 或 `str` 开发自定义结构时，若在 `__init__` 中试图修改属性，会直接抛出 `TypeError`，因为当 `__init__` 运行时，该不可变对象在物理内存中已经被彻底创建封死；
2. **全局数据库连接池或配置单例控制**：
   - 如果通过全局变量来维护单例，极易被意外篡改或被调用方无意识地多次 `DatabaseConfig()` 创建多个孤岛连接池，打爆数据库连接句柄。

---

## 二、 机制解密：__new__ 与 __init__ 的接力流水线

```text
调用 ClassName(*args, **kwargs)
       │
       ▼ (步骤 1: 内存空间分配与物理构造)
ClassName.__new__(cls, *args, **kwargs)
       │
       ├─ 若返回的是 cls 的实例 ──> (步骤 2: 属性挂载初始化)
       │                             instance.__init__(*args, **kwargs)
       │
       └─ 若返回其他类的实例/非cls ─> 彻底跳过当前类的 __init__ 执行！
```

1. **`__new__` 的静态职责**：
   - 是一个**静态方法（传入参数为 `cls`）**，其职责是向底层 C 语言申请物理内存切片，并返回一个未经初始化的裸对象；通常必须调用 `super().__new__(cls)` 完成分配；
2. **`__init__` 的实例职责**：
   - 是一个**实例方法（传入参数为已生成的 `self`）**，其职责仅是为新对象赋予初始属性，**绝对不能有返回值（必须返回 `None`）**。

---

## 三、 生产规范与最佳实践

- **单例实现必须加锁防并发竞态**：多线程并发调用 `__new__` 时，未加锁的双重检查（DCL）会导致瞬时创建多个实例；
- **慎用 `__new__` 篡改返回类型**：除非开发工厂模式（Factory Pattern）或代理，否则 `__new__` 必须返回所属类的合法实例。
