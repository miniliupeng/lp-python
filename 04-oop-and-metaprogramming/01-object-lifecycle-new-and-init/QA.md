# 大厂高频面试题精讲 (03-01-object-lifecycle-new-and-init)

---

### Q1: 请详述 Python 中 __new__ 与 __init__ 的底层本质区别及各自应用场景。

#### 🎯 面试官考点
- Python 对象实例化全流程、元编程控制点与不可变数据类型扩展机制。

#### 💡 满分回答模板
1. **职责与调用时序差异**：
   - **`__new__(cls, ...)`（物理构造阶段）**：
     - 是一个静态方法，第一个入参为当前类对象 `cls`；
     - 负责向操作系统/CPython 内存池**真正分配并返回新对象的物理内存指针**；
   - **`__init__(self, ...)`（状态初始化阶段）**：
     - 是一个普通实例方法，第一个入参是 `__new__` 创建好的未初始化实例 `self`；
     - 负责为对象挂载初始字段，**严禁有返回值（必须返回 `None`）**。
2. **经典应用场景选型**：
   - **使用 `__new__` 的场景**：
     1. 继承不可变内置类型（如定制特殊的 `int`、`tuple`、`str` 类）；
     2. 实现全局单例模式、对象池缓存复用；
     3. 动态控制对象生成类型（工厂模式动态分发子类实例）；
   - **使用 `__init__` 的场景**：日常 99% 的普通业务类，仅需进行属性绑定与赋值。

### Q2: 如果在 __new__ 方法中没有返回当前类的实例（例如返回了一个其他类的实例或 None），__init__ 还会被执行吗？为什么？

#### 🎯 面试官考点
- CPython 解释器在类调用（`type.__call__`）中的条件分发内核逻辑。

#### 💡 满分回答模板
1. **明确结论**：
   - **绝对不会执行**！
2. **底层机制解密**：
   - 当我们在代码中写 `obj = MyClass()` 时，底层触发的是元类的 **`type.__call__()`** C 语言方法；
   - 它的内部伪代码逻辑非常严格：
     ```python
     def __call__(cls, *args, **kwargs):
         # 1. 触发类自定义的 __new__
         instance = cls.__new__(cls, *args, **kwargs)
         # 2. 关键判定分支: 只有当返回值确实是当前类或其子类的实例时，才触发初始化
         if isinstance(instance, cls):
             cls.__init__(instance, *args, **kwargs)
         return instance
     ```
   - 如果 `__new__` 返回了第三方类的对象、甚至是 `None`，解释器判定类型不匹配，会**直接返回该对象，彻底跳过当前类的 `__init__` 执行**。

### Q3: 如何在 Python 中手写一个工业级、兼顾并发线程安全的单例模式？

#### 🎯 面试官考点
- 多线程并发竞态防御、双重检查锁定（Double-Checked Locking, DCL）与幂等初始化。

#### 💡 满分回答模板
1. **工业级单例的三大必备要素**：
   - **双重检查互斥锁（DCL）**：外层判断避免不必要的竞争锁开销，内层加锁确保极端并发下仅分配一次；
   - **`super().__new__(cls)` 安全分配**：从基类安全获取裸堆对象；
   - **初始化幂等标志（`_is_initialized`）**：因为每次调用 `Singleton()` 时，由于返回的是当前类实例，`__init__` 会被默认重复调用，必须使用布尔标志位加锁阻止二次属性覆写。
