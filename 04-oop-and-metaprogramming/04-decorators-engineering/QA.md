# 大厂高频面试题精讲 (03-04-decorators-engineering)

---

### Q1: 简述 Python 装饰器的底层工作机制。为什么带参数的装饰器需要写三层嵌套函数？

#### 🎯 面试官考点
- 闭包作用域（Closure Scope）、高阶函数语法糖与解释器解析时序。

#### 💡 满分回答模板
1. **普通装饰器的本质**：
   - 装饰器是**以函数为参数并返回新函数的高阶闭包函数**；
   - 语法糖 `@dec 
 def foo(): ...` 在模块加载时严格等价于：`foo = dec(foo)`。
2. **为什么带参装饰器必须三层嵌套**：
   - 语法糖规则：`@dec(param="xxx") 
 def foo(): ...`；
   - 解释器首先**立即执行小括号调用 `dec(param="xxx")`**，该调用必须返回一个“真正的无参装饰器”；
   - 随后解释器再拿该返回的函数去包裹 `foo`；
   - **三层职责切分**：
     - **第 1 层（工厂层）**：接收装饰器配置参数，返回实际装饰器函数；
     - **第 2 层（包装层）**：接收被装饰的目标函数对象 `func`，返回拦截闭包；
     - **第 3 层（执行层）**：接收每次实际调用时的实参 `*args, **kwargs`，执行前后置拦截逻辑。

### Q2: 为什么自定义装饰器内部必须使用 @functools.wraps(func)？如果遗漏会产生什么严重后果？

#### 🎯 面试官考点
- 函数对象反射属性、第三方框架（FastAPI/Pytest/文档生成器）依赖契约。

#### 💡 满分回答模板
1. **遗漏 `wraps` 的生产危害**：
   - **函数名与文档丢失**：被装饰后，函数的 `__name__` 会全部变成通用的 `"wrapper"`，`__doc__` 变成 `None`；
   - **框架路由与依赖注入瘫痪**：在 FastAPI 或 Flask 中，路由路径、Swagger 文档生成与自动入参反射完全依赖函数的 `__name__` 与 `__annotations__`。若全变成 `wrapper`，会导致路由冲突覆盖、文档全乱；
   - **自动化测试断言失效**：基于函数名分发的 Pytest fixture 或 Mock 将全部无法匹配。
2. **`@functools.wraps` 的解决方案**：
   - 它通过标准库 `functools.update_wrapper`，把原函数的 `__name__`, `__doc__`, `__module__`, `__annotations__` 完整复制到闭包外壳上；
   - 并在外壳上挂载一个 **`__wrapped__`** 属性直接指向未经装饰的原始函数对象，极大方便了单元测试绕过切面直接测试核心纯函数逻辑。

### Q3: 如果在同一个函数上叠放了多个装饰器，它们的装载时序与实际调用执行时序是怎样的？

#### 🎯 面试官考点
- 叠放装饰器的编译求值顺序与洋葱模型执行流。

#### 💡 满分回答模板
1. **代码示例**：
   ```python
   @dec_a
   @dec_b
   def target():
       pass
   ```
2. **装载时序（自底向上，从内到外）**：
   - 模块加载时，语法糖等价展开为：`target = dec_a(dec_b(target))`；
   - 因此是**先执行 `dec_b` 的包装，再执行 `dec_a` 的包装**。
3. **调用执行时序（自顶向下，洋葱折返）**：
   - 当业务代码真正发起调用 `target()` 时：
     1. 最先进入 **`dec_a` 的前置逻辑**；
     2. 接着进入 **`dec_b` 的前置逻辑**；
     3. 执行真正的 **`target` 核心函数体**；
     4. 折返执行 **`dec_b` 的后置逻辑**；
     5. 最后折返执行 **`dec_a` 的后置逻辑**。
