# 专题 02：核心魔术方法系统（__repr__、__eq__ 与 __hash__ 字典键契约）

Python 的面向对象哲学被称为“**数据模型协议（The Python Data Model）**”。通过重载以双下划线开头的“魔术方法（Dunder Methods）”，我们可以让自定义类无缝接入 Python 内置的操作符与系统级生态。其中，**`__repr__` 的调试契约** 与 **`__eq__` / `__hash__` 的哈希表一致性契约**，是大厂编写基础模型时必考的硬核功底。

---

## 一、 痛点驱动：哈希表查找失效与调试黑盒

1. **重写了 `__eq__` 导致对象无法放入 `set` 或作为 `dict` 的键**：
   - 开发者重写 `__eq__` 来比对实体 ID 是否相等，紧接着把对象放进 `set` 时，Python 突然抛出 `TypeError: unhashable type: 'User'`；
2. **`__repr__` 缺失导致日志黑盒**：
   - 线上报错日志打印对象时，只输出干瘪无用的 `<User object at 0x7fa2818>`，运维与开发根本无法定位当时出错的实体字段信息。

---

## 二、 机制解密：哈希一致性三定律与双重文本表示

```text
[ 文本表示协议分流 ]
  __repr__() ──> 面向开发者与调试器 (精确、无歧义，最好满足 eval(repr(obj)) == obj)
  __str__()  ──> 面向终端用户与前端 (友好、精炼的字符串呈现)

[ 哈希表存取检索机制 ]
  字典查找 dict[key]:
    1. 计算 hash(key) ──> 决定在哈希表中的桶槽位 (Bucket Index)
    2. 若槽位发生碰撞 ──> 触发 key1 == key2 (调用 __eq__) 进行二次精确确认
```

1. **哈希三定律（The Hash Contract）**：
   - **若两个对象相等（`a == b`），则它们的哈希值必须绝对相同（`hash(a) == hash(b)`）**；
   - 对象的哈希值在其生命周期内**必须恒定不可变**（若可变，放入集合后属性改变，导致哈希值变动，后续将永远无法再次找到它！）；
2. **为什么重写 `__eq__` 会自动将 `__hash__` 置为 `None`**：
   - Python 为保护数据安全：一旦开发者改变了相等性判定逻辑，默认继承自 `object` 的“按物理内存地址计算哈希”将破坏哈希三定律，因此解释器强制将其标记为不可哈希，必须显式协同重写。

---

## 三、 生产规范与避坑指南

- **可变对象绝对禁止实现 `__hash__`**：只有具备不可变特性的实体（Immutable Entities）才允许重写哈希方法；
- **万物皆需声明 `__repr__`**：实现类时若只重写一个方法，无条件优先选择 `__repr__`（因若未定义 `__str__`，解释器会自动回退使用 `__repr__`）。
