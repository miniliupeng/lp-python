# 专题 05：多继承体系、MRO 与 C3 线性化算法（super 协同调用链）

Python 是一门原生支持**多重继承（Multiple Inheritance）**的语言。多继承赋予了强大的 Mixin 混入复用能力，但也带来了经典的“**菱形继承问题（The Diamond Problem）**”。为了彻底终结继承图遍历中状态被重复初始化与死锁的难题，Python 2.3+ 确立了现代 **C3 线性化算法（C3 Linearization）**，并规范了 **`super()`** 协作式调用链。

---

## 一、 痛点驱动：菱形继承的基类重复初始化灾难

传统硬编码调用父类构造函数在菱形继承架构中极其危险：
```text
      A (顶级基类)
     / \
    B   C  (B 和 C 均继承 A)
     \ /
      D    (D 继承 B 和 C)
```
如果类 B 写了 `A.__init__(self)`，类 C 也写了 `A.__init__(self)`，当创建 D 实例时，**顶级父类 A 的初始化逻辑将被重复执行两次**！若 A 中包含自增 ID、计数器或不可重复的网络连接分配，将引发严重状态错乱。

---

## 二、 机制解密：MRO 单一线性链与 super() 动态协同

```text
[ C3 线性化推导原则 ]
  1. 局部优先 (Local Precedence): 子类永远在所有父类之前
  2. 单调性 (Monotonicity): 若类 A 在类 B 之前，则在所有子类的继承视图中 A 都必须在 B 之前
  3. 拓扑保序: 尊重 class D(B, C) 括号内的书写声明顺序

D.__mro__ 最终决议线性链: [ D, B, C, A, object ]
```

1. **`super()` 不是“调用父类”，而是“沿着当前 MRO 链寻找下一个类”**：
   - 在类 B 中调用 `super().__init__()` 时，它调用的**绝不是固定死板的基类 A**！
   - 在 D 的调用链上下文中，根据 `D.__mro__`，B 的下一个顺位是 **C**！因此 `super()` 实现了向同级兄弟类的协作流转，最终收敛到 A，**保证基类 A 仅被精确执行一次**。

---

## 三、 生产规范与最佳实践

- **多继承中必须全部使用 `super()`**：严禁混用传统 `Parent.__init__(self)`，否则会切断 MRO 协同链；
- **Mixin 类必须调用 `super()` 且声明通配入参 `*args, **kwargs`**：确保协同链条能透明穿透。
