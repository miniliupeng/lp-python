### Q1: 为什么在 AI 大模型打字机流式响应中，各大厂商（OpenAI、Anthropic、DeepSeek）普遍选择 SSE 而非 WebSocket？

#### 🎯 面试官考点
- 现代网络协议对比（HTTP/SSE vs WebSocket）、代理穿透、连接维护成本。

#### 💡 满分回答模板
1. **业务场景契合度（单向推送 vs 双向全双工）**：
   - 大模型打字机场景是典型的**单向流**：客户端发送一次提问请求，服务端在后续 30 秒内单向源源不断回传文本片段；
   - WebSocket 专为双向高频交互（如联机游戏、即时聊天）设计；在纯下行流场景中引入 WebSocket 属于过度设计。
2. **协议简单性与对既有 HTTP 设施的完美兼容**：
   - **原生基于 HTTP 协议**：SSE 不需要像 WebSocket 那样经历复杂的协议升级握手（Upgrade Handshake），它就是一个标准的 HTTP GET 请求；
   - **穿透防火墙与负载均衡**：天然复用现有的 HTTP/HTTPS 端口（80/443），绝不会被企业防火墙或特定反向代理阻断拦截；
   - **天生支持断线重连**：浏览器原生提供的 `EventSource` API 自带连接保活机制，若网络抖动断开会自动携带 `Last-Event-ID` 请求头自动发起重连，无需手写心跳退避逻辑。

### Q2: 如果让你从 0 到 1 架构一个日均千万级请求的高可用 Python 服务端系统，你会如何设计全链路架构？

#### 🎯 面试官考点
- 千万级架构顶层设计（高并发、高可用、可扩展、防御性治理全链路）。

#### 💡 满分回答模板
1. **接入层与网关层（流量削峰与动静分离）**：
   - 全球多节点 **CDN** 缓存静态资源与媒体内容；
   - 部署 **Nginx / K8s Ingress Controller** 集群做七层反向代理，负责 SSL 证书卸载、WAF 恶意防刷限制、基于 IP 的令牌桶限流与连接保活。
2. **应用服务层（无状态与异步非阻塞）**：
   - 核心微服务全面采用 **FastAPI + Uvicorn** 构建；
   - **进程模型**：通过 Kubernetes Pod 横向自动扩缩容（HPA），容器内依据 CPU 核数配置独立 Worker；
   - **完全无状态化（Stateless）**：服务节点绝不保留 Session，用户身份校验全部采用 JWT 或分布式 Redis 共享，实现任意节点的水平秒级漂移。
3. **数据缓存与持久层（分级防御与读写分离）**：
   - **分布式缓存（Redis Cluster）**：配置读写分离，全面落地空值缓存防穿透、互斥锁防击穿、TTL 随机抖动防雪崩；
   - **关系数据库（PostgreSQL/MySQL）**：主从读写分离，严格通过 SQLAlchemy 2.0 配置带有 `pool_recycle` 的异步连接池；
   - **异步解耦（消息队列 RabbitMQ / Kafka）**：耗时的短信发送、邮件推送、复杂报表与日志清洗异步放入消息队列削峰填谷。

### Q3: 在生产环境中，如果 Python 进程发生“内存泄漏（Memory Leak）”或“CPU 飙高 100%”，请详述系统性排查的标准 SOP 流程。

#### 🎯 面试官考点
- 生产应急故障排障 SOP、线上无侵入式 Profiling 工具链（py-spy, tracemalloc）。

#### 💡 满分回答模板
1. **CPU 飙高 100% 排查 SOP**：
   - **第 1 步：定位具体线程**：使用 `top -H -p <pid>` 找到占用 CPU 最高的线程 ID（LWP）；
   - **第 2 步：无侵入抓取火焰图**：使用 **`py-spy`** 工具直接附加到线上运行中的进程：
     ```bash
     py-spy dump --pid <pid>      # 打印当前所有线程的 Python 调用栈
     py-spy flame -o flame.svg -p <pid>  # 采集生成实时火焰图
     ```
   - **第 3 步：根因决议**：根据火焰图横条宽度，直接定位是哪个正则回溯灾难、无限死循环还是复杂计算密集函数。
2. **内存泄漏（Memory Leak）排查 SOP**：
   - **第 1 步：确认是真实泄漏还是内存碎片**：对比 `ps -o rss` 物理常驻内存与 CPython 内部堆对象；
   - **第 2 步：使用 `tracemalloc` 捕获快照差异**：
     在代码中注入轻量排查中间件，间隔 10 分钟对比两次堆快照（`snapshot2.compare_to(snapshot1, 'lineno')`），精准输出到底是哪一行代码创建的对象未被释放；
   - **第 3 步：锁定未释放对象引用链**：使用 `objgraph` 生成引用链拓扑图，重点排查是否存在全局字典无序膨胀、事件监听器未注销、闭包中被无意引用的局部巨型大对象。

### Q4: 请用三句话总结一名优秀现代 Python 工程师在日常编码中必须坚守的“核心军规”。

#### 🎯 面试官考点
- 工程师职业素养、生产敬畏之心与架构技术品味。

#### 💡 满分回答模板
1. **【并发敬畏】**：牢记单线程事件循环的协作本质，在 async 链路中**绝不混入任何同步阻塞调用**，高并发接口永远前置信号量与连接池背压保护。
2. **【契约至上】**：在系统边界永远假设外部数据不可信，**通过类型提示与 Pydantic 强契约将野数据防御在最外层**，核心业务层坚持不可变与状态纯净。
3. **【生命周期对称】**：善用 `with`、`async with` 与 `lifespan` 上下文管理器，**绝不让任何数据库连接、文件句柄或并发任务脱缰逃逸出它的词法作用域**，实现 100% 确定性的资源优雅析构。
